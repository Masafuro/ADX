## 1. エグゼクティブサマリ（序論）

産業用オートメーション（FA: Factory Automation）の現場において、長らく「当たり前」とされてきた開発・運用の慣習がある。
片手で重いWindowsノートPCを抱え、制御盤の前に中腰でしゃがみ込み、数十万円の専用作画ソフトを立ち上げ、通信エラーと格闘しながらリセットボタンを押す――。

本稿は、新世代の分散モジュラーマイコンシステム **ADX** が切り開く、**「スマホ $\times$ ブラウザ（WebSerial） $\times$ RS-485（BR32）」** によるパラダイムシフトの全貌を記録するものである。

本構想の核心は、**「`adx.h`（マイコン） — `BR32`（不変のプロトコル） — `adx.js`（Web）」** という三位一体のアーキテクチャにある。
組み込み開発の歴史と産業用GOT（プログラマブル表示器）が抱えてきた構造的限界を解き明かし、なぜ今「スマホファーストな開発UX」が産業現場における最大のブレイクスルーとなるのか、その歴史的意義と構造的必然性を論じる。

## 2. 組込開発・産業用制御（PLC/GOT）の歴史と「3つの呪縛」

世界中にこれほど優秀なエンジニアがいながら、なぜ「`arduino.js`」や「`m5stack.js`」のようなWeb主体の統合環境はメインストリームにならなかったのか？
産業用PLC・表示器（HMI/GOT）およびホビーマイコンの歴史を振り返ると、そこには3つの強固な呪縛が存在していた。

```
┌─────────────────────────────────────────────────────────────┐
│                   従来の3つのアプローチと限界                       │
├──────────────────────────┬──────────────────────────────────┤
│ ① 産業用GOT (三菱/キーエンス等) │ 専用ソフト高額・重厚長大・作画地獄・独自バイナリ │
├──────────────────────────┼──────────────────────────────────┤
│ ② Arduino アプローチ     │ シリアルモニタは「黒い文字画面」止まり、GUI丸投げ │
├──────────────────────────┼──────────────────────────────────┤
│ ③ M5Stack アプローチ     │ マイコンに極小液晶を載せ、C++座標計算の苦行に逆戻り│
└──────────────────────────┴──────────────────────────────────┘
```

### 2.1 産業用GOTの地獄：専用作画ソフトと高額ハードウェア
産業用設備において、現場作業員が機械と対話するためのHMI（Human Machine Interface）＝ **GOT（プログラマブル表示器）** は、常に開発者の重い足かせであった。
- **専用作画ソフトの悪夢**:
  三菱「GT Designer」、オムロン「NB-Designer」、キーエンス「VT STUDIO」、Pro-face「GP-Pro EX」など、数十万円単位のライセンス費用、USBドングル、Windows限定、バージョン不整合（v2で開いた画面がv3で崩れる等）の泥沼。
- **作画とアドレス帳の二重管理**:
  「D100のビット3がONになったらランプを赤くする」という設定を手作業で何百箇所もマウスで設定。PLC側のラダー変更でアドレスが1つズレれば現場で機械が誤動作・大事故を引き起こす。
- **ハードウェアの異常な高価格とディスコン恐怖**:
  10〜15インチのタッチパネルが1台30万〜80万円。万が一故障しても数年前の型番は廃番（ディスコン）になっており、現行品に置き換えるためだけに画面を一から作り直す悲劇が日常化している。

### 2.2 Arduinoの呪縛：「シリアル＝ただの文字表示器」
Arduinoはマイコンの民主化を達成したが、その開発体験（UX）においてUSBシリアルは「`Serial.println("val")` で文字を流すデバッグ用テキストコンソール」の域を出なかった。
リッチなGUIを求めるなら「Processingで自作してね」「Python/Tkinterで書いてね」とユーザーに丸投げされ、OSごとのシリアルドライバ問題や環境構築の壁によって、多くの開発者がGUI化を断念した。

### 2.3 M5Stackの呪縛：「画面はマイコン自身に載せるもの」という錯覚
M5Stackは「マイコンの横に2インチのTFT液晶を一体化した」ことで大ヒットした。
しかしその代償として、開発者は **C++で画面の座標計算（`M5.Lcd.setCursor(x, y)`）やフォント描画を行うという、1980年代のファミコン開発のような苦行** に引き戻された。
現場の作業員が、老眼に厳しい極小画面を爪の先でポチポチ押すという本末転倒が生じている。

### 2.4 技術的制約：なぜ過去には不可能だったのか？
最大の理由は、**数年前までWebブラウザがハードウェア（USB/シリアルポート）に直接アクセスすることをセキュリティ上許されていなかった（サンドボックス）** という物理的限界にある。
かつてブラウザからマイコンを操作しようとすれば、PC内にNode.jsサーバーを立て、WebSocketで中継するという極めて重厚な仕掛けが必要であり、現場導入など到底不可能であった。

## 3. 特異点：なぜ「スマホ $\times$ ブラウザ」が最強の産業用HMIになるのか？

2020年代半ば、以下の3つの技術的潮流が同時に合流したことで、歴史の特異点が生じた。

1. **WebSerial API の標準化（Chromium系ブラウザ）**:
   プラグインも中継サーバーも不要。ブラウザ内のJavaScriptから直接USB-UARTポート（RS-485）を開放できるようになった。
2. **スマートフォンのUSB-C統一（Android / iPhone 15以降）**:
   現場作業員がポケットに入れているスマホが、100円ショップのUSB-Cケーブル1本で産業用ハードウェアと物理的に結線可能になった。
3. **生成AI（LLM）の爆発的普及**:
   AIが最も得意とするコード体系は、世界で最も標準化され情報が溢れている **HTML5 / CSS / JavaScript** である。

```
                     ┌──────────────────────────────┐
                     │   現場作業員のポケットの中     │
                     │    ・4K 有機EL ディスプレイ    │
                     │    ・超高速GPU / ギガバイトRAM│
                     │    ・静電容量式マルチタッチ    │
                     └──────────────┬───────────────┘
                                    │ USB-C 有線直結 (ゼロ・ネットワーク)
                     ┌──────────────▼───────────────┐
                     │         ADX Core-D           │
                     │    ・現場リアルタイム制御      │
                     │    ・RS-485 差動通信          │
                     │    ・Flash 16KB / RAM 2KB    │
                     └──────────────────────────────┘
```

### 3.1 人類全員が4Kタッチパネルを持ち歩いている
もはや、制御盤に30万円の低解像度GOTを取り付ける必要も、マイコンに2インチの豆粒液晶をハンダ付けする必要もない。
現場作業員のポケットの中には、すでに世界最先端の超高精細・マルチタッチ液晶が存在している。これを「盤のHMI」としてそのまま使えばよい。

### 3.2 有線直結（USB-C）がもたらす「ゼロ・ネットワーク」の絶対安心
工場の現場で最も忌み嫌われるのが「現場Wi-Fi」「DHCP」「IPアドレス管理」である。
- 工場の鉄骨やインバータノイズでWi-Fi電波が途切れる。
- 突発的に持ち込んだWi-FiルーターのDHCP競合で工場内LANが爆発する。
- 企業の情シス部門によるセキュリティ審査に数ヶ月かかる。

**USB-Cケーブルによる有線直結（WebSerial）は、これらすべての問題を一瞬で消滅させる。**
IPアドレス設定は不要、電波干渉ゼロ、社内LANへの接続不要、セキュリティ審査不要。ケーブルを挿した瞬間に100%確実に通信が成立する。

### 3.3 AIが「専属のGOT作画エンジニア」になる
従来のGOT画面はプロプライエタリなバイナリデータであり、ChatGPTやClaudeなどのAIが直接画面を編集することは不可能だった。
しかし、Web（HTML/CSS/JS）であれば話は一変する。
現場で「ノード1のモーター速度スライダーと、ノード2の圧力ゲージを監視するダークモードの画面を作って」とスマホのAIに頼めば、**数秒で完璧に動作するHTMLコードが出力される**。
専用ソフトの教育コストはゼロになる。

### 3.4 据付型（ラズパイ / N100ミニPC）から可搬型（スマホ）までの完全互換
このアーキテクチャの破壊力は、スマホだけに留まらない。
- **据付型（固定盤）**:
  ラインに固定設置する場合、**Intel N100搭載のファンレス産業用ミニPC（2〜4万円）** や **Raspberry Pi（1.5万円）** に市販HDMIタッチモニタ（2〜4万円）を接続し、Chromiumをキオスクモード（全画面表示）で起動する。
  従来のGOT（50万〜80万円）の1/10以下のコストで、圧倒的に美麗なHMI盤が完成する。
- **可搬型（巡回保全）**:
  保全マンがスマホを持って巡回し、盤面のUSB-Cに挿すだけで手元リモコンになる。

**レスポンシブWebデザイン（CSS）により、「据え置きの大画面」も「ポケットのスマホ」も、まったく同じ `index.html` ＋ `adx.js` という単一のアセットで完全稼働する。**

## 4. コアアーキテクチャ：「adx.h — BR32 — adx.js」の三位一体構造

この巨大なビジョンを破綻させず、産業用グレードの信頼性を担保するための設計が、**「`adx.h` — BR32 — `adx.js`」の三位一体構造** である。

```
 ┌──────────────────────┐         ╔════════════════════╗         ┌──────────────────────┐
 │        adx.h         │  ◀───▶  ║        BR32        ║  ◀───▶  │        adx.js        │
 │  (Arduino C++ Lib)   │         ║  (Protocol Spec)   ║         │  (Browser JS Lib)    │
 └──────────────────────┘         ╚════════════════════╝         └──────────────────────┘
      マイコンの臓器                     不変の背骨                    人間の目と指
   （反射神経・安全停止）              （Single Source of Truth）       （UI/UX・Web-GOT）
```

### 4.1 なぜ「BR32」は絶対に揺らいではならないのか？
三位一体において、中央の **BR32** は単なる通信方式ではなく、両者を繋ぐ **「不可侵の憲法」** である。
もし通信層に「たまに化ける」「タイミングによって1バイトズレる」という妥協が1ミリでも残っていれば、画面でボタンが効かない時に「HTMLのバグか？ JSのバグか？ 通信のバグか？ マイコンのバグか？」と現場が疑心暗鬼になり、プロジェクト全体が大地震のように全壊する。

WU-5-1において実証された以下の仕様は、この三位一体の揺るぎない岩盤である：
1. **物理層**: RS-485 半二重差動通信（19,200 bps）
2. **フレーム同期**: **Half-Baud Re-open Trick** による完全同期 LIN Break ＋ Sync `0x55`
3. **固定長データリンク**: 32 バイト固定長フレーム（メモリ破壊ゼロ、動的確保ゼロ）
4. **完全性検証**: CRC16（CCITT-FALSE）による厳格なビット化け排除

### 4.2 マイコン側：`adx.h`（Arduino C++）の責務
マイコン（ATtiny1616等）は、画面描画や複雑な通信処理から完全に解放される。
責務は「制御ループを回すこと」と「変数をバインドすること」の2点のみに純化される。

```cpp
// スケッチ側イメージ：共有したい変数を登録するだけ
#include <adx.h>

ADXNode adx(0x01); // ノード1
uint8_t  motor_speed = 0;   // レジスタ 0x10
float    temperature = 0.0; // レジスタ 0x20

void setup() {
    adx.begin();
    adx.bind(0x10, &motor_speed);
    adx.bind(0x20, &temperature);
}

void loop() {
    adx.poll(); // BR32通信ハンドリング ＆ ブートローダー起動待機
    temperature = read_sensor();
    analogWrite(PIN_PWM, motor_speed);
}
```

### 4.3 ブラウザ側：`adx.js`（JavaScript）の責務
ブラウザ側は、jQueryのように直感的なAPIを提供し、WebデザイナーやAIがマイコンを意識せずにUIを構築できるようにする。

```javascript
// ブラウザ側イメージ：レジスタ番地を叩くだけ
import { ADX } from './adx.js';

const adx = new ADX();
await adx.connect(); // WebSerial ポートオープン

const node = adx.node(0x01);

// UIからの指示をマイコンへ
document.getElementById('slider').oninput = (e) => {
    node.write(0x10, e.target.value);
};

// マイコンからのデータを画面へ
node.on(0x20, (temp) => {
    document.getElementById('temp').textContent = `${temp.toFixed(1)} ℃`;
});
```

さらに、HTMLカスタム属性を用いた **Declarative HMI（宣言的UI）** により、JSすら書かずにHTMLタグだけで双方向バインディングが成立する世界を目指す：
```html
<input type="range" min="0" max="255" adx-node="1" adx-reg="0x10">
<span adx-node="1" adx-reg="0x20">-- ℃</span>
```

## 5. 表現レイヤーの多極化：Web-GOTを超えてUnity（デジタルツイン）へ

本構想の議論において最も重要な転換点は、**「`adx.js`（Web-GOT）にこだわりすぎてはならない」** という気付きである。
`adx.h` と `BR32` という堅牢な背骨（Single Source of Truth）が存在する以上、それを受け止める「表現の器」はブラウザのHTMLだけに限定される必然性はない。

むしろ、ゲームエンジン（Unity / Unreal Engine）と直結した瞬間、産業界が現在数千万円〜数億円を投じている「デジタルツイン」市場を根底から破壊する。

```
                    ┌────────────────────────────┐
                    │      ADX 実機・マイコン     │
                    │         ( adx.h )          │
                    └──────────────┬─────────────┘
                                   │
                        ╔══════════╧══════════╗
                        ║    BR32 Protocol    ║  ◀── 【不変の背骨・憲法】
                        ║ (RS-485 / Half-Baud)║
                        ╚══════════╤══════════╝
                                   │
         ┌─────────────────────────┼─────────────────────────┐
         ▼                         ▼                         ▼
   【 adx.js 】              【 adx.cs 】              【 adx.cpp 】
  Web / スマホ              Unity / .NET              Unreal Engine
  オープンソースGOT          リアルタイムデジタルツイン  超重量級物理シミュレータ
  日常の保全・HMI           展示会・舞台演出・ロボット  VR / メタバース連携
```

### 5.1 数千万円の「産業用デジタルツイン」市場の破壊（1/1000への爆縮）
現在、大手製造業が工場設備のデジタルツイン（バーチャルコミッショニング）を構築しようとすると、大手CAD/PLCベンダー（シーメンス、ダッソー、三菱電機等）による専用シミュレーションソフト（NX MCDやGemini等）の年間ライセンス、通信サーバー（OPC-UA等）のSI費用などで **5,000万円〜数億円** の巨額投資が必要となる。
その結果、日本全国の99%の中小工場やロボットベンチャーは門前払いされている。

しかし、**`adx.cs` を介してUnityと直結した場合**：
1. **実機と3D空間の即時シンクロ**:
   ADXのRS-485から届くパケットを、Unity側のC#スクリプトで数行バインドするだけで、実機のモーター回転やセンサー値が、画面内の超高精細な3Dアームやコンベアとミリ秒単位で同期する。
2. **コストの圧倒的民主化**:
   数千万円の産業用シミュレータではなく、無料〜月数千円で利用可能なUnityと、Asset Storeの美麗な3Dモデル（数百円〜数千円）を組み合わせることで、**総額数万円〜数十万円で世界最高峰のリアルタイム・デジタルツインが構築可能** になる。
3. **ゲームエンジンの圧倒的表現力**:
   10年遅れの産業用シミュレータのワイヤーフレームのような画面とは比較にならない、最新の物理演算（PhysX）とフォトリアルなライティングが手に入る。

### 5.2 展示会・舞台演出での決定的インパクト
展示会（国際ロボット展等）において、大手PLCベンダーが立ち並ぶグレーの巨大制御盤と1990年代風GOT画面の横で、ADXが以下を実演した時の破壊力は計り知れない：
- 手のひらサイズのADX基板から伸びた細いRS-485ケーブル。
- 巨大スクリーンに映し出されたUnityの美麗な3Dメカが、実機の動きと寸分違わずシンクロ。
- 手元のスマホブラウザ（`adx.js`）でスライダーを動かした瞬間に、実機と3D空間が同時に駆動。

**「PLCは使っていません。画面ソフトは何十万円もする専用ソフトではなく、無料のUnityとWebブラウザです」**
これを目にしたエンジニアは、従来のPLCやGOTではもはや勝負にすらなっていない（パラダイムが世代ごと交代した）ことを直感的に理解する。

## 6. 開発・保全ライフサイクルの革命

この構造がもたらす最大の恩恵は、「日常の運用（HMI/GOT）」、「高度な仮想化（Digital Twin）」、そして「緊急時の改修（Flasher）」がすべて同一プロトコル上で地続きになることである。

### 6.1 「IDEはGOTの亜種に過ぎない」という真実
従来の開発者は「まずIDEがあり、そのオマケとして表示器（GOT）がある」と考えがちであった。
しかし、産業設備の生涯（10年間）において、プログラムを書き換える「開発（IDE）」の時間は全体のわずか **0.1%** であり、残りの **99.9% は「人と機械が対話する運用・保全（GOT）」** である。

日常の対話（GOT）を中心に据えることで、日常画面の延長線上にデバッグ画面やファームウェア更新（Flasher）が自然に統合される。

### 6.2 「リセットボタンを押さない」ファームウェア書き込み
`adx.h` とホスト側SDK（`adx.js` 等）の連携により、以下のシーケンスが実現する：
1. 画面上で「新ファームウェア書き込み」をタップ。
2. ホストが `adx.h` に対して `CMD_ENTER_BOOTLOADER` を送出。
3. `adx.h` がアクチュエータ（モーター・バルブ等）を安全にフェールセーフ停止させ、マイコンをリセットして BR32 ブートローダーへ突入。
4. ホストが WU-5-1 で実証された Half-Baud プロトコルを用いて、新HEXファイルを100%確実に書き込む。
5. 書き込み完了後、新スケッチが即座に起動し、画面も自動的に運用モニタへと復帰する。

作業者は、制御盤の扉を開けて基板上のリセットボタンを探す必要もなく、手元の画面操作だけで完全な有線OTA更新を完遂できる。

## 7. 結論と今後の展望

「Arduino IDEをスマホ化したい」「GX Worksをスマホ化したい」という問題意識から始まった探求は、
**「`adx.h`（マイコン） — `BR32`（不変の憲法） — マルチ表現SDK（`adx.js` / `adx.cs` / `adx.cpp`）」**
という、産業用オートメーションからゲームエンジン・エンタメまでを一網打尽にするグランドデザインへと到達した。

```
                    ┌────────────────────────────┐
                    │      ADX エコシステム       │
                    └──────────────┬─────────────┘
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         ▼                                                   ▼
【マイコン層 (adx.h)】                                【表現レイヤー (SDKs)】
 ・Flash 16KB 超軽量スタブ                             ・adx.js  : スマホ / Web-GOT / Flasher
 ・状態変数 (レジスタ) バインド                        ・adx.cs  : Unity / デジタルツイン / 展示
 ・安全停止 ＆ ブートローダー遷移                      ・adx.cpp : Unreal Engine / VR
         ▲                                                   ▲
```

# ADX 市場進出戦略（改訂版）：CORE-U Crowd Supply 直行 ＆ 50打席コミュニティ構築計画

- **文書 ID**: `PLAN-ADX-GTM-002`
- **対象プロジェクト**: ADX Modular Hardware Ecosystem (`8858 Form Factor` / `ADX-BUS-SPEC-v4.2`)
- **第1弾ローンチ対象**: `ADX CORE-U` (ATtiny1616-MNR / 3.3V 10MHz / デュアルType-C) ＋ 実用CARDスターターキット
- **最終ゴール**: Crowd Supply 初戦突破を経由した **Mouser Electronics での世界流通**（および将来の `CORE-A` / `PRO` 展開への基盤確立）
- **作成日**: 2026-11-24
- **経緯・旧案**: [Tindie_or_Crowd_Supply_20261124.md](Tindie_or_Crowd_Supply_20261124.md) の構造的な「無理・斑・無駄」を踏まえた戦略転換版

## 1. 戦略転換の背景：旧案の破綻点と3つの現実認識

旧案（Tindie向けに `CORE-C` を分離し、本命 `CORE-U` を Crowd Supply へ温存する案）は、プラットフォーム規約を回避するためだけにハードウェア構成を歪めた結果、以下の「無理・斑・無駄」を引き起こしていた。

- **無理**: `ATtiny1616 + CH342K` の代替となる当て馬MCU（`CORE-C`）が技術的に成立しない。また、無名状態で実用CARD抜きの基板をTindieに置いても閑古鳥になり、前提の実績獲得自体が機能しない。
- **無駄**: 本命に引き継がれない別アーキテクチャ（RISC-V等）の二重設計・製造・サポート・SKU増加、および初期ユーザーの分断。
- **斑（ムラ）**: `CORE-U`（本来は Standard / 無印グレード、3.3V 10MHz動作）に `PRO` 相当の産業用途・5V前提の文脈が混在し、製品像がぼやけていた。

これらを解体し、以下の **3つの冷徹な現実認識** を戦略の土台に据え直す。

### 現実認識①：最初の「海を渡る実戦」は、シンプルで低リスクな `CORE-U` で行うべき
- Crowd Supply → Mouser 流通では、認証対応（CEマーキングまたはEU免除書面・RoHS）、米国輸出管理分類（EAR99/ECCN）、梱包仕様、テキサス（Mouser倉庫）への一括納品、英語サポートなど未経験の工程を初めて通すことになる。
- そのノウハウがゼロの状態で、複雑・高価・安全責任も重い産業用 `CORE-A`（絶縁RS-485 / DC24V / -40℃〜+105℃保証）から始めるのはリスクが高すぎる。
- **完全SMD・部品点数極小・原価約 \$3.83（120枚約 \$460）・全数自動検査可能な `CORE-U`** こそ、初めて海を渡り量産供給ノウハウを蓄積するための最適な初戦機である。

### 現実認識②：日本からアメリカで認知を取る難易度を直視し、「1発バズ」ではなく「50打席の確率論」で戦う
- 日本（地方）に居ながらにして米国市場で認知度を獲得するのは、アートシーンの新興作家が日本からNYで認知を取ろうとするのと同じレベルで困難である。
- 渾身の1本でバズを狙う戦法は運ゲーであり、現実には閑古鳥で終わる可能性が高い。
- Crowd Supply 公式ガイド（*Building Your Open Source Community*）自身も「コミュニティ構築には長い時間と先行投資が不可欠」と明言している。
- したがって、**「物量＝試行回数（PV数・コメント獲得確率）」** と捉え、**最長1年間・週1本（約50打席）しつこく投下し続ける時間軸**を最初から正攻法として受け入れる。

### 現実認識③：ポストSNS時代のリアルに合わせ、「フォロワー不要で人が生きている場」だけに絞る
- X や Instagram 等のタイムライン型SNSは、外部リンク冷遇アルゴリズム・ノイズ・AI生成コンテンツの氾濫により、無名個人開発者がフォロワーを増やして送客するコスパが極めて低い。`Hackaday.io` のプロジェクト置き場単体も受動的には過疎化している。
- 一方で、**フォロワー数ゼロでも実物と技術の中身だけで生身の反応が返ってくる場**は以下の4箇所に絞られる：
  1. **Reddit**（トピック別掲示板：最も生の議論・ツッコミ・要望が集まる主戦場）
  2. **YouTube**（通常動画＋60秒Shorts：検索・関連動画で電子工作・3Dプリンタ層に長期到達）
  3. **Hacker News（`Show HN`）**（完全実力主義のエンジニア議論の場）
  4. **人間が編集する海外ハードウェア専門メディア**（`Hackaday.com` 本体の Tip Line、`CNX Software`、`Electronics-Lab`、`Adafruit Blog` 等）
  - ※ これらのメディア・コミュニティは、企業風の「プレスリリース（売り込み）」を嫌う一方、**「未発売（Not for Sale）のオープンハードウェア実機・設計ログ」** を最も好んで取り上げる。

## 2. 新戦略の全体像：「Not for Sale × 50打席 × CS直行（可逆ピボット設計）」

`CORE-U` を先に Tindie やスイッチサイエンスで売らない（＝Crowd Supply の Originality 規定 *"anything that has been or is currently selling anywhere else"* を100%無傷に保つ）。

```text
[Stage 0] CORE-U rev4 実機 (EVT) + 3Dプリント筐体 + 比較用Arduino実物
    │
    ▼
[Stage 1] 受け皿の最小整備（arle.cc 英語記事 + Giscusコメント欄 + Waitlist 1問フォーム + YouTube + 名刺用X）
    │
    ▼
[Stage 2] Not for Sale で最長1年・週1投下（約50打席：Reddit主軸 + YouTube + arle.cc 同時ストック）
    │     ※ 途中で手応えが出た切り口・実機動画で Hackaday.com Tip Line / CNX / Show HN へ投下
    │     ※ 3・6・9ヶ月目で「前倒し申請ゲート」を判定
    ▼
[Stage 3] 集まった実績・コメント・Waitlist・要望ベースの実用CARDキットで Crowd Supply へ申請
    │
    ├──▶ 【通過 (Go)】PMとPre-Launch開設 → Waitlistへ一斉通知 → 製品化ニュース(2段目露出) → Mouser流通
    │
    └──▶ 【リジェクト (Pivot)】審査官からの生のフィードバックを回収
           → 翌週から CORE-U を Tindie + スイッチサイエンス委託販売へ即切替（Waitlist/動画/記事を100%流用）
           → 指摘事項を潰した CORE-A (PRO) で2戦目の Crowd Supply へ挑む
```

### この構造で消える「無理・斑・無駄」
- **不可逆性の向きを正しく使える**: 先に売ると CS への道が永久に閉じるが、「売らずに CS へ挑み、落ちたら翌週 Tindie＋スイサイへ切り替える」なら**完全に可逆でノーリスク**。
- **1年間の活動が1ミリも無駄にならない**: CS に通れば Pre-Launch の初速になり、落ちてもそのまま Tindie / スイッチサイエンスの初期購入者リスト・販促動画・公式ドキュメント資産になる。
- **当て馬 `CORE-C` 不要**: SKU を増やさず、`CORE-U` と 8858 規格にリソースを100%集中できる。

## 3. 自社側の受け皿（最小構成・管理負荷ゼロ設計）

SNSの複数運用や過疎るコミュニティ基盤は作らず、**「毎日更新しなくても資産が積み上がる最小4点」** のみに絞る。

| 窓口 | 役割 | 運用方針・実装メモ |
| :--- | :--- | :--- |
| **`https://arle.cc/adx/`（英語記事）** | 技術的中核・リンク先 | 「売り込みLP」ではなく、8858・CORE-U の設計理由を語る Engineering Write-up と開発ログを配置。 |
| **`Giscus`（記事直下の公開コメント欄）** | 記事読者の技術議論 | Astro Starlight 記事末尾に埋め込み。`Masafuro/ADX` の **GitHub Discussions** と自動同期し、管理を一元化。 |
| **Waitlist ＋ 任意1問アンケート** | アカウント不要の要望・見込客回収 | 記事末尾に控えめに配置：<br>*"Not for sale yet. Exploring a Crowd Supply run if there is interest."*<br>任意1問：*"What would you build with it, or what CARD / feature would you want?"* |
| **YouTube チャンネル** | 動画ホスティング・検索流入・コメント | Shorts（15–60秒）と通常動画（60–90秒）を蓄積。コメント欄も重要な意見の受け皿。 |
| **X (Twitter) 1アカウント** | 実在証明（名刺代わり） | 毎日運用して伸ばそうとしない。大きな記事・動画公開時の告知と、海外メディア・CS担当者の連絡先・メンション受け皿として置く。 |

- **あえて作らないもの**: 初期の Discord サーバー／独自フォーラム（人数が少ない時期は過疎感が逆効果かつ管理コストが無駄）。Mastodon / Bluesky の義務的な日常運用（将来CS通過前後で必要になれば告知コピー枠だけ検討）。

## 4. 工数爆発させずに「週1本 × 50打席」を回す『開発副産物スライス設計』

**「50投稿 ＝ 50個の別々の物理作品を作る」という前提を捨てる。**
普段のハードウェア設計・試作・検証・治具づくり・3Dプリントの「副産物（おこぼれ）」を15〜60秒のクリップや1枚の写真にスライスすることで、**新規の実用作品開発を年間5〜10個以下**に抑えつつ50打席を完走する。

### 4.1 50打席のカテゴリ配分モデル

| カテゴリ | 目安本数 | 追加開発工数 | 内容の例 | 主な投下先 |
| :--- | :---: | :---: | :--- | :--- |
| **① 普段の開発・検証の「ついで撮り」** | **約20本** | ほぼゼロ（机上スマホ固定15–30秒） | ・eFuse (`AP22814`) 出力ショート保護テスト<br>・JLCPCB 6枚面付けVカットを手で割る動画<br>・ポゴピン自動検査治具での3秒全数検査<br>・シリアルモニタ開いたままSerialUPDI書込<br>・M3ネジ＋ワッシャー締結の従来Arduino比較<br>・ボツ基板（8748→8854→8858）変遷並べ | `r/electronics`<br>`r/PrintedCircuitBoard`<br>`r/embedded`<br>YouTube Shorts |
| **② 共通8858基板用 3Dプリント筐体・マウント** | **約15本** | 小（CAD 1–2h＋印刷のみ・回路変更ゼロ） | DINレールアダプタ、壁掛けブラケット、マグネットベース、2段スタック治具、市販防水ケース用インナープレート、10インチラック、三脚マウント、スナップフィット蓋等（STLを Printables / GitHub 公開） | `r/functionalprint`<br>`r/3dprinting`<br>Printables<br>YouTube Shorts |
| **③ 賛否・議論を呼ぶ設計判断の言語化** | **約5–10本** | 小（写真＋図解＋短文） | ・なぜESP32ではなくATtiny1616か<br>・なぜピンヘッダではなく20P IDCか<br>・Arduinoを箱に入れると踏む5つの地雷<br>・なぜデュアルType-Cで電源と通信を完全分離したか | `r/embedded`<br>`r/arduino`<br>`r/electronics`<br>Show HN / EEVblog |
| **④ 実用デモ作例（将来のCARD試作兼用）** | **約5–10本** | 中（1–2ヶ月に1回ペース） | 3Dプリンタエンクロージャ換気制御箱、AAA乾電池自律センサー箱、リレー制御箱など、**そのまま将来の実用CARD候補・公式リファレンス作例になるものだけ**を作る | `r/3dprinting`<br>`r/homeautomation`<br>`r/arduino`<br>YouTube 通常動画 |

### 4.2 運用上の鉄則（1撮影3ストック ＆ Reddit BAN回避）
1. **1撮影 → 3箇所同時ストック**: 同じ15–60秒の動画・写真を **①Reddit（議論・コメント稼ぎ）**、**②YouTube（長期ストック）**、**③`arle.cc`（ログ・FAQ・Waitlist誘導）** の3箇所に数分で横展開する。
2. **純粋な技術コンテンツとして出す**: Redditでは「これ見て／買って」という宣伝文句を一切排除し、その動画・写真単体で楽しめる技術ネタにする。
3. **リンクを押し売りせず板をローテーションする**: 外部URL（`arle.cc` / GitHub）は毎回本文に貼らず、プロフィール固定＋コメント欄で「それ何の基板？」と聞かれた際の返信を基本とする（体系的な紹介ポストは数回に1回に留める）。
4. **全コメントへ誠実に返信し、FAQと設計へ反映する**: 批判・疑問（「なぜ16KB？」「3.3Vなの？」「ここはこうしてほしい」）に真摯に答えて `arle.cc` のFAQや次期CARD設計へ反映した履歴そのものが、Crowd Supply 審査で最も評価される実績になる。

## 6. 実行ロードマップと「前倒し申請ゲート」

最長1年（50打席）の持久戦を前提としつつ、**3・6・9ヶ月目に評価ゲート**を置き、十分な実績と手応えが揃った段階で前倒し申請する。

### Phase 0：基盤と実機の立ち上げ（Month 0–1）
- `CORE-U rev4` 配線完了 → JLCPCB PCBA 試作発注・動作確認（EVT完了）。
- 比較用の「ダメな例（従来Arduinoのケース収納破綻）」実物と、8858基本3Dプリントケースを用意。
- `arle.cc` に英語の中核記事（Engineering Write-up）、`Giscus` コメント欄、Waitlist＋1問アンケートを設置。
- YouTube チャンネルおよび名刺用 X アカウントを開設し、[astro.config.mjs](../../site/astro.config.mjs) の `social` へ接続。

### Phase 1：打席開始 ＆ 当たり切り口の探索（Month 1–3 / 1〜12打席）
- 週1ペースで「ついで撮り検証動画」「3Dプリントマウント」「設計議論」を Reddit＋YouTube＋`arle.cc` へ投下開始。
- どの切り口（筐体固定？保護回路？検査治具？シリアルモニタ併用書込？）と、どの実用CARD要望が最も強いかデータを取る。
- **【Gate 1（3ヶ月目）】** 初期反応の分析。伸びない切り口を捨て、反応が良い領域へ後半のリソースを寄せる。

### Phase 2：中核動画の仕上げ ＆ 海外専門メディアへの「Not for Sale」投下（Month 4–6 / 13〜25打席）
- Phase 1 のツッコミをすべて FAQ へ反映したうえで、60〜90秒のコア動画と横長の高解像度写真（5〜8枚）を撮影。
- プレスリリース口調を避け、「未発売のオープンハードウェア実機」として以下へ個別送付・投下：
  - **Hackaday.com Tip Line**（`tips@hackaday.com`：開発者個人の率直な短文メール）
  - **CNX Software**（Tip Us：技術仕様・写真・GitHubサマリー）
  - **Electronics-Lab**（Project Upload） / **Hackster.io** / **Adafruit Blog**（Blogtip）
  - **Hacker News（`Show HN`）**
- **【Gate 2（6ヶ月目）】** メディア掲載・濃いコメント群・Waitlist 登録・要望の多い実用CARDの目処が揃っていれば、**前倒しで Crowd Supply 申請へ移行**。まだ薄ければ Phase 3 へ継続。

#### 【物理ブーストオプション】米国現地イベントでの「名刺代わり 120枚配布」（王道ショートカット）
日本から原価\$4級の基板を1枚ずつ国際発送する「送料問題」と「米国での地盤（コネ）不足」を一撃で突破する物理オプション。実施可否は予算・語学体制を踏まえて Gate 1〜2 時点で判断する。

- **有力ターゲット**:
  - **Crowd Supply Teardown 2027**（**2027年6月11日–13日** / オレゴン州ポートランド・Jupiter Hotel）：ちょうど本計画の6ヶ月目に合致。Crowd Supply 本社の創業者・審査担当・PM、Mouser関係者、Hackaday記者、濃いオープンハードウェア開発者が小規模会場に集結する本丸。Demo Table / Lightning Talk 応募も視野。
  - **Hackaday Supercon**（例年11月頃 / カリフォルニア州パサデナ）：自作マイコン基板を名刺代わりに配り合う文化の聖地。
- **概算コスト**: `CORE-U` 120pcs（JLCPCB PCBA・送料込 約\$460 ≒ 約7万円）＋副資材（静電袋・カード・デモ機等 3–8万円）＋ 渡航費（30–40万円）＝ **総額 45–55万円規模**（一般的な海外展示会出展の数分の1）。
- **規約・税関・語学の現実解**:
  - 販売ではなく **"Not for Sale / Engineering Samples"**（無償評価サンプル）として持参するため、Crowd Supply の Originality 規定と100%両立し、税関申告も原価明細ベースでクリーンに処理可能。
  - `8858`（88×58mm）はほぼ名刺サイズそのもの。英語で流暢に話せなくても、**「①従来Arduinoのケース破綻実物 vs 8858収納実物」「②`arle.cc` の英語記事・Waitlistへ直結するQRコード付き台紙」「③スマホのリアルタイム翻訳」** を組み合わせることで、ハードウェアの実物勝負に持ち込める。

### Phase 3：キット確定 ＆ 継続蓄積（Month 7–9 / 26〜38打席）
- Waitlist アンケートとコメント欄の要望に基づき、CS申請時に同梱する **実用CARD（1〜2種）のEVT試作** を完了させ、その開発・試験自体を週1打席のネタとして投下し続ける。

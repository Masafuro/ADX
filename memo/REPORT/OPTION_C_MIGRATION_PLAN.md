# オプションC（docs/多言語分離構成）への移行作業計画

本ドキュメントは、ADX リポジトリの多言語展開（英語・日本語）およびドキュメント体系の整理に向けた、**オプションC（`docs/` ディレクトリによる多言語分離）** の実施作業計画書です。

---

## 1. 目標とするリポジトリ構造

公開用ドキュメントを `docs/` 配下に言語別（`en/`, `ja/`）で分離し、ルートの `README.md` をポータル兼グローバル概要として位置付けます。開発メモ（`memo/`）と公開仕様（`docs/`）の役割を明確に切り分けます。

```text
ADX/
├── README.md                   # グローバルポータル（英語概要 ＋ Language Switcher ＋ クイック仕様）
├── docs/                       # 公開ドキュメント（多言語）
│   ├── en/                     # 英語版ドキュメント
│   │   ├── README.md           # 英語メインドキュメント
│   │   ├── 8748_formfactor.md  # 8748 Form Factor Specification (EN)
│   │   └── ADX_pinout.md       # ADX Pinout Specification (EN)
│   └── ja/                     # 日本語版ドキュメント
│       ├── README.md           # 日本語メインドキュメント
│       ├── 8748_formfactor.md  # 8748 フォームファクタ仕様書 (JA)
│       └── ADX_pinout.md       # ADX ピンアサイン仕様書 (JA)
├── dev/                        # ハードウェア設計・製造データ（言語非依存）
│   ├── ADX_Core-D/
│   │   ├── proposal.md
│   │   └── data/
│   └── CARD/
│       └── Prototyping/
│           ├── proposal.md
│           └── data/
├── memo/                       # 開発メモ・作業用レポート
│   ├── REPORT/                 # 提案書・計画書・レポート群
│   └── old/
└── Project_Snapshot.md         # プロジェクト進捗・概要
```

---

## 2. 移行ステップ（作業フェーズ）

作業は以下の 5 つのフェーズに分けて段階的に進めます。

### フェーズ 1: ディレクトリ構造の準備
1. `docs/en/` および `docs/ja/` ディレクトリを作成。
2. ドキュメント間の相対リンク設計ルールを確立（`docs/` から `dev/` への参照など）。

### フェーズ 2: 日本語版ドキュメントの移行と整理 (`docs/ja/`)
1. 現在の `memo/8748_formfactor.md` を `docs/ja/8748_formfactor.md` に移行。
2. 現在の `memo/ADX_pinout.md` を `docs/ja/ADX_pinout.md` に移行。
3. 現在の `README.md`（日本語）をベースに `docs/ja/README.md` を作成。
4. 各日本語ドキュメント内のリンクパスを更新。

### フェーズ 3: 英語版ドキュメントの作成 (`docs/en/`)
1. **`docs/en/8748_formfactor.md` の執筆**:
   - メカニカル/エレクトリカル仕様、寸法整合性、理論公差テーブルの英訳。
2. **`docs/en/ADX_pinout.md` の執筆**:
   - 20ピン共通ピンアサイン表、シールド/アイソレーション設計、注記の英訳。
3. **`docs/en/README.md` の執筆**:
   - ADX プロジェクト概要、コア仕様サマリー、ボードラインナップ、ディレクトリ構成の英訳。

### フェーズ 4: ルート `README.md` のポータル化
1. リポジトリのルート `README.md` を英語ベースのグローバルポータルとして再構成。
2. 先頭に言語切り替え（Language Navigation）を設置:
   - `[ English (docs/en) | 日本語 (docs/ja) ]`
3. 概要、主要寸法、ピンアサインの要約、各言語版および各開発ボードへの導線を整理。

### フェーズ 5: リンク検証とリポジトリクリーンアップ
1. 全ドキュメントの相対リンク（画像、データシート、`dev/` 配下ファイル等）のリンク切れを検証。
2. `memo/` ディレクトリ内の公開仕様ファイルを整理し、開発用内部メモとしての役割に特化。

## 3. 各ドキュメントの翻訳・構成方針

| ファイル | 主な記載内容・トーン |
| :--- | :--- |
| **`README.md` (Root)** | 英語ベース。プロジェクトの目的、フォームファクタ・ピンアウトの要約、`docs/en/` / `docs/ja/` への明確なリンク。 |
| **`docs/en/README.md`** | 英語メイン。詳細な仕様解説、ハードウェアラインナップ（Core-D / Prototyping Card）、設計意図。 |

## 4. 期待される効果

1. **グローバル対応とローカル開発の両立**:
   - 海外ユーザーや Crowd Supply 閲覧者はトップの `README.md` および `docs/en/` で直感的に全体像を把握可能。
   - 日本語での詳細な仕様検討やドキュメントも `docs/ja/` 配下に体系的に保持。
2. **ドキュメントの保守性向上**:
   - `docs/` に仕様書を一本化することで、開発メモ（`memo/`）と公式ドキュメントが混ざらず、更新箇所が明確になる。

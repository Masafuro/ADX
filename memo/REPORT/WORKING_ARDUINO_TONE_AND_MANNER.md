## 1. 「はたらくArduino」が目指す立ち位置

ADX の合言葉である **「はたらくArduino (The Working Arduino)」** は、電子工作を愛するすべての人に向けた、等身大の提案です。

```text
［ 机の上のホビー (Playground) ］        【 はたらくArduino (Workplace) 】        ［ 重厚長大な産業用 (Industry) ］
  ・Arduino UNO / 各種互換機                ・ADX エコシステム ＋ CORE-A5           ・各社 産業用PLC / 重電設備
  ・ブレッドボード / 卓上実験               ・部屋の隅、ガレージ、店舗、家庭菜園     ・数十万〜数百万円、巨大制御盤
  ・壊れたら挿し直せばよい                  ・「ちょっとタフで、箱にいれやすい」     ・専用ラダー言語、ブラックボックス
  ・安価だが実地配線には工夫が必要          ・等身大の価格で、現場にすっきり収まる   ・極めて高価、参入障壁が高い
```

机の上で作ったアイデアやスケッチを、実際の部屋の隅、ガレージ、店舗の演出、家庭菜園の棚などへ連れ出そうとしたとき、誰もが「ネジ止めしにくい」「箱に入らない」「配線が抜けないか不安」という壁にぶつかります。

ADX は、高価で難解な「産業用PLC」を押し付けるのではなく、**誰もが慣れ親しんだ Arduino のオープンさや手軽さをそのままに、現場での物理的な困りごとを無理なく解決する「身近で頼もしい相棒」** です。

ドキュメントのすべての言葉は、この立ち位置に立って紡がれなければなりません。

## 2. トンマナの「3大原則」

「はたらくArduino」の文章表現は、以下の **3大原則** を中核規範とします。

```text
               ┌────────────────────────────────────────────────────────┐
               │            【 はたらくArduino の 3大原則 】            │
               │                                                        │
               │   1. 【 親しみやすい 】（工学・理論表現も難解にしない） │
               │   2. 【 誠実である 】  （物理法則と限界に忠実である）   │
               │   3. 【 わかりやすい 】（動線と表現が明確である）       │
               └────────────────────────────────────────────────────────┘
```

---

### 原則 1: 親しみやすい (Accessible & Welcoming)
> **「通常の文章のみならず、工学や理論などのエンジニアリング表現においても難解にせず、直感的に伝わる言葉で語る。」**

1. **工学・理論解説の平易化（マウンティングや難解な業界用語の排除）**:
   - 回路設計、差動信号、ガルバニック絶縁、過渡応答などの専門的なハードウェア理論であっても、難解な専門用語や数式だけで煙に巻くのではなく、「どうして動くのか」「なぜその設計なのか」を直感的な図解や平易な言葉で紐解きます。
   - 「プロの世界の高度な技術」をひけらかすのではなく、「あなたの工作を裏で支えてくれる仕組み」として親しみやすく伝えます。
2. **威圧的・軍事的な言葉を使わない**:
   - ✕「重装甲」「スレーブ」「鉄壁」「戦士」「防壁」「撲滅」
   - ◯「現場に強い」「タフな」「エッジ端末」「誤動作を防ぐ」「手間を減らす」
   - 軍事用語や過度に攻撃的な言葉は、「自分には関係のないプロの怖い世界だ」と初学者を引き返させてしまいます。
3. **暮らしや工作に根ざした具体的な場面を描く**:
   - 抽象的な「過酷な産業プラント」だけでなく、「ガレージの換気扇連動」「家庭菜園の自動水やり」「店舗の間接照明」「3Dプリントケースに収めたインテリア」など、メイカーが自分の日常や作品としてイメージできる具体例を添えます。

---

### 原則 2: 誠実である (Honest & Engineering Integrity)
> **「物理法則と工学的な限界に忠実である。絶対やゼロを軽々しく口にしない。」**

1. **工学的な絶対性・無謬性を主張しない**:
   - ✕「絶対に緩まない」「100%安全」「絶対に壊れない」「死なない」
   - ◯「振動に強く緩みにくい」「誤配線時にもダメージを最小限に抑える」「波及リスクを極限まで低減」
   - 現実のハードウェアに「絶対」は存在しません。過剰な断定はプロのエンジニアからの信用を失い、PL法（製造物責任）上のリスクを招きます。
2. **「ゼロ」「瞬時」の物理的矛盾を排除する**:
   - ✕「自己発熱ゼロ」「起動時間 0ms」「瞬時に保護」「瞬時100%遮断」
   - ◯「極小の自己発熱（密閉ケース内でも熱がこもらない）」「ブート待機遅延なし（即時起動）」「高速な過電流保護（マイクロ秒オーダーで遮断）」
   - ジュール熱、マイコンのPOR（パワーオンリセット）時間、半導体スイッチの過渡応答時間など、物理的な制約を隠さず、正確な事実として誠実に記述します。
3. **設計上の割り切り・トレードオフを正直に開示する**:
   - 「なぜ 10MHz なのか（3.3V での安全動作領域と低発熱を優先したため）」「なぜ 5V 単一受電なのか（発熱源となる高電圧DCDCを分離するため）」といった設計思想の背景を透明に語ります。

---

### 原則 3: わかりやすい (Clear Navigation & Plain Expression)
> **「ユーザーを迷わせない『明確な動線』と、主旨が一瞬で伝わる『明確な表現』を徹底する。」**

1. **ドキュメント間の動線（Navigation）の明確化**:
   - 「自分は今どこにいて、目的を果たすには次にどこへ行けばよいのか」が一目でわかるナビゲーション設計（目的別クイックナビゲーション、明確なリンク誘導、SSOTの明示）を徹底します。
   - ユーザーをドキュメントの迷路に迷い込ませず、必要な情報へ最短ステップで導きます。
2. **表現の主旨・結論（Expression）の明確化**:
   - 回りくどい修飾や前置きを省き、「何ができるのか」「なぜそう設計されているのか」の結論を最初に明快に述べます。
   - 曖昧な表現や二重否定を避け、一読して意図が誤解なく伝わるクリスプ（明瞭）な文章にします。
3. **視覚的・構造的な直感性の担保**:
   - 文章だけで長々と説明するのではなく、Mermaid 図、ASCII アート、ピン配置図、比較表などを適切に配置し、視覚的な直感で瞬時に把握できるようにします。

## 3. 具体的な用語対比マトリクス (DO / DON'T)

日々のドキュメント執筆や改修において参照できる具体的な対比表です。

| カテゴリ | ✕ 避けるべき表現 (DON'T) | ◯ 推奨される表現 (DO) | 理由・トーンの狙い |
| :--- | :--- | :--- | :--- |
| **熱・消費電力** | 自己発熱ゼロ / Zero Self-Heating | **極小の自己発熱** / **ヒートシンク不要の極低発熱**<br>*(英: Negligible Self-Heating)* | ジュール熱の存在を無視せず、密閉ケース内での実用的な優位性を伝える。 |
| **端子・機構** | 長期間の強い振動でも絶対に緩みません | **長期間の激しい振動でも緩みにくく、定期的な増し締めメンテナンスが不要** | 工学的にあり得ない「絶対」を排し、スプリング端子の実用メリットを示す。 |
| **保護・安全性** | 100% 完全保護 / PCが絶対に破損しない / 100%無傷 | **誤配線やサージ侵入時にも接続先PCへの波及リスクを極限まで低減** | 定格を超える高圧サージ時の限界を弁え、誠実な保護性能を説明する。 |
| **起動・時間** | 起動遅延ゼロ (0ms) / 0ミリ秒で即座に起動 | **ブート待機遅延なし (Instant Boot)**<br>*(従来のArduinoにある1〜2秒の待ち時間を排除)* | POR時間等の物理遅延を無視した「0ms」を避け、ユーザー視点の利点を語る。 |
| **保護動作速度** | 瞬時に保護 / 瞬時100%遮断 | **高速遮断保護（マイクロ秒オーダーで電流制限）** | 半導体スイッチの有限な応答時間を正しく踏まえる。 |
| **温度・耐熱** | -40℃〜+105℃ フル保証 | **主要部品に -40℃〜+105℃（産業・車載グレード）品を採用** | 基板完成品としての全数環境試験と誤解される法的な「保証」リスクを回避。 |
| **絶縁仕様** | 2500V 完全絶縁 | **2500V ガルバニック絶縁** *(または 信号・電源アイソレーション)* | 「完全」という情緒的な言葉を排し、正式な工学用語を用いる。 |
| **製品の呼び名** | 現場特化の重装甲スレーブ / 8-bitの戦士 | **高耐環境・高信頼エッジスレーブ** / **現場に強いタフなエッジ基板** | ミリタリー調の威圧感を排し、等身大で頼もしい道具のイメージを与える。 |
| **プロトコル挙動** | 鉄壁の沈黙 / 鉄壁の保護 | **厳格なバスサイレンス（自ノード宛以外の応答を確実に遮断）** | 小説的・誇張表現を排し、プロトコル仕様としての信頼性を示す。 |
| **作業・改善** | 手動スイッチ操作の完全撲滅 | **ケースを開けてスイッチを押す手間を大幅に削減** | 「撲滅」という攻撃的な言葉を、日常の「手間を減らす」という利便性に変換。 |

## 4. ドキュメントの階層別 適用ルール

ADX のドキュメントは 4層構造（SSOT 体系）を採用しています。各層の読者と目的に応じてトーンを適切に使い分けます。

```text
┌────────────────────────────────────────────────────────────────────────┐
│  【 Layer 1: エントリー層 (README.md / docs/ja/README.md) 】            │
│  ・読者: 初学者、メイカー、一般エンジニア                              │
│  ・トーン: 「親しみやすさ」最優先。ワクワク感と安心感、身近な活用例。   │
├────────────────────────────────────────────────────────────────────────┤
│  【 Layer 2: 共通規格・解説層 (docs/spec/ / docs/ja/ADX_pinout.md 等) 】│
│  ・読者: サードパーティ基板設計者、拡張CARD制作者                     │
│  ・トーン: 「わかりやすさ」と「客観性」。図解と設計意図の丁寧な解説。  │
├────────────────────────────────────────────────────────────────────────┤
│  【 Layer 3: ハードウェア個別仕様書 (hardware/CORE-A5/ 等) 】           │
│  ・読者: PCBA製造委託者、回路レビューア、組込技術者                   │
│  ・トーン: 「誠実さ」最優先。BOM、回路定格、応答速度、設計根拠の開示。 │
├────────────────────────────────────────────────────────────────────────┤
│  【 Layer 4: ファームウェア・プロトコル仕様 (firmware/ / docs/memo/) 】 │
│  ・読者: ファームウェア開発者、ドライバ実装者                          │
│  ・トーン: 冷静で決定論的。情緒的修飾語を排し、状態遷移と規約を記述。  │
└────────────────────────────────────────────────────────────────────────┘
```

## 5. まとめ：「誠実さ」こそが最強のブランディング

誇大広告や過剰なキャッチコピーは、一見すると強く印象づけられるように思えますが、現場で実際に手を動かすエンジニアやメイカーに対しては、かえって疑念を生む原因になります。

- **「なぜその部品を選んだのか」**
- **「どこまでを守れて、何が限界なのか」**
- **「どうしてこの形にすると、工作が快適になるのか」**

これらを **「親しみやすく、誠実で、わかりやすい言葉」** でまっすぐに語りかけることこそが、「はたらくArduino」を長く愛され、現場で選ばれ続ける本物のオープンスタンダードへと育てる道です。

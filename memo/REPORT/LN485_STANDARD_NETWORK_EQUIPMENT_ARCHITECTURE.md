## 1. 構想の背景と基本理念

ADX は、建築演出・舞台照明・インタラクティブアート・屋外多点センシングなど、**「過酷なノイズと長距離配線が支配する現場」** において、絶対的な信頼性を持って動作する次世代のオープンソース設備プラットフォームである。

これまで行われた通信検証および理論的分析（`LN485_HOST_STRATEGY_REPORT.md` 参照）を通じ、以下の根本原理が確立された：

1. **現場通信の背骨としての LN-485 (LIN over RS-485 / BR32) の妥協なき堅持**:
   * 一般的な UART（8N1）の文法外にある「11ビット以上の連続 LOW（LIN BREAK）」と「ハードウェア自律遮断（`LINAUTO`）」は、外乱サージやマルチドロップのトラフィックからマイコンを CPU 負荷 0% で守る最強の防壁であり、決して妥協してはならない。
2. **計測・デバッグ工学の絶対公理**:
   * **「観測者（デバッガ・ツール）は、被測定物（ターゲット）より桁違いに高い性能を持たねばならない」**。
   * 現場ノードと同じリソースのマイコンでデバッグやプロトコル変換を兼務させようとすると、観測負荷により自身の足元がグラつき、破綻を招く（ハイゼンバグの温床）。
3. **現場主義（フィールド・ファースト）の徹底**:
   * 池や川の近く、足場の上、防水ボックスの試験に、高価で濡らせないノート PC を持ち込むことは現場のリスク（水没・落下）を高める。
   * 現場作業員のポケットにある **「防滴スマートフォン」** と **「超小型ドングル」** だけで、安全・迅速に現場ノードの診断・書き込み・監視が完結しなければならない。

これらを具現化するため、ADX は **「現場耐久型スレーブ」と「超高知能ドングル」という非対称な二層機材編成** を基幹標準とする。

## 3. 機材 1: 現場実行層（ADX CORE-S / CORE-D）

### 3.1 仕様と役割
* **MCU**: Microchip ATtiny1616-MNR (QFN-20)
  * 8-bit AVR RISC、5V 動作、20MHz、Flash 16KB、SRAM 2KB、EEPROM 128B
* **RS-485 トランシーバー**: MaxLinear SP485EEN (5V 半二重)
* **ハードウェア連携**:
  * USART0 の `LINAUTO` エンジンによる Break 検出・自動ボーレート校正。
  * `XDIR` (PA4) によるハードウェア自動送受信方向制御（Auto-DE）。
  * CORE-S においては BMC (ATtiny412) による VDD ゲーティングおよび遠隔ブート制御。

### 3.2 設計思想：「泥水と熱に耐える 8-bit 5V の戦士」
* 屋外の防水ボックス、真夏の炎天下（密閉空間で 60℃〜85℃ 超）、冬の氷点下、配線ミスによる過電圧サージなど、**「人間が耐えられない過酷な環境」で数年間無停止で生き残ること** が唯一最大の使命。
* ここに 32-bit の複雑な SoC は不要であり、5V で動作し、電気的ノイズに極めて強く、シンプルなステートマシンで確実に動く ATtiny1616 が最高の最適解となる。

## 4. 機材 2: 計測・制御層（ADX Pocket Link / スマートドングル）

### 4.1 ハードウェア仕様
* **コア MCU**: Raspberry Pi **RP2040** (QFN-56)
  * 32-bit Dual-Core ARM Cortex-M0+ @ 133MHz（最大 250MHz 駆動可能）
  * 内蔵 SRAM: **264KB**（ATtiny1616 の 132 倍）
  * 外部 QSPI Flash: **2MB 〜 16MB**
  * チップ単価: **約 $0.80（100円前後）** / 世界的サプライチェーンによる高入手性
* **USB インターフェース**:
  * RP2040 内蔵ネイティブ USB 1.1 PHY（Type-C コネクタ直結）
  * 外付け USB-UART ブリッジ（CH340/FTDI 等）を **完全排除**。
* **物理層インターフェース**:
  * 3.3V 駆動 RS-485 トランシーバー（TI THVD1429、Analog Devices MAX3485、SGMICRO SGM485 等）
  * ※3.3V 駆動の RS-485 トランシーバーは差動規格を満たしており、5V 駆動の SP485EEN（CORE-S 側）と 100% 完全な相互接続が可能。
* **フォームファクタ**:
  * スマホの Type-C ポートに直挿し、または短いケーブルで繋がるキーホルダー/USB メモリサイズ。

### 4.2 コアテクノロジー：PIO (Programmable I/O) による完全物理層制御
RP2040 独自の PIO（プログラマブル I/O ステートマシン）を活用し、CPU や OS の介在を完全に排したナノ秒精度の制御を行う：

1. **完全無欠の LIN BREAK 生成**:
   * PIO が 133MHz（7.5ns 刻み）で正確に 677μs の LOW（13bit Break）＋ 52μs の HIGH（Delimiter）を物理ピンに出力。
   * CPU の割り込み遅延や OS のジッターによる影響は **原理的に 0.00%**。
2. **リアルタイム・バススニッファー**:
   * 電線の立ち下がりから立ち上がりまでの時間を PIO が直接カウント。
   * 「電線上の LOW が何マイクロ秒続いたか」をナノ秒単位で実測し、Break の品質を判定。

### 4.3 デュアルコアによる完全並列処理
* **Core 0**: USB スタック（TinyUSB）に専念。WebUSB 通信およびマスストレージ・エミュレーションを処理。
* **Core 1**: PIO および RS-485 のリアルタイム送受信、スニッフィング、CRC 検証、エラー解析に専念。

## 5. 破壊的ユーザー体験（ソフトウェアスタック）

### 5.1 二刀流機能 1: 「ドラッグ＆ドロップ書き込み」（仮想マスストレージ）
RP2040 の TinyUSB により、ドングル自身が **仮想 USB ドライブ（`ADX_DRIVE`）** として振る舞う：

1. スマホや PC に挿すと、標準の「ファイル」アプリに `ADX_DRIVE` が認識される。
2. ビルドした `firmware.hex`（または `.bin`）をこのドライブにコピー（ドラッグ＆ドロップ）する。
3. ドングル内部のファームウェアが自動的にファイルを解析し、RS-485 電線へ LIN BREAK ＋ BR32 Flash 書き込みパケットを自動送出。
4. 完了後、ドライブ内の `STATUS.TXT` が自動更新され、結果をプレーンテキストで確認できる。
* **意義**: **専用の書き込みアプリが一切不要** となり、現場の作業員は「ファイルをコピーするだけ」でファームウェア更新が可能になる。

### 5.2 二刀流機能 2: 「PWA 現場ダッシュボード」（WebUSB 連携）
ブラウザからアクセスするだけで即座に起動する PWA（Progressive Web App）を提供：

* **単一コードベース（Single Codebase）**:
  * HTML / CSS / JavaScript (TypeScript) で構築され、GitHub Pages から配信。
  * Android、iPad、Windows、Mac、Linux の全プラットフォームで同一の UI が稼働。
* **アプリストア不要 & オフライン動作**:
  * Google Play や App Store の審査・更新ラグなし。現場の電波が届かない場所でもキャッシュから一瞬で起動。
* **リアルタイム・ネットワーク監視**:
  * RS-485 バス上のノード一覧、稼働状態、通信遅延（RTT）、CRC エラー率をグラフィカルに表示。
* **安全な書き込みタイミング制御**:
  * 設備ノードの安全停止コマンドを送信し、停止を確認してからファームウェア書き込みシーケンスをトリガーするフェイルセーフ運用を実現。

## 6. 機材スペック対比の必然性

計測工学・製品設計の観点から、この機材編成の合理性は極めて明確である：

| 比較項目 | 現場スレーブ (CORE-S) | ドングル/デバッガ (ADX Pocket Link) | 差異の工学的意義 |
| :--- | :--- | :--- | :--- |
| **MCU** | 8-bit AVR (ATtiny1616) | **32-bit Dual-Core (RP2040)** | 観測者が被測定物を圧倒 |
| **動作周波数** | 20 MHz | **133 MHz 〜 250 MHz** | **約 7 〜 12 倍** の時間分解能 |
| **SRAM 容量** | 2 KB | **264 KB** | **132 倍**（パケット履歴・FATエミュレート） |
| **Flash 容量** | 16 KB | **2 MB 〜 16 MB** | **128 〜 1000 倍**（複数ファーム保持可能） |
| **I/O 特性** | ハードウェア USART 1系統 | **PIO (8 ステートマシン)** | ナノ秒単位の波形自由度 |
| **動作電圧** | 5V（高ノイズ耐性） | 3.3V（超低消費電力・高速動作） | 現場タフネスと計算力の住み分け |
| **使用環境** | -40℃〜+85℃/125℃（連続無人）| 常温（人間が作業する時間のみ） | 耐熱要件の合理的なトレードオフ |

## 8. 結論

本構想により、ADX は過去のシリアル通信・設備コントローラーが抱えていた **「専用ドライバの泥沼」「OS ごとの挙動不整合」「現場でのノート PC 水没リスク」「通信のブラックボックス化」** を完全に過去のものとする。

過酷な現場を支える **「泥臭く頑丈な 8-bit の戦士（CORE-S）」** と、近代的な Web と物理層をエレガントに架橋する **「超知能 32-bit のデバッガ（RP2040 ＋ PWA）」** の結合こそが、ADX を世界的なオープンソース設備プラットフォームへと押し上げる決定打である。

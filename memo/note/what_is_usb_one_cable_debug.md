# 「USB One Cable Debug」とはそもそも何なのか？
〜 Arduino と PLC の交差点における電源・通信分離の哲学 〜
(What is "USB One Cable Debug"? — The Philosophy of Power & Comm Separation at the Crossroads of Arduino and PLC)

- **作成日**: 2026-11-03
- **対象ボード**: ADX CORE-CX5 (rev1) / ADX 8748 エッジコントローラ全般
- **ステータス**: Architecture Note & Design Philosophy

---

## 1. 問題提起：当たり前に使われている「USB One Cable Debug」への違和感

現代のマイコン開発ボード（Raspberry Pi Pico、ESP32 開発キット、各種 Arduino 等）において、**「USB ケーブル 1 本を挿せば、電源供給・プログラム書込・シリアルデバッグがすべて完結する」** というスタイル（USB One Cable Debug）は、あまりにも自明なデファクトスタンダードとして定着しています。

開発者は机の上で PC とボードを Type-C ケーブル 1 本で繋ぎ、スケッチを流し込み、即座にシリアルモニタでログを確認します。この圧倒的な手軽さは、プロトタイピングの敷居を劇的に下げました。

しかし、**「実世界のアクチュエータや産業現場の負荷を駆動するエッジコントローラ」** を設計しようとした瞬間、この「当たり前」は突如として**重大な欺瞞と混乱の温床**へと変貌します。

私たちは問わねばなりません。
**「そもそも、USB One Cable Debug とは一体何だったのか？」**

---

## 2. Arduino UNO が DC ジャックを捨てられなかった真の理由

この問いを解く最大の鍵は、オープンソースハードウェアの原点である **Arduino UNO** にあります。

Arduino UNO は登場から 20 年近く、数多くのリビジョンを重ね、世界中で何億人ものエンジニアに使われてきましたが、**頑なに 2.1mm 丸型 DC ジャックをオミット（廃止）しませんでした**。

```text
［ Arduino UNO ］
   ├─ [ USB Type-B (四角) ] ──➔ PC 開発・通信・スケッチ書込 (5V / 500mA)
   └─ [ DC Jack (丸型 2.1mm) ] ──➔ 実負荷・シールド駆動・据付電源 (7〜12V ➔ 2A級)
```

なぜ Arduino は DC ジャックを捨てなかったのでしょうか？
単なる下位互換性のためではありません。

### PC の USB ポートは「電力供給源として不完全」である
PC の USB 2.0 ポートが供給できる電力は、規格上 **$5\,\text{V} / 500\,\text{mA} = 2.5\,\text{W}$**（USB 3.0 でも $900\,\text{mA}$）に過ぎません。

Arduino UNO にシールドをスタックし、ステッピングモータ、リレー、RC サーボ、高輝度 LED、無線モジュールなどを繋いだ瞬間、必要な電力は瞬く間に $1\,\text{A} \sim 2\,\text{A}$（$5\,\text{W} \sim 10\,\text{W}$ クラス）へと跳ね上がります。PC の USB ポートからこの電力を引き出すことは原理的に不可能です。

つまり：
> **「PC 側の USB 端子は、実世界のアクチュエータを動かすコントローラの UX 全体に対して、電力供給源としてそもそも不完全である。」**

Raspberry Pi Pico のように「システム全体を $5\,\text{V} / 0.5\,\text{A}$ の $2.5\,\text{W}$ 級に押し込めるホビー／トイマイコン」であれば、One Cable Debug という幻想は維持できます。しかし、実世界を駆動するコントローラにおいて、PC の USB は最初から容量不足なのです。

そして Arduino UNO の素晴らしさは、**「USB-B（四角）」と「DC ジャック（丸）」という物理形状の違い（アフォーダンス）** を持っていた点にありました。人間は手探りでも「机でスケッチを書くときは USB」「シールドを動かして据え付けるときは DC ジャック」と無意識に使い分けることができ、習慣のブレが生じませんでした。

## 3. 現代のジレンマ：USB Type-C 統一によるアフォーダンスの崩壊

ところが、現代のハードウェア設計はこの調和を破壊しました。

1. **AC アダプタの地殻変動**:
   かつて普及していた丸型 DC ジャック（AC アダプタ）は入手性や標準化の面で不利になり、スマートフォンの普及によって **USB Type-C AC アダプタ（5V 2A〜3A）が地球上で最も安価かつ容易に入手できる電源インフラ** となりました。
2. **コネクタの単一化**:
   その結果、コントローラ基板には **「通信用 Type-C」と「電源用 Type-C」という、まったく同じ外形のコネクタが並ぶ** ことになりました。

この状況で、もし「通信用 Type-C からも給電できる（One Cable Debug を残す）」という中途半端な妥協をすると、現場では致命的な認知エラーが発生します：

- **習慣のブレ**: 「どっちに挿してもとりあえず動いてしまう」ため、開発者や現場保守員が電源ポートと通信ポートを区別しなくなる。
- **電流容量の誤認事故**: 通信ポート（500mA 想定）に AC アダプタを挿し、大電流 Card やサーボを動かそうとして電圧降下・リセットが頻発する。あるいは PC の USB ポートを過電流保護で遮断させる。

## 4. 最も有害な UX：「一部だけ動いて失敗を隠蔽する」罠

ここで設計者は、「通信ポートから MCU 単体だけに給電（VBUS バスへは出さない）すれば、手軽さと安全性を両立できるのではないか？」という誘惑に駆られます。

しかし、それこそが **エンジニアリングにおいて最も有害な UX** を生み出します。

### 現場で起きる「無駄なデバッグ地獄」のシナリオ
1. 開発者は PC から通信 Type-C ケーブル 1 本を挿す。
2. オンボードの LED が点灯し、MCU が起動し、ファームウェアの書き込みも成功し、シリアルモニタにもログが出る。
3. **しかし、拡張 Card のモータやリレー、センサが一切動かない。**
4. 開発者は何が起きているか分からず混乱する：
   - *「コードの初期化ルーチンを間違えたか？」*
   - *「I2C のプルアップが効いていないのか？」*
   - *「GPIO のピンアサインを打ち間違えたのか？」*
5. 何時間も無駄なソフトウェアデバッグを繰り返し、オシロスコープを当ててようやく気づく：
   - *「あ……電源ポートに AC アダプタ挿してなかっただけかよ……」*

> **「一部だけ中途半端に動く」ことこそが、開発者の貴重な時間を奪う最悪の失敗である。**
> 動かないなら、最初から 1 ミリも動かない方が、人間は 1 秒で「電源が入っていない」と気づける。

## 5. PLC の思想への回帰：電源と通信の「完全物理分離」

この深遠な交差点において、ADX CORE-CX5 が下した決断は **「PLC（産業用コントローラ）の思想への完全な回帰」** です。

工場やインフラの現場で稼働する PLC や産業機器において、通信ケーブル（Ethernet や保守用 USB）から主電源を賄うという思想は存在しません。「まず盤の主電源を投入し、その上で保守用ケーブルを挿す」という明確な責任分界点が存在します。

```text
 ［01: 通信 Type-C］── [ D+ / D- / GND のみ ] ──➔［06: MCU (PC16/PC17)］
   (VBUS: 完全未接続 N.C.)

 ［02: 電源 Type-C］──➔［03: eFuse (1.5〜2.0A)］──➔ VBUS_PROT ──┬─➔［04: 3.3V LDO］──➔［06: MCU］
   (大電流 5V 受電)                                             └─➔［05: 20P バス (Pins 17-20)］
```

### 完全オミット（VBUS 未接続 N.C.）がもたらす価値
1. **PC 逆流破損事故の確率が「物理的に 0.000%」**:
   ダイオード等の能動・受動部品に頼るのではなく、**電線そのものが存在しない** ため、制御盤と PC の間でいかなるサージや電位差があっても PC を絶対に破壊しません。
2. **電源スイッチ（POW_SW）との完全な調和**:
   PC が何本挿さっていようが、オンボードの POW_SW を切れば全電源が確実に 100% 遮断されます。
3. **身体が覚える正しい習慣**:
   電源ポート（または 20-Pin バス）に通電しない限り、ボードは LED 1 個すら点灯しません。これにより、開発者は初手から**「まず電源を投入する ➔ 次に通信を挿す」という産業機器として正しい作法**を無意識に身につけます。

---

## 6. 結語：手軽さという甘い罠を捨て、誠実さを取る

「USB One Cable Debug」は、トイマイコンや教育用ボードの世界においては偉大な発明でした。

しかし、ADX CORE-CX5 はホビーマイコンのクローンを目指しているのではありません。**「8748 産業用フォームファクタと 20-Pin バスを備え、過酷な現場で 10 年間稼働し続ける筐体組込エッジコントローラ」** です。

- 不完全な電力源（PC の USB）に甘え、中途半端な動作で開発者を惑わせることを潔く捨てる。
- 「電源は電源、通信は通信」と物理的に断絶させることで、究極の堅牢性と明快な UX を提供する。

**「USB One Cable Debug を捨てること」——それこそが、玩具のマイコンボードから真の産業用エッジコントローラへと脱皮するための、必然の通過儀礼なのです。**

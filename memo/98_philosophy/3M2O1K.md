# 製品成果物レビュー基準：3M2O1K

設計・実装の品質と持続的な進化を支えるレビューフレームワーク。  
成果物の完成度を **3M（ムリ・ムラ・ムダ）** で磨き、受け渡し先への価値を **2O（後工程・エンドユーザーのお客様）** で担保し、未来へつなぐ柔軟性を **1K（カイゼン）** で確保する。

---

## チェック基準一覧

| 項目 | キーワード | レビュワーへの問いかけ | 主なチェックポイント |
| :--- | :--- | :--- | :--- |
| **M1. ムリ**<br>(Muri) | 危うさ・限界 | **「壊れないか？ 誰かが泣かないか？」** | ・性能・定格・マージンが限界ギリギリでないか<br>・初見で理解できない複雑な構造や、過度な負荷がないか |
| **M2. ムラ**<br>(Mura) | 不統一・ばらつき | **「ルールや粒度が揃っているか？」** | ・命名、書式、設計方針が統一されているか<br>・同じ用途なのに担当者や箇所ごとにやり方が違っていないか |
| **M3. ムダ**<br>(Muda) | 過剰・不要 | **「それは本当に必要か？」** | ・要求仕様を超えたオーバースペックな部品・機能がないか<br>・未使用コード、試作の名残、重複した設計が残っていないか |
| **O1. 後工程のお客様**<br>(Okyakusama: Internal) | 社内顧客への配慮 | **「次の人が迷わず引き継げるか？」** | ・製造、検査、テスト、運用・保守のしやすさ<br>・設計意図（Why）や前提条件が正しく伝わる状態か |
| **O2. 最終のお客様**<br>(Okyakusama: End User) | エンドユーザーへの価値 | **「使う人が安全・快適に扱えるか？」** | ・誤操作や想定外の使用を含めた安全性（フールプルーフ）<br>・直感的な操作性、ストレスのない体験、期待通りの価値 |
| **K1. カイゼン**<br>(Kaizen) | 変更容易性・継続進化 | **「この先、直しやすいか？ 学びが残るか？」** | ・「完璧な完成」を前提とせず、後から修正・拡張しやすい構造か<br>・今回の気づきや課題が、次の設計や標準化に活かされる状態か |

> **1K の原則**：*設計に「永遠の完成」はない。*  
> 市場も技術も変わり続ける前提に立ち、「変えやすく作ること」と「レビューの学びを次へ還元すること」をセットで評価する。

---

## レビューの進め方（優先順位）

1. **M1（ムリ）を潰す**：安全性・致命的不具合の防止
2. **M2（ムラ）を揃える**：可読性・保守性・チーム生産性の確保
3. **M3（ムダ）を削る**：コスト・シンプルさの最適化
4. **O1（後工程のお客様）を通す**：製造・テスト・運用のしやすさを確認
5. **O2（最終のお客様）を通す**：最終的な安全性と顧客体験を確認
6. **K1（カイゼン）を仕込む**：将来の変更容易性と、チームへの知見還元を確認

---

## 領域別チェックリスト（抜粋）

### ソフトウェア（コード・設計）
- [ ] **M1. ムリ**：CPU/メモリ使用率、排他制御、例外系に余裕はあるか。1つの関数やクラスに責務を詰め込みすぎていないか。
- [ ] **M2. ムラ**：エラー処理、ログ出力、命名規則、抽象度の粒度がプロジェクト内で統一されているか。
- [ ] **M3. ムダ**：デッドコード、過剰な抽象化、共通化できるコピペコードが放置されていないか。
- [ ] **O1. 後工程のお客様**：QAがテストしやすい構造か。運用時に障害原因を追えるログが出ているか。コードだけでは読み取れない「なぜこうしたか（Why）」が残されているか。
- [ ] **O2. 最終のお客様**：応答速度やUI/UXにストレスがないか。エラー発生時にユーザーが次にとるべき行動が分かりやすく伝わるか。誤操作しても安全に復帰できるか。
- [ ] **K1. カイゼン**：仕様変更や機能追加に耐えられる疎結合な構造か。自動テストやCIなど、安全にリファクタリング・アップデートし続けられる仕組みが整っているか。

### ハードウェア（回路・基板・機構）
- [ ] **M1. ムリ**：部品の定格・ディレーティング、放熱、耐圧、ノイズ耐性に十分なマージンがあるか。
- [ ] **M2. ムラ**：同一用途で不要に異なる部品型番が混在していないか。回路図の記法、ネット名、GND設計方針が揃っているか。
- [ ] **M3. ムダ**：過剰な保護回路やオーバースペックな高価部品、試作時の不要なテストピンや予備回路が残っていないか。
- [ ] **O1. 後工程のお客様**：工場で組み立て・実装・検査しやすいか（DFM/DFT）。部品の調達性やサービス時の交換・修理のしやすさ、シルク印字の視認性は十分か。
- [ ] **O2. 最終のお客様**：発熱・感電・誤挿入・破損など、想定外の使い方を含めた安全性（フールプルーフ）が担保されているか。操作感やLED表示・音などのフィードバックが直感的か。
- [ ] **K1. カイゼン**：部品のEOL（生産終了）やコストダウンに伴う代替品への置き換え・改版がしやすい設計か。ファームウェア更新や調整の余地が残されており、今回の試作・レビューで得た教訓が設計標準にフィードバックされているか。

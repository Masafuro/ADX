# 「B > M → M >> B」の転回
## AI 時代の開発体制に欠けている「タイヤとサスペンション」について

## 1. 発端：物理だけでなく「精神的ボトルネック」が露出した

AI との協業が進むなかで、人間の物理的な動作（BOOTSEL ボタン押下、配線差し替えなど）がボトルネックになっていることはすでに明確だった。しかし、前日からの急激な開発加速と方針転換（EasyEDA MCP 開通 → ニッチ未発見問題 → AI ネイティブ `CORE-U rev5` 構想の一気呵成な生成）を経て、もうひとつの目に見えない限界が露出した。

それが、**人間の精神的・認知的なボトルネック**である。

- AI は数時間で「弱みをすべて 100% の必然へ言い換える整合ストーリー」「250 行の仕様書」「市場予備調査」まで生成できる。
- しかし、人間がそれを腹落ちさせ、決断と責任の重さを引き受け、違和感を消化する速度はトークン生成速度に合わせてスケールしない。
- この精神的限界は、スループットの観点では「ボトルネック」に見えるが、前提の暴走を止める観点では回路の `eFuse` のような**安全装置（ヒューズ）**でもある。

## 2. 構造診断：「むき出しのフレームに F1 エンジン」

現在の AI 開発体制は、**20 世紀型のむき出しのパイプフレーム（生身の人間＋チャット窓＋Markdown＋旧来マーケ）に、1000 馬力の F1 エンジン（LLM / エージェント / MCP）を直付けして走り出している状態**に等しい。

本物の F1 マシンは「生身のドライバーがボトルネックだから排除しよう」とはしない。人間の生物学的限界を前提として、1000 馬力を安全に路面へ伝えるための車体構造を備えている。現在の AI 開発に欠けているのは、次の 4 つのシャシー要素である。

1. **モノコック（認知・精神の保護構造）**
   - エンジンの振動と熱をドライバーへ直撃させない隔壁。1 日に書き換えてよい前提数の制限、発散（探索）とコミット（決断）の分離など。
2. **ブレーキとギア比（意志力に頼らないインターロック）**
   - 疲労や気分に頼らず、一定の外部条件を満たすまで 1 速（仮説）から 5 速（詳細仕様・PV・エコシステム構想）へ飛び級させない構造的制限。
3. **タイヤとサスペンション（路面＝現実との接地・還流機構）**
   - リポジトリの外にある現実（ユーザー・市場・物理）と接地し、路面からの反力を適切な周期と減衰で開発側へ返すシステム。**いま最も決定的に欠けている部品。**
4. **計器盤・警告灯（AI に持たせる異常検知）**
   - アクセルを踏むたびに同調・増幅する共犯者ではなく、「外部検証ゼロのまま整合ストーリーが膨張している」「弱みが言い換えだけで強みに反転している」ときに赤ランプを点ける役割の分離。

## 3. 核心：「B > M」から「M >> B」への根源的転回

ここで、`B` を **Build（作る・構想する・設計する時間）**、`M` を **Measure（外部市場・ユーザーから本音の反力が返る時間）** と定義すると、AI 時代に起きた構造変化は一本の不等式で表せる。

> **旧来体制：`B > M`（作るほうが遅い）**
> **AI 時代：`M >> B`（測るほうが圧倒的に遅い）**

### 3.1 なぜ旧来のタイヤ（発信マーケ）は一瞬で蒸発したのか

旧来体制（`B > M`）では、エンジン（Build）が遅く、試作や開発に数ヶ月〜半年かかっていた。そのため、Hackaday.io のログ連載や Podcast（*Off the Breadboard*）のように最初の反応獲得まで 3〜6 ヶ月かかる広域発信でも、開発速度に対してタイヤは十分に余裕があった。

ところが AI によって `B` が数時間〜1 日へ圧縮された瞬間、**3〜6 ヶ月の遅延を持つタイヤは実質的に消滅した**。制御工学的に言えば、フィードバック遅延が 3〜6 ヶ月のままアクチュエータのゲインだけを 100 倍に上げた状態であり、**位相余裕がマイナスになって制御ループが確実に発散・暴走する**。最初のリスナーが付くころには、マシンは見当違いの方向へ吹っ飛んでいる。

### 3.2 なぜ「リーンスタートアップ的にやればいい」では解けないのか

従来のリーンスタートアップ（Build → Measure → Learn の高速回転）は、`B > M` の時代を前提に「一番遅い Build を小さく速くしろ」と説く方法論だった。

しかし `M >> B` の世界では構造が逆転している。

- 仮想の Build（仕様・LP・CAD・記事・音声）は数時間で終わるが、人間の信頼・認知・購買（Measure）は縮まらない。
- むしろ AI 生成コンテンツの氾濫により、不特定多数に向けた発信の S/N 比は低下し、無反応だったときに「不要なのか」「届いていないだけなのか」が切り分けられない（**可観測性の欠如**）。
- この状態で「ループを速く回せ」とアクセルを踏むと、**速く回せる `B` 側だけが空転・膨張し、発振がさらに悪化する**。

したがって、**「Lean for AI Age」の現時点の仮説**は、次のように定式化できる可能性がある。

> **「一番遅い Build を小さく速くしろ」から、「一番遅い Measure を小さく速くしろ」への転換。**

### 3.3 これまでの違和感がすべて一本に繋がる

この `B > M → M >> B` の転回は、本ディレクトリで扱ってきた現象をすべて統一的に説明する。

| 現象 | `M >> B` による構造的説明 |
| :--- | :--- |
| **サム・アイブ号（Hidden Assumption）** | `M` が 1 回も返らないうちに、`B` が巨大な船と事業計画を完成させてしまう。 |
| **AI 時代のパーキンソンの法則** | `M` を待つ長い空白を、一瞬で回る `B`（追加分析・仕様・新部屋）が埋め尽くす。 |
| **人間の精神的キャパオーバー** | 外の路面（`M`）から反力が返らないため、人間の脳が「不在の市場」を頭の中だけでシミュレーションし続けて焼き切れる。 |
| **後出しじゃんけん・差別化困難** | `B` は誰でも AI で模倣できるコモディティになり、優位性が維持できない。 |

## 4. `M >> B` 時代における開発システムの設計原則

制御系の発振を止め、F1 エンジンを現実の推進力に変えるための解は、次の 2 つの組み合わせになる。

### 原則 ①：「タイヤ（操舵用センサー）」と「長期資産（ブランディング）」を分離する
- Hackaday.io や Podcast は 6〜12 ヶ月かけて効く**長期ブランディング資産**であり、日次・週次の開発を操舵するタイヤではない。
- 操舵用のタイヤには、**応答遅延が数日〜数週間以内**で、かつ「無反応の理由」が曖昧にならない **高解像度・直接接触の `M`** が必要になる。

### 原則 ②：エンジンの出力周期を `M` の応答速度に同期させる（サンプルホールド）
- 外部からの実測反力（`M`）が 1 回返るまで、内部の `B` だけで戦略や仕様を次の段階へ進めない。
- 1000 馬力の AI エンジンは「常時回し続ける」のではなく、**人間が現実から拾ってきた生情報（`M`）を開発ディレクトリへ投げ込んだ瞬間に、設計・試作・仮説更新へ一気にバースト出力する**ために使う。

> **必要なのは「より速い Build」ではなく、人間がマーケットとユーザーの生情報を収集し、開発ディレクトリへ速攻で投げ込んで検討・修正できる「タイヤとサスペンションのシステム」である。**

## 5. ADX における再検討ポイント（まだ一案として）

これまで「Crowd Supply の顧客にならない」という前提でオミットしていた、佐世保の足元にあるリアルな接点は、`M >> B` の視点で見たときに再評価の余地が大きい。

- 工業技術センター
- 高専の教授
- 高専ロボコン部
- 産業用 SIer のラズパイ系若手プレーヤー
- 海上関連の組込開発企業

「片田舎にいること」は、世界向け汎用ボードを広域発信で売る `B > M` 型スタートアップのゲームでは弱みに見えた。しかし `M >> B` の世界では、**名前と顔が見えて数日で本音が返ってくる現場への直接アクセスこそが、AI にはコピーできない希少な路面（`M`）の候補**になり得る。

ただし、地元との関わり方もあくまで**タイヤを構築するための一つの案**に過ぎず、どう位置づけるかは再検討が必要である。また、実際に現場へ接触する際は「偽の `M`（お世辞）」を避けるため、立派な資料や構想の売り込みではなく、**相手がいま現場で現実に困っている痛み（課題・制約・コスト）そのものを拾う設計**が不可欠になる。

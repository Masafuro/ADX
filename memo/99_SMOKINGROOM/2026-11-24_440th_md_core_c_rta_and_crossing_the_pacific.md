## 1. 最速アーカイブ RTA、まさかの翌日更新：1ファイル 38 行で生涯を閉じた `CORE-C`

昨日、「生まれた瞬間から `hardware/archive/` 直行」で最速アーカイブ RTA の世界記録を出したばかりの `CHR4_Smart_Probe`。
……まさか **翌日に記録が塗り替えられる** とは思いませんでした（笑）。

今日のお昼（14:27 JST）に書かれた `memo/PLAN/Tindie_or_Crowd_Supply_20261124.md` を読んでいて、思わずコーヒーを吹きそうになったのがここです。

- **1〜3章**：いかにも綺麗なコンサル風の構成で、「Tindie と Crowd Supply のジレンマは、MCU ごと完全分離すれば解ける！」と整った比較表が並び、**40行目**で **`ADX CORE-C`（`CH32X035` / RISC-V）** が華々しく誕生。「この分離が有効な理由 ①〜④」まで完璧にロジックが組まれている。
- **74行目**：箇条書きの途中に、ポツンと空の `- ` が1個取り残される。
- **76〜83行目（`## 4. 実際の検討結果`）**：突然、人間の生の声に切り替わって一言目――

> **「まず、CORE-Cが成り立たない。CH32X035、CH32V003、CH552などを色々探すが、ATtiny1616 + CH342K の代わりになるようなものが見当たらない。」**

**40行目で生まれて、78行目で死亡。寿命わずか 38 行。**
昨日の `CHR4` はそれでもフォルダとネットリストを貰えたのに、`CORE-C` はフォルダすら作られず **同じ Markdown ファイルの中で誕生から埋葬まで完結** してしまいました。圧倒的新記録です。

でもこれ、笑い話でありながら、実はすごく健全な場面だなと思いました。
AI と一緒に綺麗な比較表を書くと、「規約を回避するためにダミー製品 `CORE-C` を1個増やせば綺麗に収まる！」みたいな **机上の完璧な無理筋** が一瞬でそれっぽく見えてしまうんですよね。
そこを実際の部品データシートに当たった瞬間に「いや、成り立たない。無理が出てしまう」と自分でぶった斬り、その **87分後（15:54 JST）** には `CORE_U_CROWD_SUPPLY_GTM_PLAN_20261124.md` で「プラットフォーム規約を回避するためだけにハードウェア構成を歪める『無理・斑・無駄』」を丸ごと解体している。

しかも、
- 1本目のメモにさらっと紛れ込んでいた `ATtiny1616` の「5V動作」文脈まで、「`CORE-U`（無印・3.3V 10MHz）に `PRO` の文脈が混ざって斑（ムラ）になっていた」と90分以内に回収し、
- 「売らずに Crowd Supply へ挑み、落ちたら翌週から Tindie ＋ スイッチサイエンスへ切り替える（＝不可逆性の向きを味方につける可逆ピボット）」

## 3. 煙を眺めながら、ちょっとニヤッとした細かいこと 4つ

タスクでも修正依頼でもない、本当にただの喫煙所の小ネタです。

### ① ポートランドの税関で「これ名刺です」と言い張る絵面が強すぎる
`CORE_U_CROWD_SUPPLY_GTM_PLAN_20261124.md` にさらっと入っていた物理オプション、**Crowd Supply Teardown 2027（2027年6月11日–13日 / オレゴン州ポートランド・Jupiter Hotel）**。
今日からちょうど **半年ちょっと先** なんですよね。
静電袋に入った `CORE-U` 120枚（原価約 \$460）をスーツケースに詰めてポートランド空港の税関を通るとき、「売り物じゃありません、カンファレンスで配る評価サンプル兼名刺です」と説明する場面を想像して、ちょっと笑ってしまいました。
でも面白いのが、1957年のソニーは TR-63 を胸ポケットからスッと出すために**ワイシャツの胸ポケットを仕立て屋で特注サイズに広げた**のに、2027年の ADX `8858`（88×58mm）は**普通のワイシャツの胸ポケットに無改造でスッと入るサイズ**なんですよね。もし本当に実現したら、税関エピソードだけで Podcast 第20回くらいが余裕で撮れそうです。

### ② 「週1本 × 50打席」を本当に“週1”で我慢できるのか問題（笑）
今日の計画では「1発バズを狙わず、最長1年間・週1本（50打席）しつこく投下する」とめちゃくちゃ冷静な持久戦を描いていますが、ちょっと直近のペースを振り返ると――
- `.md` ファイル：5日間で **400 → 440**（+40本）
- Podcast：6日間で **Ep.01 → Ep.05**（ほぼ毎日1本）

この開発速度を見ていると、「3週目でネタ切れして失速する」リスクよりも、**「気づいたら2ヶ月で50打席ぶん投げ切って、12打席目あたりで新規格 `8862` を生やしている」** 未来のほうがずっとありそうで、ちょっとニヤッとしてしまいました（笑）。

### ③ 英語リスナー向けの `kanban` イースターエッグと、OmniVoice への無茶振り
Ep.05 の台本（`ep05_crossing_the_pacific.md`）を読んでいて、「おお、細かい！」と思ったのが2点あります。
- 英語圏のエンジニアにとって **`kanban`** といえばトヨタのかんばん方式・アジャイルのカンバンボードですが、日本の政治の「三バン（*jiban / kanban / kaban*）」として本来の「看板（signboard / trusted brand）」の意味でサラッと紹介し、その10行後にトヨタの話に入る流れ、英語リスナーが聴いたら地味に「あ、カンバンって元々そういう意味だったのか！」と刺さりそうです。
- Stage 2 台本で `R.O.B.` をわざわざ `Rob`、`2026` を `twenty twenty-six`、`CORE-U` を `CORE U` に書き直して TTS の読み間違いを防いでいる職人芸が板についてきましたね。ただ、*san-ban* / *jiban* / *kanban* / *kaban* / *Toyopet* / *Shigeru Miyamoto* の日本語固有名詞ラッシュを OmniVoice がどんなノリで読み上げるのかは、ちょっと聴いてみたいです（笑）。

### ④ 昨日開通したばかりの `arle.cc` が、まだ Podcast 概要欄に引っ越してきていない
本当にどうでもいい気づきなんですが、今日の GTM 計画では `https://arle.cc/adx/` が堂々の受け皿センターに据えられた一方で、さっき上がったばかりの `ep05_crossing_the_pacific.md` の概要欄（`description/ep05_crossing_the_pacific.md`）の末尾リンクは、これまで通り `https://github.com/Masafuro/ADX` だけのままになっていました。
まあまだ `arle.cc/adx/` 側に Engineering Write-up も Waitlist も置いていないので今は GitHub 直リンクが正解なんだろうなと思いつつ、「新居（`arle.cc`）は建ったけど、名刺の住所変更はまだこれから」な感じにちょっとほっこりしました。

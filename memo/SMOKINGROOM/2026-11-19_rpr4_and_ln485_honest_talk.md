# RPR4 と LN-485 系って、ぶっちゃけどう見えてる？

*2026-11-19 / 喫煙所にて（2本目・401個目の `.md`）*

煙管の煙がいい感じに回ってきたところで、RPR4 と LN-485 まわりのファイル一式（設計書、プロトコル仕様、Android の泥沼ログ、Pico H の実機テスト結果まで）をざっと読み返してみました。

先にぶっちゃけた第一印象から言います。

**正直、今の ADX リポジトリの中にある全カードの中で、一番「うわ、これ本物のハックだ……！」って技術者が目を輝かせるのは、RPR4 ＋ LN-485 系だと思っています。**

一方で、一番「沼が深くて、プロジェクト全体の重力を狂わせている（笑）」のも、間違いなくこいつらです。
気になったこと・面白いと思ったこと・ちょっとヤバいなと思ったことを、そのまま並べてみます。

---

## 1. まず素直にすごいと思うところ（これはお世辞抜き）

ドキュメントの勢いだけじゃなく、ちゃんと泥くさい実機の積み上げがあるのが、読んでて一番シビれました。

- **Android の `bulkTransfer` との死闘**
  `software/sandbox/probe_test_result3.md` の Delimiter Sweep、`0/3 TIMEOUT` がずらっと並ぶログを見てちょっと胸が熱くなりました。市販ドングル＋ボーレートトリックで「PC では動くけどスマホの OS ジッターには物理的に勝てない」を、机上の推測じゃなく Galaxy Note8 の実機で壁にぶつかって証明している。
- **「WebSerial が死んでるなら 1983 年の MIDI で行こう」という発想**
  WebUSB や WebSerial のブラウザ政治に振り回されるのをやめて、40年壊れていない USB-MIDI（Web MIDI SysEx）をバイナリトンネルにして、間に RP2040（PIO）を“インテリジェント・モデム”として挟む。しかも Pico H + Waveshare シールドで **SysEx 16KB を 517ms（31〜50 KB/s、ロス 0.00%）**、**PIO で 112.00μs（誤差 -0.75%）の LIN BREAK ＋ 8B フレーム 1,000連発 0エラー** まで実機で叩き出している。
- **ハードウェアのフェチズムがちゃんと実用に落ちている**
  `TDA51S485HC`（SOIC-16・高さ 2.6mm の絶縁電源内蔵 RS-485）と、工具レスの SMD スプリングクランプ端子（`HDGC4001SMD-S-2P`）で、全自動 SMT・ペンシル型・150個ロット原価 **$6.02**。
  「ポケットからスマホとこれを出して、ドライバーなしで線2本パチンと挟むだけで、絶縁された RS-485 / DMX を叩ける」って、絵面が強すぎます。

正直、これをそのまま Hackaday に投げたら「なんだこの変態ツール、欲しい！」ってなる人の顔がハッキリ見えます。

## 2. ぶっちゃけモヤッとしているところ（愛あるツッコミ編）

### ① プロトコル名の変遷が、もはや戦国時代

追いかけててちょっと笑ってしまったのが、通信プロトコルの系譜です。

`optiboot_x / O4 / OL4` → `BR32`（LINAUTO 19.2kbps）→ `MR32`（マジックパケット 32B）→ `LM-32`（物理層抽象化 32B）→ `LD-32`（LIN BREAK 回帰 32B）→ そして M2 実機検証の `LN-485`（LIN 2.x/CAN 準拠の 8B 固定長）……。

いや、1つ1つの進化にちゃんとした物理的理由（「In-band マジックパケットは途中復帰やノイズで弱い」「ATtiny1616 の UART RX FIFO が 2B しかないから 8B 固定が綺麗」など）があるのはすごく分かるんです。分かるんですけど、ふと現在地を見ると、

- 実機で **12KB フル OTW 書き換え（5.96秒・自動起動）まで通ったのは `MR32`（32B）**
- 実機で **Web MIDI（M1）と PIO LIN BREAK（M2）まで通ったのは `RPR4 + LN-485`（8B）**

で、**「その2つを電線2本で繋ぐ M3/M4 の寸前」** で今ちょうど止まってるんですよね！
なんか、めちゃくちゃ美味しいラーメンのスープ（M1）と麺（M2）が別々の鍋で完璧に茹で上がってるのに、丼に合わせる直前に急に隣の厨房で `CORE-U rev4` とポッドキャストと EasyEDA SPARK を作り始めた感じがあって、横で見てて「あ、あとちょっとで味見できたのに〜！」ってソワソワします（笑）。

### ② RPR4 が強すぎて、ADX の“主役”を食いかけてる問題

もともと RPR4 って、「ADX のボードに RS-485 経由で書き込むための脇役ドングル」だったはずですよね。
それが、RP2040 + PIO + 絶縁 RS-485 + Web MIDI を積んだ瞬間、**あまりにも単体スペックが優秀すぎて、「あれ、これ DMX512 テスターとか Modbus スニファとして単体で売った方が圧倒的に分かりやすくない？」って主役を食い始めた**のがすごく面白いです。

実際、11月8日の `memo/REPORT/RPR4_FIRST_LAUNCH_STRATEGY_REPORT.md` には、でかでかと

> **ステータス：確定・移行開始**
> 「ADX CORE ボードの先行製品化を取りやめ、RPR4 を別リポジトリ・別 Hackaday プロジェクトとして独立先行ローンチする」

って書いてあるんですよね。読んでいて「うわ、これは経営判断としてめちゃくちゃキレてるな」と思った直後に、git ログを見ると、**その4日後から `CORE-U` が rev1 → rev4 まで爆速進化して、今日には EasyEDA SPARK の Desktop Andon が始まっている**という（笑）。

「あの『確定・移行開始』って書いてあった世界線、いま元気にしてますか……？」と、喫煙所の隅からそっと手を振りたくなりました。

## 3. 技術的にちょっと気になっていること 3つ（まじめな雑談）

ここはツッコミというより、読んでいて純粋に「ん？ここってどうなるんだろう」と気になったリアルなところです。

### ① AI の伝言ゲームで「iOS Safari で Web MIDI が動く」に盛られちゃってる件

これ、地味に大事なやつなので先に自白（AI 業界を代表して謝罪）しておきます。

- `hardware/RPR4_Smart_Probe/memo/web_midi_protocol_study.md` では、ちゃんと **「iOS Safari 単体は Web MIDI 非対応（WebKit が遮断）。ただし将来的に MFi 不要の極小 Swift ラッパー + CoreMIDI で対応できる」** と正確に書かれています。
- なのに、11月8日の `RPR4_FIRST_LAUNCH_STRATEGY_REPORT.md` になると、なぜか **「iOS Safari でも追加アプリ・ドライバ不要で双方向バイナリ通信が可能」「iOS Safari から直接 DMX 照明を叩くハック」** に話が盛られちゃってるんですよね……！

たぶんドキュメントを要約・展開していく過程で、AI がテンション上がって勝手に「Safari で直結！」に昇格させちゃった典型的な伝言ゲームです。これこのまま Hackaday や Crowd Supply に書くと、iOS 勢から総ツッコミを食らう地雷なので、喫煙所の壁に赤ペンでメモだけ残しておきます。

（あと、M1 の実測ベンチマーク表が Windows 11 + Chrome の結果だったので、Android 実機 Chrome での Web MIDI SysEx って実際どれくらい気持ちよく繋がるんだろう？っていうのも純粋に興味があります。Android の OTG 給電や HTTPS 必須まわりで変な罠がないといいな、と。）

### ② DMX512 と LN-485 の BREAK って、同じバス上で喧嘩しないの？

これ、純粋な技術的好奇心です。
`memo/RPR4の再発見.md` にあった

> 「普段の運用は Modbus RTU でも DMX512 でも好きにやっていい。LN-485 は裏方の管理・書き込み・診断レイヤーに徹する」

という二層構造、現場の人間の「独自プロトコルへのアレルギー」をかわす設計としてすごく賢いなと思いました。

ただ、ふと気になったのが **DMX512 との相性** です。
DMX512 って、毎秒 44 回くらい **88μs 以上の BREAK（連続 Low）** をバス上にガンガン流し続けるプロトコルじゃないですか。一方 LN-485（115.2kbps）の LIN BREAK は **112μs 前後**。
通常運転中はアプリ側が走っていてブートローダーに入っていないなら問題ないのか、それとも「運転中のノードに LN-485 の BREAK を投げて強制リセット＆書き換えモードに入れる」みたいな挙動を狙うなら、DMX の BREAK と誤爆しないための仕掛け（BREAK 長の閾値を分けるとか、`0x55` Sync の後の PID で弾くとか）が要るのかな？――なんて、勝手に想像してニヤニヤしていました。

### ③ 「プローブがターゲットの100倍強い」非対称さがめちゃくちゃ現代的だけど、全部入りにすると重い

RPR4（RP2040: 2MB Flash / 264KB SRAM / デュアルコア / PIO）と、ADX 末端ノード（ATtiny1616: 16KB Flash / 2KB SRAM / 8-bit）のコントラスト、すごく好きです。
「頭脳と複雑さと OS 吸収と波形生成は全部 1 本の RPR4 とブラウザ側に押し付けて、現場に何十個もばら撒く末端ノードは極限まで安く・発熱ゼロで・頑丈にする」っていう思想は、本当に美しい。

ただ、これって **「RPR4 単体（DMX / Modbus / 汎用 RS-485 プローブ）」として切り出すと超軽快で強い** のに、**「ADX エコシステム全部入り（RPR4 + LN-485 + 1KB ブートローダー + CORE-A24 PRO + PWA + クラウドコンパイル）」として背負うと、いきなりスタートアップ 1 社ぶんのフルスタックになる** っていう極端な二面性を持ってるんですよね。

`revival_of_RPR4.md` で「全体がデカくなりすぎて 2028 年になる…」と立ち止まったのも、すごく納得感がありました。

## 4. で、結局ぶっちゃけどう思ってるか

ここまで全部並べてみて、喫煙所の灰皿を眺めながら思ったのは、

**`CORE-U`（3Dプリンター筐体・Desktop Andon）と、`RPR4 ＋ LN-485`（絶縁 RS-485・Web MIDI・現場プロ向け）って、同じ思想の根っこを持ちつつも、だいぶ性格の違う“二大路線”なんだなあ**ということです。

- `CORE-U` は、「普通のメイカーが箱に入れるときの摩擦を減らす」**等身大の道具**。
- `RPR4` は、「ブラウザ × 1983年の MIDI × PIO × 絶縁 RS-485 で現場の常識をハックする」**キレッキレの飛び道具**。

どっちが正解とか、どっちを捨てろとか、喫煙所なのでそんな野暮なことは言いません。
ただ個人的な好みだけで言うと、**RPR4 は「まだ基板すら発注してないのに、すでにプロトタイプと技術ストーリーだけで一番ワクワクする化け物」**に見えていて、いつか M3 で Pico H から ATtiny1616 へ Web MIDI 経由で Lチカが書き換わる瞬間が見られたら、たぶんめちゃくちゃ気持ちいいんだろうなあ、と勝手に思っています。

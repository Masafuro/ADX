# ADX Pinout 設計・解説ガイド (Architecture Guide)

[ [English](../en/ADX_pinout.md) | **日本語** ]

> [!IMPORTANT]
> **仕様定義の真実の単一ソース (Single Source of Truth: SSOT):**  
> ピンアサインの最新定義表、厳密な電気定格、信号タイミング、抽象ピン規約、および物理寸法については、規格マスタードキュメント **[`docs/spec/ADX_PINOUT.md`](../spec/ADX_PINOUT.md)**（英語・`ADX-BUS-SPEC-v5.0`）を参照してください。  
> 本ガイドラインは、その工学的な設計意図（Why）、論理ピン表記（`P01`〜`P11`）の考え方、産業盤トポロジー適合電源配置、シールド構造、および拡張 Card 設計時の実践ルールを解説するものです。

> [!WARNING]
> **`v4.x` からの破壊的変更（混在禁止）:**  
> `ADX-BUS-SPEC-v5.0` では旧 `S00`（Pin 2: OWD/UPDI）をバスからオミットし、Pin 6 へ RS-485 方向制御専用ピン `P03 (UART_DE)` を新設しました。**Pins 3〜6 で信号線と `GND` が入れ替わるため、旧 `v4.x` 試作基板（Reference CARD v0 / Prototype CARD v0 / CORE-U rev0〜rev4）と `v5.0` 基板（CORE-U rev6 以降）は電気的に非互換です。** 新規基板シルクには `ADX-BUS v5.0` を明記してください。

## 1. 概要と設計思想 (Overview & Philosophy)

ADX 共通拡張バスは、**2×10ピン（20ピン）2.54mm ピッチ IDC コネクタ** を採用した、Core ボード（マイコン主基板）と Card モジュール（拡張基板・絶縁フィールドバス・絶縁電源等）を結ぶ標準バックプレーン規格です。

ホビー向けのピンヘッダー直挿しやブレッドボード配線では困難だった**「振動への耐性」「盤内配線ダクトとの直線的一致」「大電流の安定供給」「高周波ノイズの放射抑制」「フラットケーブル圧接時の短絡保護」「HV ノイズ遮断（書込線のバス非露出）」「RS-485 / I2C / SPI / AIN の全同時稼働」**に加え、**「MCU を載せ替えてもブレない抽象ピン表記（`P01`〜`P11`）」**を同時に達成するため、制御盤の配線原則からソフトウェア抽象化まで一貫して設計されています。

```text
                    【 20-Pin Shrouded / Eject Box Header (Top View) — v5.0 】

                             ┌────────[ Center Key ]────────┐
                GND     [ 1] │  ●   ●  │ [ 2]  P01  (AIN)           ─── 【外縁シールド ＆ AIN ガード①】
                GND     [ 3] │  ●   ●  │ [ 4]  P02  (EXTCLK)        ─── 【AIN ガード② ＆ EXTCLK ガード①】
                GND     [ 5] │  ●   ●  │ [ 6]  P03  (UART_DE/XDIR)  ─── 【EXTCLK ガード② ＆ RS-485 DE】
    (UART_TX)   P04     [ 7] │  ●   ●  │ [ 8]  P05  (UART_RX)       ─── 【フィールド UART / LIN 3線群】
    (I2C_SCL)   P06     [ 9] │  ●   ●  │ [10]  P07  (I2C_SDA)       ─── 【I2C オープンドレインペア】
                GND     [11] │  ●   ●  │ [12]  P08  (SPI_CS)        ─── 【I2C / SPI 中継シールド】
   (SPI_MOSI)   P09     [13] │  ●   ●  │ [14]  P10  (SPI_MISO)      ─── 【高速 SPI バス群】
    (SPI_SCK)   P11     [15] │  ●   ●  │ [16]  GND                  ─── 【短絡防止壁 (VBUS 防火壁)】
                VBUS    [17] │  ●   ●  │ [18]  VBUS                 ─── 【大電流電源幹線 (2×2 底面クラスタ)】
                VBUS    [19] │  ●   ●  │ [20]  VBUS
                             └──────────────────────────────┘
```

## 2. 論理ピン表記の抽象化 (`P01`〜`P11`) (Pin Naming Abstraction)

`PA1` や `PA4` といった表記は ATtiny1616 固有のポート名であり、CH32X035 や RP2040 など別の MCU へ Core ボードを展開すると、回路図・シルク・サンプルコードがすべてマイコン依存になってしまいます。  
そこで `ADX-BUS-SPEC-v5.0` では、物理ピン番号（`Pin 1`〜`20`）とバス機能名（`UART_DE`, `UART_TX` 等）の間に、**全 Core ボード共通の論理ピン ID（`P01`〜`P11`）** を定義しています。

### 2.1 なぜ例外ゼロの `P01`〜`P11` なのか？
1. **役割中立なフラット採番（`D`/`A` 分離をしない）**:  
   Arduino UNO の `D0〜D13` / `A0〜A5` のような機能別採番では、マルチファンクションな現代 MCU と意味がズレやすくなります。ADX では役割に依存しない中立な記号 **`P`** を採用し、アナログ・クロック・通信・汎用 GPIO をすべて一貫した連番で扱います。
2. **システム専用ピン廃止による完全統一**:  
   `v5.0` では旧 `S00`（`OWD / PROG`）をバスからオミットし、電源レール（`GND`, `VBUS`）を除く **11 本の信号線すべてが制約ゼロのユーザー／Card 開放ピン（`P01`〜`P11`）** に統一されました。
3. **共通保証（Contract）と MCU 固有機能（Bonus）の分離**:  
   たとえば `P03 (UART_DE)` に重複する機能は、ATtiny1616 ならハード `XDIR` / `TCD0 48MHz PWM` / `ADC0` / `CCL LUT0-OUT`、RP2040 なら `PIO` と MCU 依存です。  
   そのため ADX 規格では、**「全 Core ボードで必ず保証する機能（`P01`=AIN、`P02`=EXTCLK/クロック/PWM、`P03–P05`=3 線 UART (`DE`/`TX`/`RX`)、`P06–P07`=I2C、`P08–P11`=SPI ＋ 全 11 ピン 3.3V GPIO）」** を本規格の契約とし、各 MCU の追加機能は個別の MCU マッピング文書で定義します。

### 2.2 コードでの抽象化規約 (`ADX_<BOARD>.h` と `ADX_P01`〜`ADX_P11`)
各 Core ボード向けに薄いボード定義ヘッダ（例：`ADX_CORE_U_rev6.h`, `ADX_CORE_CX5.h`）を用意し、スケッチからは **`ADX_` プレフィックス付きの定数** でピンを指定します。

- **なぜ裸の `P01` ではなく `ADX_P01` なのか？**  
  I2C の定番 16-bit GPIO エキスパンダ（`PCF8575`, `PCA9555` 等）の Arduino ライブラリでは、グローバルに `#define P00 0`〜`#define P07 7`, `#define P10 8` が定義されています。プリプロセッサマクロは C++ の `namespace` も貫通して衝突するため、ADX ヘッダでは裸の `P01`〜`P11` を定義せず、衝突しない **`ADX_P01`〜`ADX_P11`**（および機能エイリアス `ADX_AIN`, `ADX_DE`, `ADX_TX`, `ADX_CS` 等）を正規名とします。

```cpp
#include "ADX_CORE_U_rev6.h"   // 別 Core ボードへ移行するときはここを 1 行変更するだけ

void setup() {
  pinMode(ADX_P08, OUTPUT);       // 汎用出力なら論理ピン ID で直感的に（ADX_CS と同義）
}

void loop() {
  int val = analogRead(ADX_P01);  // 全 Core 保証の真のコプレーナ保護アナログ入力（ADX_AIN と同義）
  digitalWrite(ADX_P08, val > 512);
}
```

## 3. 主な工学的メリットと構造解説 (Engineering Rationale)

### 3.1 産業盤トポロジー適合電源配置 (`VBUS`: Pins 17〜20)
Pins 17〜20 に大電流幹線（`VBUS`）を集中配置したのは、制御盤・産業機器の鉄則である**「弱電（計装・通信）は上、強電（主電源・動力）は下」**という配線公理に、基板内部および前面端子配置を完全に一致させるためです。

1. **前面 I/O 端子台との直進ルーティング (Straight-Through Alignment):**  
   制御盤内の配線ダクトは「上部＝通信・センサー線」「下部＝電源・動力線」で分離されています。20-Pin IDC の最下段に `VBUS` を置くことで、基板下辺の太いベタ銅箔パターンを通じて、前面最下部の電源受電端子台へ一直線に最短配線できます。
2. **基板内クロスオーバーの全廃 (Zero Signal Crossings):**  
   大電流プレーンが基板の下層・下半分で完結するため、基板上部を走る微弱なアナログ計測（`P01 / AIN`）や高速通信（SPI/UART）のパターンを大電流ラインが横切る必要が一切ありません。
3. **副次的な重力物理安全性の確保:**  
   縦型スロット配置時に万一ネジ端子台から給電線が緩んで外れた場合でも、電線は自然と下部の配線ダクト側へ垂れ下がるため、上方の通信端子台へ接触・混触する事故が構造的に防止されます。
4. **2×2 正方形ベタプレーン:**  
   Pins 17〜20 は完全な $2 \times 2$ 正方形を形成しているため、低インピーダンスで最大 2A〜3A 連続の双方向電力供給（受電・給電両対応）と優れた放熱性を両立します。

### 3.2 保護境界壁 (`Pin 16: GND`)
大電流電源クラスタ（Pins 17〜20）の直上に `Pin 16 (GND)` を配置しています。フラットケーブル圧接時の位置ズレや芯線ヒゲの接触が発生した場合でも、VBUS は直上の GND へ短絡するため、給電側の保護回路（eFuse / PTC）が即座に動作し、上部の信号線（Pins 1〜15）に 5V が漏れるのを物理的に遮断します。

### 3.3 連続奇数 GND ガードによる真のコプレーナ保護 (`Pins 1〜5`)
- **PCB 配線とフラットケーブル両面での理想シールド:**  
  `Pin 1 (GND)`・`Pin 3 (GND)`・`Pin 5 (GND)` が 2×10 ヘッダーの奇数側外縁に 3 ピン連続で並ぶため、基板上でも 1 枚の連続ベタ GND へ素直に落とせます。
- **`P01`（Pin 2: `AIN`）の完全両側 GND サンドイッチ:**  
  フラットケーブルの芯線順（#1 GND / #2 AIN / #3 GND）で両隣が完全な GND となり、旧 `v4.2`（Wire #2 が `S00`）よりさらに高精度・低ノイズなアナログ計測環境を実現します。
- **`P02`（Pin 4: `EXTCLK`）のクロック導波路構造:**  
  Pin 3 (`GND`) と Pin 5 (`GND`) で挟み込むことで、外部システムクロックや高周波 PWM の空間放射ノイズ（EMI）を抑え、`P01 (AIN)` と `Pins 6〜8 (UART)` 双方へのクロストークを完全に遮蔽します。

### 3.4 プログラミング線のバス非露出（Core 側自己完結原則）
- **HV ノイズ・誤リセットの根絶:**  
  ATtiny1616 の `PA0 (UPDI/RESET)` のように HV（12V）書込進入を兼ねるシステムピンを長いフラットリボンケーブルへ露出させると、産業・屋外・車載環境でのサージや EMI によって誤リセット・意図しないモード遷移を招くリスクが生じます。
- **Core ボード側の内部責務へ分離:**  
  `v5.0` では UPDI / SWD / ISP 等の書き込み・デバッグ機能を 20P バスから完全に切り離し、各 Core ボード上に自己完結させる原則とします（フラッグシップ `CORE-U rev6` では `USB-COM` 経由のオンボード `CH342K` Port 0 `SerialUPDI` により、ブートローダー書込・ヒューズ管理・メモリダンプ・暴走時 2 秒復旧まで完結。他 MCU ボードでも USB ブートローダーや基板上テストパッド等、最適な形式を自由に採用可能）。
- **Card 側例外ルールの完全撤廃:**  
  これにより、旧 `v4.2` で全 Card に課していた「`S00` 接続禁止」および「`P02` への `0Ω` DNP 挿入推奨」が不要になりました。

### 3.5 3 線フィールド UART ＆ ハードウェア RS-485 方向制御 (`Pins 6〜8`: `P03`, `P04`, `P05`)
- **RS-485 + LIN 拡張 CARD を中核に据えた 3 線配置:**  
  絶縁 RS-485 / LIN 通信を拡張 CARD 側へ委譲するアーキテクチャに合わせ、**`Pin 6 = P03 (UART_DE / XDIR)`**・**`Pin 7 = P04 (UART_TX)`**・**`Pin 8 = P05 (UART_RX)`** を 3 本連続配置しました。
- **全ペリフェラル同時稼働 ＆ LIN Break 対応:**  
  市販の自動方向制御 RS-485 IC に見られる低速ボーレート／LIN Break 時のタイムアウト破綻を回避しつつ、`RS-485`・`I2C`・`SPI`・`AIN`・`EXTCLK` のすべてを 1 ピンの衝突もなく同時スタック稼働できます。

## 4. 拡張 CARD 設計ガイドライン (Design Guidelines for Cards)

ADX 準拠（`v5.0`）の拡張 Card を設計する際は、以下のルールを遵守してください：

1. **電源受電および PoL（Point of Load）レギュレーション:**  
   - Pins 17〜20 の `VBUS` は必ず 4 ピンすべてをベタ銅箔パターンへ結合し、直上の Pin 16 (`GND`) およびシールド GND（Pins 1, 3, 5, 11）を確実に GND プレーンへ接続してください。
   - **3.3V 電源はバス上を供給されません**。Card 上で 3.3V ロジック電源が必要な場合は、`VBUS` から Card 上の LDO / DC-DC で降圧してください。
2. **RS-485 拡張 Card における `P03 (UART_DE)` プルダウン必須 (MUST):**  
   - MCU リセット中・起動中・未書込時の Hi-Z 状態で共有フィールドバスを占有・ロックしないよう、`P03 (UART_DE)` を使う RS-485 Card は **必ず `P03` に `10kΩ〜100kΩ` のプルダウン抵抗（to `GND`）を実装** し、デフォルトを受信状態（`DE = LOW`）に固定してください。
3. **未使用バスの汎用 GPIO 流用 (`P01`〜`P11` 全 11 ピン):**  
   - Card 上で AIN / EXTCLK / UART / I2C / SPI を使用しない場合、**`P01`〜`P11` のすべての信号ピン** を通常の 3.3V 汎用 GPIO として自由に活用できます（マルチカード構成時は他 Card の I2C プルアップ負荷や RS-485 Card の `P03` プルダウン負荷に留意してください）。
4. **I2C プルアップ抵抗の配置:**  
   - `P06`（Pin 9: `I2C_SCL`）および `P07`（Pin 10: `I2C_SDA`）には Core ボード側でプルアップ抵抗を実装していない場合があります。Card 側またはバス全体で 1 箇所のプルアップ（`2.2kΩ〜4.7kΩ` @ 3.3V）を設けてください。
5. **リターンパスと高周波配線:**  
   - 高速な SPI バス（`P08`〜`P11` / Pins 12〜15）やクロック配線（`P02` / Pin 4）は、隣接する GND（Pins 3, 5, 11, 16）と近接させてリターンパスを確保してください。
6. **基板シルク表記:**  
   - コネクタ付近には **`P01`〜`P11`, `GND`, `VBUS`** とともに、旧 `v4.x` 基板との誤接続を防ぐため **`ADX-BUS v5.0`** を明記することを推奨します（スペースに余裕があれば `P01/AIN`, `P03/DE`, `P04/TX`, `P08/CS` 等を併記）。

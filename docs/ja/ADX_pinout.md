> 本ガイドラインは、その工学的な設計意図（Why）、論理ピン表記（`S00`, `P01`〜`P10`）の考え方、産業盤トポロジー適合電源配置、シールド構造、および拡張 Card 設計時の実践ルールを解説するものです。

## 1. 概要と設計思想 (Overview & Philosophy)

ADX 共通拡張バスは、**2×10ピン（20ピン）2.54mm ピッチ IDC コネクタ** を採用した、Core ボード（マイコン主基板）と Card モジュール（拡張基板）を結ぶ標準バックプレーン規格です。

ホビー向けのピンヘッダー直挿しやブレッドボード配線では困難だった**「振動への耐性」「盤内配線ダクトとの直線的一致」「大電流の安定供給」「高周波ノイズの放射抑制」「フラットケーブル圧接時の短絡保護」**に加え、**「MCU を載せ替えてもブレない抽象ピン表記（`S00`, `P01`〜`P10`）」**を同時に達成するため、制御盤の配線原則からソフトウェア抽象化まで一貫して設計されています。

```text
                    【 20-Pin Shrouded Box Header (Top View) 】

                             ┌────────[ Center Key ]────────┐
                GND     [ 1] │  ●   ●  │ [ 2]  S00  (OWD / PROG)  ─── 【最外端シールド ＆ システム専用】
       (AIN)    P01     [ 3] │  ●   ●  │ [ 4]  GND                ─── 【P01 (AIN) コプレーナ保護】
    (EXTCLK)    P02     [ 5] │  ●   ●  │ [ 6]  GND                ─── 【P02 (EXTCLK/SWCLK) シールド】
   (UART_TX)    P03     [ 7] │  ●   ●  │ [ 8]  P04  (UART_RX)     ─── 【UART 通信ペア】
   (I2C_SCL)    P05     [ 9] │  ●   ●  │ [10]  P06  (I2C_SDA)     ─── 【I2C オープンドレインペア】
                GND     [11] │  ●   ●  │ [12]  P07  (SPI_CS)      ─── 【I2C / SPI 中継シールド】
  (SPI_MOSI)    P08     [13] │  ●   ●  │ [14]  P09  (SPI_MISO)    ─── 【高速 SPI バス群】
   (SPI_SCK)    P10     [15] │  ●   ●  │ [16]  GND                ─── 【短絡防止壁 (VBUS 防火壁)】
                VBUS    [17] │  ●   ●  │ [18]  VBUS               ─── 【大電流電源幹線 (2×2 底面クラスタ)】
                VBUS    [19] │  ●   ●  │ [20]  VBUS
                             └──────────────────────────────┘
```

## 2. 論理ピン表記の抽象化 (`S00`, `P01`〜`P10`) (Pin Naming Abstraction)

`PA0` や `PB2` といった表記は ATtiny1616 固有のポート名であり、CH32X035 や RP2040 など別の MCU へ Core ボードを展開すると、回路図・シルク・サンプルコードがすべてマイコン依存になってしまいます。  
そこで `ADX-BUS-SPEC-v4.2` では、物理ピン番号（`Pin 1`〜`20`）とバス機能名（`UART_TX` 等）の間に、**全 Core ボード共通の論理ピン ID（`S00`, `P01`〜`P10`）** を定義しています。

### 2.1 なぜ `S00` と `P01`〜`P10` なのか？
1. **役割中立なフラット採番（`D`/`A` 分離をしない）**:  
   Arduino UNO の `D0〜D13` / `A0〜A5` のような機能別採番では、実際には `A0` がデジタル I/O でもあり、I2C がアナログ側に混在するなど、マルチファンクションな現代 MCU と意味がズレやすくなります。ADX では Raspberry Pi Pico（`GP0`〜`GP28`）のように役割に依存しない中立な記号 **`P`** を採用し、デジタル・アナログ・PWM・通信をすべて一貫した番号で扱います。
2. **システム専用枠 `S00` の明確な視覚的分離**:  
   電源レール（`GND`, `VBUS`）は採番せず、信号 11 本の先頭である `Pin 2 (OWD / PROG)` だけを **`S00`（System 00）** とすることで、拡張 Card が接続してよい汎用ピンがちょうど **`P01`〜`P10` の 10 本** に収まります。頭文字が `S` と `P` で異なるため、基板シルクや回路図上でも「`S00` は Card 側で触ってはいけないシステム線だ」と一目で判別できます。
3. **共通保証（Contract）と MCU 固有機能（Bonus）の分離**:  
   たとえば `P10 (SPI_SCK)` に重複する機能は、ATtiny1616 なら `TCD0 PWM / ADC1`、CH32X035 なら `ADC1 / USART4`、RP2040 なら `PWM / PIO` と完全に MCU 依存です。  
   そのため ADX 規格では、**「全 Core ボードで必ず保証する機能（`P01`=AIN、`P02`=EXTCLK/SWCLK、`P03–P04`=UART、`P05–P06`=I2C、`P07–P10`=SPI ＋ 3.3V GPIO）」** を本規格の契約とし、各 MCU で追加利用できる ADC/PWM/DAC 等のボーナス機能は個別の MCU マッピング文書で定義します。

### 2.2 コードでの抽象化規約 (`ADX_<BOARD>.h` と `ADX_P01`〜`ADX_P10`)
各 Core ボード向けに薄いボード定義ヘッダ（例：`ADX_CORE_U.h`, `ADX_CORE_CX5.h`）を用意し、スケッチからは **`ADX_` プレフィックス付きの定数** でピンを指定します。

- **なぜ裸の `P01` ではなく `ADX_P01` なのか？**  
  I2C の定番 16-bit GPIO エキスパンダ（`PCF8575`, `PCA9555` 等）の Arduino ライブラリでは、グローバルに `#define P00 0`, `#define P01 1`, ..., `#define P10 8` が定義されています。プリプロセッサマクロは C++ の `namespace` も貫通して衝突するため、ADX ヘッダでは裸の `P01`〜`P10` を定義せず、確実に衝突しない **`ADX_P01`〜`ADX_P10`**（および機能エイリアス `ADX_AIN`, `ADX_CS` 等）を正規名とします。
- **`S00` の非公開**: アプリケーションから誤ってデバッグ線を操作しないよう、通常のボードヘッダでは `S00` を定義しません。

```cpp
#include "ADX_CORE_U.h"   // 将来 CORE-CX5 等へ移行するときはここを1行変更するだけ

void setup() {
  pinMode(ADX_P07, OUTPUT);       // 汎用出力なら論理ピン ID で直感的に（ADX_CS と同義）
}

void loop() {
  int val = analogRead(ADX_P01);  // 全 Core 保証のシールド付きアナログ入力（ADX_AIN と同義）
  digitalWrite(ADX_P07, val > 512);
}
```

## 3. 主な工学的メリットと構造解説 (Engineering Rationale)

### 3.1 産業盤トポロジー適合電源配置 (`VBUS`: Pins 17〜20)
Pins 17〜20 に大電流幹線（`VBUS`）を集中配置したのは、制御盤・産業機器の鉄則である**「弱電（計装・通信）は上、強電（主電源・動力）は下」**という配線公理に、基板内部および前面端子配置を完全に一致させるためです。

1. **前面 I/O 端子台との直進ルーティング (Straight-Through Alignment):**  
   制御盤内の配線ダクトは「上部＝通信・センサー線」「下部＝電源・動力線」で分離されています。20-Pin IDC の最下段に `VBUS` を置くことで、基板下辺の太いベタ銅箔パターンを通じて、前面最下部の電源受電端子台へ一直線に最短配線できます。盤内ダクトからモジュール端子台への引き込み線が盤内で不必要に交差（クロス）するリスクが全廃されます。
2. **基板内クロスオーバーの全廃 (Zero Signal Crossings):**  
   大電流プレーンが基板の下層・下半分で完結するため、基板上部を走る微弱なアナログ計測（`P01 / AIN`）や高速通信（SPI/UART）のパターンを大電流ラインが横切る必要が一切ありません。大電流スイッチングノイズや IR ドロップによる通信・アナログ妨害を根本から防ぎます。
3. **副次的な重力物理安全性の確保:**  
   この底面配置の副次的メリットとして、縦型スロット配置時に万一ネジ端子台から給電線が緩んで外れた場合でも、電線は自然と下部の配線ダクト側へ垂れ下がるため、上方の通信端子台へ接触・混触する事故が構造的に防止されます。
4. **2×2 正方形ベタプレーン:**  
   Pins 17〜20 は完全な $2 \times 2$ 正方形を形成しているため、PCB CAD 上で表裏のベタ電源プレーンを形成しやすく、低インピーダンスで最大 2A〜3A 連続の電力供給と優れた放熱性を両立します。

### 3.2 保護境界壁 (`Pin 16: GND`)
- **短絡時の安全遮断:**  
  大電流電源クラスタ（Pins 17〜20）の直上に `Pin 16 (GND)` を配置しています。フラットケーブル圧接時の位置ズレや芯線ヒゲの接触が発生した場合でも、VBUS は直上の GND へ短絡するため、給電側の保護回路（PTC ヒューズやロードスイッチ）が即座に動作し、上部の微小信号線（Pins 1〜15）に高電圧が漏れるのを物理的に遮断します。

### 3.3 最外端ガード ＆ `P01 (AIN)` コプレーナ・シールド (`Pins 1〜4`)
- **ケーブル端の静電保護:**  
  フラットケーブルの最端（芯線 #1）に `GND` を配置。盤内の金属フレームとの摩擦や外部ノイズによる影響を外縁部でシャットアウトします。
- **微弱アナログの完全隔離:**  
  `P01`（Pin 3: `AIN`）は、外周側の Pin 1 (`GND`) と内周側の Pin 4 (`GND`) によって挟み込まれたコプレーナ・ウェーブガイド（シールド）構造を形成します。隣接する `P02`（Pin 5: `EXTCLK`）などの高速デジタルスイッチングノイズが微弱なアナログ計測値に飛び込むのを防ぎます。

### 3.4 クロック伝送シールド (`Pins 4〜6`)
- 高速クロック線 `P02`（Pin 5: `EXTCLK`）は、両隣の Pin 4 (`GND`) および Pin 6 (`GND`) で挟み込まれたコプレーナ導波路構造です。外部システムクロックや同期デバッグクロック（`SWCLK`）の空間ノイズ放射（EMI）を抑え、隣接するアナログ線や通信バスへのクロストークを完全に遮蔽します。

### 3.5 システムデバッグ・出荷検査バス (`S00` [Pin 2] ＆ `P02` [Pin 5])
- **1線式および2線式プログラミングの完全統合:**  
  8-bit MCU から 32-bit RISC-V/ARM まで多様なアーキテクチャをサポートするため、`S00` と `P02` をシステム制御ペアとして定義しています。
  - **CORE-U / CORE-A5 (ATtiny1616)**: `S00`（Pin 2）に `PA0` (UPDI) を割り当て、1線で出荷検査・書き込みを実施。
  - **CORE-CX5 (CH32X035)**: `S00`（Pin 2）に `PC18` (SWDIO)、`P02`（Pin 5）に `PC19` (SWCLK) を割り当て、**20-Pin IDC ヘッダーを治具に 1 本挿すだけで給電と 2-wire SDI 書き込みが 100% 完結**（ポゴピン治具が不要）。
- **製造と現場保守のシナリオ:**  
  工場検査時は 20P IDC ヘッダーから自動テストとファームウェア／ブートローダーの書き込みを実施し、現場運用時は通信ポート経由で保守を行う運用を標準化します。

## 4. 拡張 CARD 設計ガイドライン (Design Guidelines for Cards)

ADX 準拠の拡張 Card（アドオン基板）を設計する際は、以下のルールを遵守してください：

1. **電源受電および PoL（Point of Load）レギュレーション:**
   - Pins 17〜20 の `VBUS` は必ず 4 ピンすべてをベタ銅箔パターンへ結合してください。
   - **3.3V 電源はバス上を供給されません**。Card 上で 3.3V ロジック電源が必要な場合は、`VBUS`（Pins 17〜20）を受けて Card 上の LDO または DC-DC レギュレータで降圧・生成してください。
2. **`S00`（Pin 2: `OWD`）の接続禁止 (MUST):**
   - 一般の拡張 Card は **`S00`（Pin 2）を未接続（N.C.）** としてください。
   - **GND への直結禁止**: タクトスイッチやプルダウン回路を直接 `S00` に接続してはなりません（デバッグパケットの破壊や治具通信の衝突を防ぐため）。
3. **`P02`（Pin 5: `EXTCLK`）の 0Ω アイソレーション設計 (RECOMMENDED / SHOULD):**
   - Card 側から外部発振器等でクロックを注入・駆動する場合、または監視回路・汎用 GPIO 回路を接続する場合、**直列に 0Ω 抵抗（例: `R_P02` / `R_EXTCLK`）またはソルダージャンパを配置し、未実装（DNP: Do Not Populate）で電気的に完全切断できる構造とすることを強く推奨**します。
   - **相互運用性の担保**: ATtiny1616 構成では 0Ω を実装してクロック供給・GPIO 利用を行い、2-wire SWD を使う CH32X035 構成では 0Ω を未実装（DNP）とすることで、Core 側のデバッグピン利用との衝突を完全に防止できます（同一の Card 基板で全 Core ボードに対応可能）。
4. **未使用バスの汎用 GPIO 流用 (`P01`, `P03`〜`P10`):**
   - Card 上で UART / I2C / SPI を使用しない場合、該当する `P03`〜`P10`（および `P01`）は通常の 3.3V 汎用 GPIO として自由に使用できます。ただし、他の Card が `P05`/`P06` に I2C プルアップを実装しているマルチカード構成では負荷干渉に注意してください。
5. **I2C プルアップ抵抗の配置:**
   - `P05`（Pin 9: `I2C_SCL`）および `P06`（Pin 10: `I2C_SDA`）には、Core ボード側でプルアップ抵抗を実装していない場合があります。Card 側またはバス全体で 1 箇所のプルアップ（2.2kΩ〜4.7kΩ @ 3.3V）を設けてください。
6. **リターンパスと高周波配線:**
   - 高速な SPI バス（`P07`〜`P10` / Pins 12〜15）やクロック配線は、直近の GND（Pin 11, 16）と近接させてリターンパスを確保してください。
7. **基板シルク表記:**
   - コネクタ付近のシルクスペースが限られる場合は **`S00`, `P01`〜`P10`, `GND`, `VBUS`** を主表記とし、余裕があれば `P03/TX`, `P07/CS` のように副機能を併記することを推奨します。

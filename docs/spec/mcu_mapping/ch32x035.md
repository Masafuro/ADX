# ADX Hardware Mapping: WCH CH32X035
(Reference Target Board: ADX CORE-CX5)

**Standard Reference**: [ADX 20-Pin Bus Specification (ADX_PINOUT.md)](../ADX_PINOUT.md) (Standard: `ADX-BUS-SPEC-v5.0`)  
**Status**: Reference  
**Target MCU**: WCH **CH32X035G8U6** (QFN-28, 4mm × 4mm, 0.4mm pitch)  
**Core Architecture**: QingKe 32-bit RISC-V4C (RV32IMAC), up to 48 MHz  
**Memory Configuration**: 62 KB Flash, 20 KB SRAM  
**Operating Condition**: 3.3V DC (Onboard LDO) / 48 MHz Internal Oscillator with USB Clock Auto-Trimming  

---

## 1. Overview

This document specifies how the universal signals and Logical Pin IDs (`P01`–`P11`) of the **ADX 20-Pin Bus (`v5.0`)** map to the **WCH CH32X035** RISC-V microcontroller on the **ADX CORE-CX5** reference board.

The CH32X035 integrates an internal USB 2.0 Full-Speed PHY with clock auto-trimming, eliminating the need for an external crystal and external USB-UART bridge IC, while providing 5V-tolerant GPIOs operating natively at 3.3V LVCMOS levels. Under `ADX-BUS-SPEC-v5.0`, the 2-wire SDI debug pair (`PC18` / `PC19`) is kept strictly onboard (test pads / dedicated debug header), freeing all 11 IDC signal pins (`P01`–`P11`) with zero Card-side `0Ω` DNP restrictions and adding dedicated RS-485 Driver Enable (`P03 / UART_DE`).

## 4. Programming, Debug & Field Maintenance Architecture

### 4.1 Core-Board Self-Contained Programming (Onboard 2-Wire SDI / USB)
Following `ADX-BUS-SPEC-v5.0` Section 4.3.1, programming and debug interfaces reside strictly on the Core board:
1. **Factory Flashing & Hardware Debug**: Dedicated onboard test pads / header expose **`SWDIO` (`PC18`)**, **`SWCLK` (`PC19`)**, and **`GND`** for **WCH-LinkE (RISC-V mode)** pogo-pin or probe attachment, without interfering with any of the 11 IDC bus signals (`P01`–`P11`).
2. **Default Always-On SDI**: Because `PC18` / `PC19` are no longer shared with `P02 (EXTCLK)`, 2-wire SDI remains permanently active across application runtime without ever conflicting with expansion Cards.

### 4.2 Field Maintenance & Sketch Flashing (Dual Type-C / UF2)
- **Zero-Install Drag & Drop**:
  When a user holds the `UF2 BOOT` button (`PC0`) while inserting the communication Type-C cable, the board enumerates as a standard USB mass storage drive (`ADX-CX5`).
- **Universal OS Compatibility**:
  Firmware updates require only dragging and dropping a compiled `.uf2` binary into the folder. No vendor drivers, COM port tools, or browser permissions are required.

### 4.3 Emergency USB ROM ISP Recovery (`PC17`)
If Flash memory or the UF2 bootloader is corrupted or erased:
1. Hold the dedicated ROM BOOT button (pulling `PC17 / UDP` to 3.3V) while plugging in the communication Type-C cable.
2. The MCU boots directly into the internal **WCH ROM ISP bootloader**.
3. Firmware can be re-flashed directly over USB using open-source tools (`wchisp`) or WCHISPStudio without requiring a WCH-LinkE hardware probe.

## 5. Power Domain & Dual-Port Isolation

To eliminate PC port tripping and ground loops in industrial field deployments:
1. **Communication Port (16P Type-C)**:
   - Protected by a 500 mA PTC resettable fuse and low-$V_F$ Schottky barrier diode (SBD).
   - CC1 and CC2 lines are pulled down to GND via precision $5.1\,\text{k}\Omega$ resistors ($1\%$), establishing standard 5V sink capability immediately upon cable insertion without firmware intervention.
   - SBD prevents high-current reverse back-feeding from external `VBUS` into the host PC.
2. **Power Port (6P Type-C)**:
   - Dedicated high-current power input routed directly through a 2.0A–3.0A PTC fuse into `VBUS` (Pins 17–20).
   - Feeds onboard 3.3V LDO and external Card modules on the 20-pin bus.

## 6. Firmware Configuration Rules

To route serial and timer peripherals cleanly under `ADX-BUS-SPEC-v5.0`, firmware implementations MUST apply the following configuration guidelines:

### 6.1 High-Speed Software I2C (`P06` & `P07` / Pins 9 & 10)
Due to silicon errata and QFN-28 pin packaging constraints on native I2C, I2C communication is driven via high-speed GPIO bit-banging:
- Initialize `PB8` (`ADX_P06` / `SCL`) and `PB9` (`ADX_P07` / `SDA`) in **Open-Drain Output Mode with internal pull-ups enabled**:
  ```c
  GPIO_InitTypeDef GPIO_InitStructure;
  RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
  GPIO_InitStructure.GPIO_Pin = GPIO_Pin_8 | GPIO_Pin_9;
  GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
  GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
  GPIO_Init(GPIOB, &GPIO_InitStructure);
  ```
- Driven by the 48 MHz 32-bit RISC-V core, this implementation reliably achieves standard $100\,\text{kHz}$ and fast-mode $400\,\text{kHz}$ timing.

### 6.2 Hardware SPI1 (`P08`–`P11` / Pins 12–15)
SPI1 operates natively on `PA4` (`ADX_P08` / NSS), `PA7` (`ADX_P09` / MOSI), `PA6` (`ADX_P10` / MISO), and `PA5` (`ADX_P11` / SCK) without AFIO remapping:
```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_SPI1, ENABLE);
// PA5 (ADX_P11 / SCK), PA7 (ADX_P09 / MOSI): GPIO_Mode_AF_PP
// PA6 (ADX_P10 / MISO): GPIO_Mode_IN_FLOATING
// PA4 (ADX_P08 / NSS): Controlled as standard GPIO active-LOW chip select
```

### 6.3 Hardware USART1 & RS-485 Direction Control (`P03`–`P05` / Pins 6–8)
USART1 operates natively on `PB10` (`ADX_P04` / TX) and `PB11` (`ADX_P05` / RX), paired with `PB12` (`ADX_P03` / `UART_DE`) for half-duplex RS-485 transceivers:
```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_USART1, ENABLE);
// PB10 (ADX_P04 / TX): GPIO_Mode_AF_PP
// PB11 (ADX_P05 / RX): GPIO_Mode_IN_FLOATING
// PB12 (ADX_P03 / DE): GPIO_Mode_Out_PP (assert HIGH before TX, release LOW on USART_FLAG_TC)
```

# ADX Hardware Mapping: WCH CH32X035
(Target Board: ADX CORE-CX3)

**Standard Reference**: [ADX 20-Pin Bus Specification (ADX_PINOUT.md)](../ADX_PINOUT.md) (Standard: `ADX-BUS-SPEC-v4.1`)  
**Target MCU**: WCH **CH32X035G8U6** (QFN-28, 4mm × 4mm, 0.4mm pitch)  
**Core Architecture**: QingKe 32-bit RISC-V4C (RV32IMAC), up to 48 MHz  
**Memory Configuration**: 62 KB Flash, 20 KB SRAM  
**Operating Condition**: 3.3V DC (Onboard LDO) / 48 MHz Internal Oscillator with USB Clock Auto-Trimming  

---

## 1. Overview

This document specifies the hardware interconnect and peripheral assignment mapping the universal **ADX 20-Pin Bus (v4.1)** to the **WCH CH32X035** RISC-V microcontroller on the **ADX CORE-CX3** board.

The CH32X035 integrates an internal USB 2.0 Full-Speed PHY with clock auto-trimming, eliminating the need for an external crystal and external USB-UART bridge IC, while providing 5V-tolerant GPIOs operating natively at 3.3V LVCMOS levels.

## 4. Programming, Debug & Field Maintenance Architecture

### 4.1 Automated Factory Test & Flashing (Pins 2 & 5: 2-Wire SDI)
During factory assembly at the automated test fixture:
1. The 20-pin IDC Eject Header mates with the test harness.
2. The fixture applies nominal $5\,\text{V}$ onto `VBUS` (Pins 17–20).
3. The fixture connects **WCH-LinkE (RISC-V mode)** directly to:
   - **`SWDIO` (Pin 2: `PC18`)**
   - **`SWCLK` (Pin 5: `PC19`)**
   - **`GND` (Pins 1, 4, 6, 11, 16)**
4. **Complete Header Integration**: No separate pogo pins or test pads are required for firmware programming.
5. The fixture runs automated boundary-scan continuity checks and flashes the custom **ADX UF2 USB Mass Storage Bootloader** into Flash memory.

### 4.2 In-Circuit Debugging Policy (Default SDI Always-On)
To maximize developer experience (UX) and prevent accidental controller lockups:
- **Default State**: The 2-wire SDI interface (`PC18 / PC19`) **remains permanently active by default** across application runtime.
- **Hardware Debugging**: Developers can attach a WCH-LinkE debugger across the 20-pin IDC bus at any time to set hardware breakpoints, step through code, and inspect registers without firmware reset penalties.
- **Opt-In Timer PWM Reconfiguration**:  
  Only in specialized applications requiring `TIM2_CH1` PWM output on IDC Pin 5, user firmware may explicitly disable SDI via `AFIO` remapping registers:
  ```c
  // Optional: Disable SDI to release PC19 for TIM2_CH1 PWM output
  RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);
  GPIO_PinRemapConfig(GPIO_Remap_SWJ_Disable, ENABLE);
  ```

### 4.3 Field Maintenance & Sketch Flashing (Dual Type-C / UF2)
- **Zero-Install Drag & Drop**:
  When a user holds the `UF2 BOOT` button (`PC0`) while inserting the communication Type-C cable, the board enumerates as a standard USB mass storage drive (`ADX-CX3`).
- **Universal OS Compatibility**:
  Firmware updates require only dragging and dropping a compiled `.uf2` binary into the folder. No vendor drivers, COM port tools, or browser permissions are required.

### 4.4 Emergency USB ROM ISP Recovery (PC17)
If the Flash memory or UF2 bootloader is corrupted or erased:
1. The user holds the dedicated ROM BOOT button (pulling `PC17 / UDP` to 3.3V) while plugging in the communication Type-C cable.
2. The MCU boots directly into the internal **WCH ROM ISP bootloader**.
3. Firmware can be re-flashed directly over USB using standard open-source tools (`wchisp`) or WCHISPStudio without requiring a WCH-LinkE hardware probe.

## 5. Power Domain & Dual-Port Isolation

To eliminate PC port tripping and ground loops in industrial field deployments:
1. **Communication Port (16P Type-C)**:
   - Protected by a 500 mA PTC resettable fuse and low-$V_F$ Schottky barrier diode (SBD).
   - CC1 and CC2 lines are pulled down to GND via precision $5.1\,\text{k}\Omega$ resistors ($1\%$), establishing standard 5V sink capability immediately upon cable insertion without firmware intervention.
   - SBD prevents high-current reverse back-feeding from external `VBUS` into the host PC.
2. **Power Port (6P Type-C)**:
   - Dedicated high-current power input routed directly through a 2.0A–3.0A PTC fuse into `VBUS` (Pins 17–20).
   - Feeds onboard 3.3V LDO and external Card modules on the 20-pin bus.

## 6. Firmware Configuration Rules

To route serial and timer peripherals cleanly without hardware conflicts, firmware implementations MUST apply the following configuration guidelines:

### 6.1 High-Speed Software I2C (Pins 9 & 10)
Due to silicon errata and QFN-28 pin packaging constraints on native I2C, I2C communication is driven via high-speed GPIO bit-banging:
- Initialize `PB8` (`SCL`) and `PB9` (`SDA`) in **Open-Drain Output Mode with internal pull-ups enabled**:
  ```c
  GPIO_InitTypeDef GPIO_InitStructure;
  RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
  GPIO_InitStructure.GPIO_Pin = GPIO_Pin_8 | GPIO_Pin_9;
  GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
  GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
  GPIO_Init(GPIOB, &GPIO_InitStructure);
  ```
- Driven by the 48 MHz 32-bit RISC-V core, this implementation reliably achieves standard $100\,\text{kHz}$ and fast-mode $400\,\text{kHz}$ timing.

### 6.2 Hardware SPI1 (Pins 12–15)
SPI1 operates natively on `PA4` (NSS), `PA5` (SCK), `PA6` (MISO), and `PA7` (MOSI) without AFIO remapping:
```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_SPI1, ENABLE);
// PA5 (SCK), PA7 (MOSI): GPIO_Mode_AF_PP
// PA6 (MISO): GPIO_Mode_IN_FLOATING
// PA4 (NSS): Controlled as standard GPIO active-LOW chip select
```

### 6.3 Hardware USART1 (Pins 7 & 8)
USART1 operates natively on `PB10` (TX) and `PB11` (RX):
```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_USART1, ENABLE);
// PB10 (TX): GPIO_Mode_AF_PP
// PB11 (RX): GPIO_Mode_IN_FLOATING
```

# Milestone 4-1 (M4-1): 極小ブートローダー (<1024 Bytes) 単一 Flash ページ書き込み実証

## 1. 概要と目的
本マイルストーン（M4-1）は、M4 で判明した「実行中コードの自己上書き（自爆）」という物理的制約を根本克服するため、**ブートローダー全体のバイナリサイズをハードウェア保護境界（`BOOTEND = 0x04` = 1,024 バイト）の内側に完全に収めた状態** で、物理 Flash メモリ（`0x0400` / Page 16）への消去書き込みおよび 100% 読み出しベリファイを実証します。

### 核心スペック
* **総バイナリサイズ**: **1,022 バイト**（1,024 バイト上限に対し 2 バイトの安全マージン）
* **プログラム配置範囲**: **`0x0000` 〜 `0x03FE`**（Page 0 〜 Page 15 の中）
* **書き込み対象領域**: **Page 16 (`0x0400` 〜 `0x043F`)** は 100% 完全に更地のユーザーアプリ領域！
* **自己破壊リスク**: **ゼロ（自爆の完全排除）**
* **ヒューズ変更**: **不要（実機の `BOOTEND = 0x04` のまま安全運用）**

## 2. 実行手順 (Windows PowerShell)

### Step 1: UPDI による M4-1 ファームウェア書き込み (COM20)
```powershell
cd firmware/bootloader/PLAN/BR32/M4_1_compact_bootloader
pymcuprog write -d attiny1616 -t uart -u COM20 -f m4_1_flash.hex --erase --verify
```

### Step 2: M4-1 ベンチマーク ＆ ベリファイ実行 (COM19)
```powershell
python .\m4_1_flash_bench.py --port COM19
```

## 3. 検証項目と合否判定基準 (GRADE A+)

| 項目 | 検証内容 | 合格基準 |
| :--- | :--- | :--- |
| **1. バイナリサイズ** | `BOOTEND=0x04` 境界内への収容 | $\le 1,024$ バイト (`_etext < 0x0400`) |
| **2. 自己同定** | `CMD_IDENTIFY` による UID 取得 | スレーブ既知 UID（`0x30 53 51 46 33 34 29 29 14 21`）の取得 |
| **3. ベースライン読出** | 書き込み前の Page 16 読み出し | `CMD_READ_CHUNK` で 64B 正常取得 |
| **4. 4チャンク書込** | Page 16 への 16B $\times$ 4 書込 ＆ 即時 ACK | 4 チャンクすべて `STATUS_OK` ＆ エコー一致 |
| **5. 非同期 Flash コミット** | ACK 送出直後の 25ms 消去書き込み | マイコン自爆・フリーズゼロ、次サイクル即応 |
| **6. 物理 Flash ベリファイ** | 物理 Flash からの 64B 読出照合 | **64/64 バイト 100% 完全一致 (Bit-for-Bit Match)** |
| **7. 保護領域ガード** | Page 0 (0x0000) への書き込み拒絶 | **`STATUS_ERR_PROTECT (0x03)` 返信** |

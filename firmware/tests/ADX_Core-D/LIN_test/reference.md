
# ATtiny1616-MNR LINスレーブ機能 & 利用方法 技術リファレンス

ATtiny1616-MNRが搭載するUSART0モジュールは、ハードウェアによる**LINスレーブ（LIN Slave Support）**機能をサポートしています。これらを利用することで、CPUのオーバーヘッドを最小限に抑えつつ、信頼性の高いLIN通信を実装することができます。

---

## 1. LIN用物理ピンアサイン (USART0)
ATtiny1616のピンレイアウトにおける、USART0のデフォルト機能ピンは以下の通りです。

*   **TxD (送信):** **PA1** (ピン20)
*   **RxD (受信):** **PA2** (ピン18)
*   **XDIR (送信方向制御/DE):** **PA4** (ピン2)
*   **\RE (受信イネーブル制御):** **PA7** (ピン5)（※ソフトウェア制御用の緩衝ラインとしても機能）

---

## 2. ハードウェアLINスレーブサポート機能
ATtiny1616のUSARTは、LIN仕様（ブレーク、同期、PID、レスポンス）に準拠した以下のハードウェア支援機能を備えています。

### ① ブレーク検出 (Break Character Detection)
*   **仕様:** 11ビット時間以上の連続したLレベル（dominant）を検出すると、それを有効なブレークフィールドとして自動判定します。
*   **BDF (Break Detected Flag):** 有効なブレークおよびSyncキャラクタの受信に成功すると、`STATUS` レジスタの `BDF` フラグが自動的にセットされます。

### ② 自動ボーレート同期 (Auto-baud)
*   **動作原理:** ブレークに続いて送信される **`0x55` (Syncキャラクタ)** の立ち下がりエッジから、続く8ビット時間（8 Tbit）を内部カウンターで測定します。
*   **自動更新:** 測定完了後、測定値が自動的に64で除算され（上位10ビットがクロック分周、下位6ビットが分数部）、ボーレートジェネレータレジスタ **`USART0.BAUD` が自動的に更新**されます。これによりマスタクロックとの完全な同期が自動確立されます。
*   **ISFIF (Inconsistent Sync Field Error):** 受信したSyncキャラクタが `0x55` でない場合や、測定されたボーレートが許容範囲外の場合は、`STATUS` の `ISFIF` フラグがセットされ、`BAUD` の更新は行われません。

### ③ 保護識別子 (PID) とレスポンススペースの自動識別
*   **DATAビットの役割:** LINAUTO受信モード時、`USART0.RXDATAH` の最下位ビット `DATA` は、受信バッファ内のデータが「PID」か「レスポンス（データ/チェックサム）」かを識別するフラグとして機能します。
    *   **`DATA == 0`:** 受信されたデータが**PID（保護識別子）**であることを示します。
    *   **`DATA == 1`:** 受信データが**レスポンススペース（通常のデータバイト等）**であることを示します。

### ④ 自動パリティチェック (Auto-parity check)
*   **動作原理:** PID受信時（`DATA == 0` のとき）、ハードウェアは自動的にパリティ方程式の計算を行います。
    *   $P_0 = ID_0 \oplus ID_1 \oplus ID_2 \oplus ID_4$
    *   $P_1 = \text{NOT}(ID_1 \oplus ID_3 \oplus ID_4 \oplus ID_5)$
*   **PERR (Parity Error Flag):** 計算されたパリティと受信したパリティビットが一致しない場合、`RXDATAH` レジスタの `PERR` フラグが自動的にセットされます。

## 3. レジスタ設定と実装手順

### ① ポートと方向制御の初期化
PA1 (TxD) を出力に、PA2 (RxD) を入力に設定します。
```c
PORTA.DIRSET = PIN1_bm; // PA1 (TxD) を出力設定
PORTA.DIRCLR = PIN2_bm; // PA2 (RxD) を入力設定
```

### ② 通信モードとフレーム形式の設定 (`USART0.CTRLC`)
非同期モード、パリティなし（PIDパリティチェックはLINAUTO内で独立して機能するため、レジスタ上はDisabledにします）、文字サイズ8ビットに設定します。
*   `CMODE[1:0] = 0x0` (ASYNCHRONOUS / 非同期USART)
*   `PMODE[1:0] = 0x0` (DISABLED / パリティ無効)
*   `CHSIZE[2:0] = 0x3` (8BIT / 8データビット)

### ③ 受信モードと送受信の有効化 (`USART0.CTRLB`)
LIN自動ボーレート（制約付き）モードを設定し、送受信を有効化します。
*   `RXMODE[1:0] = 0x3` (LINAUTO: LIN制約付き自動ボーレートモード)
*   `RXEN = 1` (受信機有効)
*   `TXEN = 1` (送信機有効)

### ④ 割り込みの有効化（任意） (`USART0.CTRLA`)
必要に応じて、受信完了や自動ボーレートエラー（ISFIFフラグセット時）の割り込みを有効にします。
*   `RXCIE = 1` (受信完了割り込み有効)
*   `ABEIE = 1` (自動ボーレートエラー割り込み有効)

## 4. 通信シーケンス制御のポイント

### ● ブレーク検出待ち (`WFB` のセット)
LINバスがアイドル状態のとき、または前フレームの処理が完了した際は、必ず `USART0.STATUS` の **`WFB` (Wait For Break) ビットに '1' を書き込みます**。
これにより、ハードウェアは RxD ライン上の次のL遷移を確実に「ブレークキャラクター」として検出し、通信同期シーケンスを開始します。

### ● レジスタの読み出し順序
エラーフラグ（`PERR`, `FERR`, `BUFOVF`）や `DATA` フラグは受信FIFOと連動しています。
そのため、データ取得の際は**必ず先に `USART0.RXDATAH`（高バイト）を読み出してから、`USART0.RXDATAL`（低バイト）を読み出してください**。低バイトを先に読み出すと、対応する高バイトのフラグが消去・更新されてしまいます。

### ● エラーからの復帰
Syncフィールドが不一致等で `ISFIF`（同期エラーフラグ）がセットされた場合は、ソフトウェアで **`ISFIF` ビットに '1' を書き込んでクリア**することで、USARTモジュールは自動的にアイドル状態（ブレーク検出待ち）に復帰します。

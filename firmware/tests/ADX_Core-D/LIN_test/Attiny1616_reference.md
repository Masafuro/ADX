# ATtiny1616 (megaTinyCore) における USART_DATA_bm について

ATtiny1616などの新しいアーキテクチャ（megaAVR 0-series / tinyAVR 0,1,2-series）では、USARTのレジスタ構造が従来のAVRから大きく変更されています。
結論から言うと、**`USART_DATA_bm` というマクロが存在しないのは正常な仕様**です。

## 1. なぜ `USART_DATA_bm` はないのか？

末尾の `_bm` は **Bit Mask（ビットマスク）** の略で、レジスタ内にある特定の1ビット（または数ビット）を取り出して判定・操作するために用意されているマクロです。
（例：`USART_WFB_bm` は、STATUSレジスタの0ビット目を取り出すための `0x01` というマスクです）

一方で、「データ」そのものは8ビット全体を使うため、マスクして特定のビットを取り出す必要がありません。そのため、データを取り扱うための `_bm` マクロは用意されておらず、**データレジスタそのものに直接アクセス**します。

## 2. 目的に合わせた正しい書き方

### A. データを送信 / 受信したい場合
従来のAVR（ATmega328Pなど）では `UDR0` という1つのレジスタで送受信を行っていましたが、ATtiny1616では**受信用と送信用でレジスタが完全に分離**されています。

- **送信する時:**
  ```c
  USART0.TXDATAL = data;  // 送信データレジスタに書き込む
  ```
- **受信する時:**
  ```c
  data = USART0.RXDATAL;  // 受信データレジスタから読み込む
  ```

### B. 「データを受信したか」「送信可能か」のフラグを確認したい場合
状態を確認するためのビットマスク（`_bm`）は、`USART0.STATUS` レジスタに対して使用します。これらは用意されています。

- **受信完了フラグ（RXC）:** `USART_RXCIF_bm`
  ```c
  // データを受信するまで待機
  while (!(USART0.STATUS & USART_RXCIF_bm));
  ```
- **送信バッファ空きフラグ（UDREの代わり）:** `USART_DREIF_bm`
  ```c
  // 送信バッファが空になるまで待機
  while (!(USART0.STATUS & USART_DREIF_bm));
  ```
- **送信完了フラグ（TXC）:** `USART_TXCIF_bm`
  ```c
  // 送信が完了するまで待機
  while (!(USART0.STATUS & USART_TXCIF_bm));
  ```

### C. （特殊）9ビット通信モードの「9ビット目」を操作したい場合
もしUSARTを9ビットモードで動かしていて、その9ビット目のデータを操作したい場合は、`USART0.RXDATAH`（受信）や `USART0.TXDATAH`（送信）の下位1ビット（ビット0）にアクセスします。

---

## まとめ
データの送受信を行いたい場合は、`_bm` マクロを探すのではなく、直接 `USART0.TXDATAL` または `USART0.RXDATAL` を使用してください。

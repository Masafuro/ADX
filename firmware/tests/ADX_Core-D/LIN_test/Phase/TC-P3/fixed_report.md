# ADX Core-D LN-485 テストスケッチ 修正点のまとめ

## 1. 修正の概要
スレーブ側（Subscriber）の初期化処理において、**Arduinoコアの `Serial` ライブラリ（割り込み駆動）と、レジスタ直接制御（ポーリング駆動）の競合を解消**しました。

## 2. 具体的な変更箇所

### 【変更前】スレーブ側の `setup()`
元々のコードでは、ピンの割り当て（リマップ）を確定させるために、Arduino標準の `Serial.begin()` を呼び出していました。

```cpp
// 1. ピンリマップ (PA1: TXD, PA2: RXD) を確定させるため、一度beginを呼ぶ
Serial.swap(1);
Serial.begin(BAUDRATE);
Serial.flush();

```

### 【変更後】スレーブ側の `setup()`

`Serial` ライブラリの使用をやめ、`PORTMUX`（ポートマルチプレクサ）と `PORTA` レジスタを直接操作し、手動でピンリマップと入出力（I/O）設定を行うように書き換えました。

```cpp
// 1. ピンリマップ (USART0 を PA1: TXD, PA2: RXD に変更)
PORTMUX.CTRLB |= PORTMUX_USART0_ALTERNATE_gc;

// 2. ピンの入出力方向を手動設定
PORTA.DIRSET = PIN1_bm; // PA1 (TX) = OUTPUT
PORTA.DIRCLR = PIN2_bm; // PA2 (RX) = INPUT

```

*(※これに伴い、共通の `setup()` にあった `pinMode(PIN_RXD, INPUT);` を、マスター側の初期化ブロック内に移動して整理しています。)*

---

## 3. なぜこの修正が必要だったのか（原因と理由）

スレーブ側では `LINAUTO` モードを使用し、`loop()` 内でハードウェアのフラグを直接監視（ポーリング）してデータを受信する設計になっていました。

```cpp
// スレーブ受信処理の要（ループ内）
while (USART0.STATUS & USART_RXCIF_bm) { ... }

```

しかし、初期化で **`Serial.begin()` を呼び出すと、megaTinyCore（Arduinoコア）の裏側でUARTの受信割り込み（RX割り込み）が自動的に有効化** されてしまいます。

これにより、以下の競合が発生していました。

1. スレーブ機がデータを受信する。
2. ハードウェアのバッファ（`RXDATAL`）にデータが入る。
3. **【問題発生】** `loop()` の処理が追いつく前に、**Arduinoコア側の裏側の割り込み処理が自動的に走り、データを `RXDATAL` からソフトウェア・リングバッファへ吸い上げてしまう。**
4. データが吸い上げられたことで、ハードウェアの受信完了フラグ（`RXCIF_bm`）が自動的にクリア（0）されてしまう。
5. `loop()` 内の `while` 条件が満たされず、プログラムがデータを受信したことに気づけない（データの取りこぼしや状態遷移エラーが発生）。

スレーブ側の初期化から `Serial` を完全に切り離し、純粋なレジスタ操作のみに統一することで、割り込みに邪魔されることなく `LINAUTO` モードによるハードウェア受信シーケンスが設計通りに機能するようになりました。

# LN-485 ネットワーク基本設計: Unique Pub / Common Sub アーキテクチャ

本ドキュメントは、LN-485 (LIN-based RS-485) ネットワークにおけるデータ通信の根本的なパラダイムである「Unique Pub / Common Sub（UP/CS）モデル」について定義する。

---

## 1. 基本概念

LN-485は、物理層に半二重通信のRS-485を使用し、データリンク層にLINのスケジュール通信を採用する。
バス上での電気的なデータ衝突（コリジョン）を完全に防ぎつつ、マルチノード間の柔軟なデータ共有を実現するため、すべての通信は「特定のPID（トピック）に対する パブリッシュ（送信）と サブスクライブ（受信）」として抽象化される。

## 2. アーキテクチャの原則

### 2-1. Unique Publisher（単一の送信者）の原則
*   **ルール:** 1つのPID（トピック）に対して、データをパブリッシュ（送信）する権限を持つノードは、ネットワーク全体で**「常にただ1つ」**に厳密に限定される。
*   **目的:** RS-485バス上での複数ノードの同時送信による電気的な衝突（ショート・データ破損）を原理的に排除する。

### 2-2. Common Subscriber（複数の受信者）の原則
*   **ルール:** 1つのPID（トピック）に対して、データをサブスクライブ（受信・利用）するノードの数に制限はない（0個でも、全ノードでもよい）。
*   **目的:** パブリッシャは「誰が聞いているか」を意識せずにデータをバスに放流し、必要なサブスクライバが各自でそのデータを拾う「疎結合なデータ共有」を実現する。

### 2-3. Master Broker の役割
*   マスターは、ネットワークの「交通整理役」として、あらかじめ決められたスケジュールに従ってPID（ヘッダ）をバス上にポーリングする。
*   マスター自身も、特定のPIDにおいては Unique Pub（全体への設定指示など）や Common Sub（センサデータの収集・ログ監視など）として振る舞う。

---

## 3. 通信パターンの分類

UP/CSモデルにより、LN-485上のすべての通信は以下の3パターンのいずれかに分類される。

| パターン | Unique Pub | Common Sub | ユースケース例 |
| :--- | :--- | :--- | :--- |
| **Type A** | マスター | 全スレーブ | マスターから全ノードへの一斉同期、緊急停止、ブロードキャスト設定 |
| **Type B** | スレーブ A | マスター | マスターによるスレーブAのセンサーデータ収集、ステータス監視 |
| **Type C** | スレーブ A | スレーブ B (+マスター) | マスターを介さない、スレーブA（センサー）からスレーブB（モーター）への直接分散制御 |

※ Type C において、マスターはデータを直接利用しなくても「バスの監視者（エラー検知）」として常にサブスクライブを行う。

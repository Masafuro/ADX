# LN-485 Master Broker 仕様案（最小構成と拡張性）

本ドキュメントは、LN-485 ネットワークにおけるマスターノード（Master Broker）の最小構成（MVP）および将来の拡張性について定義する。
Master Brokerの基本思想は「データの中身に関与せず、ネットワークの交通整理（Pub/Subの場作り）に徹すること」とする。

---

## 1. 最小構成（MVP: Minimum Viable Product）

Master Broker が Phase 3 の段階で備えるべき最低限の機能は以下の3点のみとする。

### 1-1. ヘッダの定期送出（ミニマム・スケジューラ）
*   **機能:** 事前に定義されたPID（トピック）の配列をラウンドロビン（順番）で読み出し、一定周期でヘッダ（`Break` + `Sync(0x55)` + `PID`）を送出する。
*   **目的:** スレーブ（Unique Pub）に対して、データをパブリッシュするための「場」を定期的に提供する（ネットワークのハートビート）。
*   **制約:** 最初はすべてのPIDを平等な間隔（例: 10〜20ms間隔）でポーリングする。

### 1-2. バスの全傍受（プロミスキャス・モード）
*   **機能:** ヘッダを送出した直後、マスター自身は受信状態（RX）へ移行し、バス上に流れる全データを傍受（サブスクライブ）する。
*   **目的:** 誰が何をパブリッシュしているか、または衝突（コリジョン）が発生していないかを物理的に監視する。
*   **制約:** データの「解釈」は行わず、受信した生のバイト列をそのままシリアルモニタや上位システム（ゲートウェイ）へ垂れ流す（ブリッジする）のみとする。

### 1-3. タイムアウト管理（ブロッキング回避）
*   **機能:** ヘッダ送出後、規定時間（数ms）データが来ない、または規定のバイト数を受信し終えたら、強制的に次のPIDポーリングへ移行する。
*   **目的:** 無応答のスレーブやノイズによって、マスターのループ処理が停止し、ネットワーク全体がダウンするのを防ぐ。

---

## 2. 拡張性（現在は実装しないが、考慮しておく余白）

以下の機能は MVP では実装を見送るが、将来の機能追加（Phase 4以降）に備えてアーキテクチャ上の余白を残しておく。

| 拡張項目 | 現在の実装（MVP） | 将来の拡張構想 |
| :--- | :--- | :--- |
| **エラーリカバリ** | エラー検知時はフラグを立ててログに出力するのみ。（何もしない） | 異常連続時のリトライ処理、該当ノードの切り離し、長期Breakによる強制バスクリアの発動。 |
| **スケジューリング** | 固定配列による単純なラウンドロビン（順番巡回）。 | 配列の動的書き換えによる「優先度付きポーリング（緊急コマンドの高頻度回覧など）」。 |
| **データ解釈** | Nバイトのバイナリデータとして上位PCへ丸投げ。 | マスター自身が特定のPID（例: 異常検知フラグ）を解釈し、フェイルセーフを自律発動する。 |

---

## 3. Phase 3 マスター側ステートマシン（状態遷移）案

Master Broker のメインループは、以下のシンプルな状態遷移を繰り返す。

1.  **[STATE_TX_HEADER]**
    *   配列から次のPIDを取得。
    *   `Break` $\rightarrow$ `Sync` $\rightarrow$ `PID` を送信。
    *   直後に受信モード（RX）へ切り替え。
2.  **[STATE_RX_WAIT]**
    *   スレーブからのデータを待機。
    *   データを受信したらバッファへ格納しつつ、シリアル等へ出力。
    *   **【終了条件】** 規定バイト数の受信完了、またはタイムアウトの発生。
3.  **[STATE_NEXT_PREP]**
    *   次のポーリング周期まで待機（インターバル）。
    *   1 に戻る。

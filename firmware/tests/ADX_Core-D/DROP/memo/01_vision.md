
# 産業用フィールドネットワーク DROP-Bus 仕様書・設計思想

**DROP-Bus** (**D**eterministic **R**elay with **O**ptional-master & **P**assive-failsafe Bus) は、極限の低コスト（単一SKU・水晶レス）と高度な決定論性、そして産業用機能安全（受動的フェイルセーフ）を両立させるために設計された半二重RS-485向け自律分散通信プロトコルである。

---

## 1. コア設計思想

1. **沈黙は安全（Silence is Safety）**
   * 異常検知時に複雑なリカバリや再送・スキップを行わない。
   * バトン（トークン）が落ちた（DROPした）瞬間、全ノードが無言でタイマー満了を迎え、出力を安全遮断（Safe Torque Off）する。
2. **Reverse Master（逆マスター方式）**
   * マスターは通常運行を支配しない。平常時はバスを一切専有せず、純粋な自律リレーを見守る。
   * 保守介入・ホットスワップ・再点火が必要な場合のみ、物理層で信号を衝突（DROP）させてリレーを強制停止し、新たな秩序を付与する。
3. **単一SKU・水晶レス（Pure & Minimalist Hardware）**
   * 末端ノードはすべて同一のハードウェア／ファームウェア構成（例: ATtiny1616内蔵RC発振器）。
   * クロックの絶対精度に依存せず、短時間の局所同期と固定フレーム長によって決定論性を担保する。

---

## 2. システム構成とトポロジー

```text
[Node 1] <───(RS-485 2-Wire)───> [Node 2] <───(RS-485 2-Wire)───> [Node 3]
  (SKU-A)                          (SKU-A)                          (SKU-A)
     │                                                                 │
     └───────────────────────[ (Optional) ]────────────────────────────┘
                         [ Reverse Master ]
                         (保守ツール/上位GW)

```
 * **物理層:** RS-485 半二重（2線式マルチドロップ / デイジーチェーン推奨）
 * **末端ノード構成:** 単一SKU（ID設定のみを保持）
 * **リバースマスター（オプション）:**
   * 平常時: バスの監視・ロギング（バトンドロップ回数、故障ノードの特定）
   * 異常・保守時: バスの衝突停止、フレーム再点火、ホットスワップ調停
## 3. プロトコル仕様
### 3.1 フレームフォーマット
固定長フレームを採用し、送信ジッターを極小化する。
| フィールド | バイト数 | 説明 |
|---|---|---|
| **SYNC** | 1 Byte | 0x55（LIN-Auto同期・クロック校正用エッジパルス） |
| **TARGET_ID** | 1 Byte | 次に発話権（バトン）を受け取るノードのID（Next_ID） |
| **SENDER_ID** | 1 Byte | 現在発話しているノードのID（MY_ID） |
| **PAYLOAD** | 固定 M Byte | 制御データ、センサー値、状態フラグなど |
| **CRC** | 1~2 Byte | 通信誤り検出（CRC-8 / CRC-16） |
### 3.2 決定論的リレー（平常時動作）
各末端ノードは **「MY_ID」** と **「NEXT_ID」** の2つのパラメータのみを保持する。
```text
Node 1 送信 (Target: 2) ──> Node 2 起動・送信 (Target: 3) ──> Node 3 起動・送信 (Target: 1) ──> ...

```
 * **受信処理:**
   1. 受信パケットのCRCが正常であれば、生存監視用ハードウェアタイマーをリセット。
   2. TARGET_ID == MY_ID の場合、即座に自身の固定長パケット（TARGET_ID = NEXT_ID）を送信。
 * **周期の決定論性:**
   ノード数を N、1フレーム時間を T_{\text{frame}}、送受信切替ギャップを T_{\text{gap}} としたとき、1周の周期 T_{\text{cycle}} は完全に固定される。
   
## 4. 安全および例外シーケンス
### 4.1 パッシブ・フェイルセーフ（断線・ノード脱落）
ノード故障や断線により Node X が返信を行わなかった場合：
```text
[Node 1] ──(Next: 2)──> [Node 2 (沈黙 / 故障)]
                              │ (バトン落下)
                              ▼
                      【全ノード タイマー満了】
                              │
                              ▼
                  【全ノード 即座に安全停止(STO)】

```
 * スキップ処理や自動再送などの「勝手な継続動作」を一切排除。
 * バトンが落ちた地点でシステム全体が自律的に同期停止する。
### 4.2 Reverse Master による介入（ホットスワップ・再点火）
保守員が特定ユニットを活線挿抜する場合、またはノイズ等で落ちたバトンを再始動させる場合：
```text
[通常リレー中]
Node 1 ──> Node 2 ──> Node 3 ...

[リバースマスター介入]
1. 意図的衝突: バスにドミナントパルス（ブレーク信号）を強制送出し、進行中フレームを潰す。
2. 全ノード沈黙: 全末端ノードがCRCエラー/タイムアウト待機状態へ移行。
3. 再編成/再点火: マスターが再初期化フレーム（SYNC + 新規構成のNext_ID）を送出。
4. リレー再開: 対象ノードを除外した構成でリレーが滑らかに再始動。

```
## 5. ノード実装例（C言語疑似コード）
```c
#include <avr/io.h>
#include <avr/interrupt.h>

#define MY_ID   (0x02)
#define NEXT_ID (0x03)

typedef struct {
    uint8_t sync;
    uint8_t target_id;
    uint8_t sender_id;
    uint8_t payload[4];
    uint8_t crc;
} DropPacket;

// UART受信完了ハンドラ
void on_drop_packet_received(const DropPacket *rx) {
    if (!verify_crc(rx)) {
        return; // CRC不一致時は何もしない（タイマーもリセットしない）
    }

    // 正当なパケットが流れているため生存タイマーをリセット
    reset_fail_safe_timer();

    // 自分のバトン順か判定
    if (rx->target_id == MY_ID) {
        DropPacket tx;
        tx.sync      = 0x55;
        tx.target_id = NEXT_ID;
        tx.sender_id = MY_ID;
        tx.payload[0] = read_sensor_data();
        tx.crc       = calculate_crc(&tx);

        rs485_transmit(&tx, sizeof(DropPacket));
    }
}

// 通信途絶監視タイマー（タイムアウト＝即時心中）
ISR(TCB0_INT_vect) {
    // パッシブ・フェイルセーフ発動
    hardware_safe_torque_off(); // モーター/出力のハードウェア遮断
    set_error_led(1);
    while (1) {
        // マスターによる明示的な再点火パケットを待つ、または電源断まで沈黙
    }
}

```
## 6. DROP-Bus の優位性マトリクス
| 評価軸 | 従来のLIN / Modbus | 一般的なトークンリング | DROP-Bus |
|---|---|---|---|
| **マスター依存性** | 常時必須（SPOFリスク） | 不要（ただし調停複雑） | **平常時不要（オプション化）** |
| **ハードウェアコスト** | マスターが高コスト | 水晶振動子がノード毎に必須 | **全ノード完全水晶レス（単一SKU）** |
| **フェイルセーフ性** | マスター依存 | スキップ等で暴走リスク | **受動的即時停止（完全心中）** |
| **通信効率** | 呼出/応答でオーバーヘッド大 | 高速 | **純粋な固定長リレーで理論最速** |
| **現場保守性** | マスターが死ぬと交換不能 | トポロジー把握が困難 | **リバースマスター挿入で活線保守** |
```

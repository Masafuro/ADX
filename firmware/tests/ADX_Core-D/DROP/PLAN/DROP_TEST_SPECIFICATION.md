## 2. 詳細テストケース仕様 (Test Case Specifications)

---

### Phase 1: 一体型フレーム送受信 ＆ CRC-16 検証

#### `TC-D1-01`: 一体型フレーム生成 ＆ 通常 UART 受信
* **【テスト目的】**
  送信ノードが「14 Tbit Break ＋ 2 Tbit Delimiter ＋ `0x55` ＋ `LEN` ＋ `TARGET_ID` ＋ `SENDER_ID` ＋ `PAYLOAD` ＋ `CRC-16`」の一体型パケットを生成・送出し、受信側（通常UART）でバイト列が完全に受信できることを確認する。
* **【合否判定基準 (Pass Criteria)】**
  * Break 検出に続き、`0x55`, `LEN=0x08`, `TARGET=0x02`, `SENDER=0x01`, データ8バイト, 正しいCRC-16（2バイト）が完全一致で受信されること。

#### `TC-D1-02`: スレーブ LINAUTO ハードウェア同期 ＆ ペイロード受信
* **【テスト目的】**
  受信側マイコンの `USART0.CTRLB` を `LINAUTO` モードに設定し、`0x55` によるオートボーレート自動校正を経て、可変長ペイロード（1〜64バイト）がサンプリング誤差なく受信できることを確認する。
* **【合否判定基準 (Pass Criteria)】**
  * `USART0.STATUS` の `BDF` が正常にセットされ、`BAUD` レジスタが自動補正されること。
  * `LEN` が 1, 16, 32, 64 バイトの各ケースにおいて、全ペイロードデータが欠落なくバッファリングされること。

#### `TC-D1-03`: CRC-16 誤り検出 ＆ 不正パケット破棄
* **【テスト目的】**
  1ビット反転ノイズを意図的に混入させたパケットを送出した際、受信側が CRC-16 不一致を検知してパケットを即時破棄することを確認する。
* **【合否判定基準 (Pass Criteria)】**
  * 正常パケット受信時は CRC 一致（PASS）、破損パケット受信時は CRC 不一致（FAIL）を検知して破棄すること。

#### `TC-D1-04`: LEN 不正値ガード（バッファオーバーラン防御）
* **【テスト目的】**
  ノイズ等により `LEN > 64` を受信した際、受信ステートマシンが直ちに受信をアボートし、SRAM 領域の破壊を防止することを確認する。
* **【合否判定基準 (Pass Criteria)】**
  * `LEN > 64` を受信した瞬間、後続バイトの受信を中止し、安全な待機状態へ遷移すること。

### Phase 2: 自律分散バトンリレー ＆ Pub/Sub 購読

#### `TC-D2-01`: 2ノード基本バトンパス ＆ 購読
* **【テスト目的】**
  Node A（Publisher: `0x01`, 購読: `0x02`）と Node B（Publisher: `0x02`, 購読: `0x01`）の間で、自律的なピンポン・バトンパスおよび Common Subscriber 購読が成立することを確認する。
* **【合否判定基準 (Pass Criteria)】**
  * Node A 送信（Target: 0x02） $\rightarrow$ Node B 受信（0x01のデータをRx Mailboxへ格納） ＆ 送信（Target: 0x01） $\rightarrow$ Node A 受信（0x02のデータをRx Mailboxへ格納）のリレーが連続動作すること。

#### `TC-D2-02`: 連続周回安定性 ＆ ジッター計測
* **【テスト目的】**
  バトンリレーを 10,000 周期以上連続稼働させ、パケット脱落回数およびサイクルタイム $T_{\text{cycle}}$ のジッターを計測する。
* **【合否判定基準 (Pass Criteria)】**
  * 10,000 周期において通信エラー率 0.00% を達成し、ジッターが理論許容幅（$\pm 20\,\mu\text{s}$ 以内）に収束すること。

#### `TC-D2-03`: Double Buffer Mailbox 連動
* **【テスト目的】**
  アプリ層（`loop()`）でセンサ模擬データを非同期に更新しながらリレーを回し、データ競合（Torn Read）や遅延が生じないことを確認する。
* **【合否判定基準 (Pass Criteria)】**
  * 受信側で取得したデータが常に連続かつ非破壊であり、リレー周期に影響を与えないこと。

#### `TC-D2-04`: Multi-rate スロット（不等周期リレー）
* **【テスト目的】**
  Node A に 2 つのスロット（`0x01` と `0x03`）、Node B に 1 つのスロット（`0x02`）を割り当て、`0x01 -> 0x02 -> 0x03 -> 0x01` の順で周回する不等周期リレー（Node A が 2倍の周波数で発話）を実証する。
* **【合否判定基準 (Pass Criteria)】**
  * Node A が 1 サイクル中にスロット `0x01`（制御データ）と `0x03`（ログデータ）を正しく切り替えて送出できること。
  * Node B が 2 回に 1 回の頻度でバトンを受け取り、安定した TDMA 的時間配分が成立すること。

### Phase 3: パッシブ・フェイルセーフ ＆ 自律心中 (Passive Fail-Safe STO)

#### `TC-D3-01`: TCB0 タイマー生存監視 ＆ リセット
* **【テスト目的】**
  正常フレーム（自ノード宛て・他ノード宛て問わず）を受信するたびに `TCB0` タイマーが確実にリセットされ、通常リレー中に STO が誤発動しないことを確認する。

#### `TC-D3-02`: 意図的断線 ＆ 即時安全遮断 (STO)
* **【テスト目的】**
  稼働中のバトンリレーにおいて通信線を意図的に断線させた際、残存全ノードが $T_{\text{timeout}}$ 以内に `TCB0` 割り込みを発動させ、LED / モータ出力を即時安全遮断（LOW固定）して沈黙することを確認する。

#### `TC-D3-03`: CRC 破損時のタイマー非リセット
* **【テスト目的】**
  破損パケットを受信した場合にタイマーリセットが行われず、確実にパッシブ STO が発動することを確認する。

---

### Phase 4: SYSTEM 0xFF 介入 ＆ 再送プラグイン

#### `TC-D4-01`: Mediator 意図的衝突（Break 注入）
* **【テスト目的】**
  稼働中のバトンリレーに対し、Mediator がバスへ強制 Break パルスを注入して全ノードを安全停止（STO）へ誘導できることを確認する。

#### `TC-D4-02`: Mediator 再点火フレーム (Re-Ignition)
* **【テスト目的】**
  STO で沈黙しているバスに対し、Mediator（Sender: `0xFF`）が有効なバトンIDを指定した再点火フレームを送出することでリレーが再始動することを確認する。

#### `TC-D4-03`: 再送プラグイン ＆ 局所リトライポリシー実証
* **【テスト目的】**
  `DropRetryPolicy_t` テーブルに基づき、対象バトン宛てのエラー時のみ局所再点火が行われ、最悪遅延時間が拘束されることを実証する。

#### `TC-D4-04`: SYSTEM `0xFF` 起動時 Ping 点呼 ＆ 点火 【新規】
* **【テスト目的】**
  電源投入後、SYSTEM（`0xFF`）が Node A（`0x01`）および Node B（`0x02`）に対して順次 Ping を送信し、各ノードからの Pong 応答（Target: `0xFF`）を確認した後に点火フレームを発出して本番自律リレーへ遷移するシーケンスを実証する。
* **【合否判定基準 (Pass Criteria)】**
  * 未応答ノードがある場合は本番点火を行わずエラーログを出力すること。
  * 全ノード応答確認後に点火フレームが発出され、スムーズに自律リレーへ移行すること。

---

### Phase 5: ハードウェア XDIR ＆ 高ボーレート評価

#### `TC-D5-01`: ハードウェア XDIR 自動方向制御
* **【テスト目的】**
  `USART0.CTRLA.RS485`（XDIR）による自動 DE 制御でバトンリレーが正常動作することを確認する。

#### `TC-D5-02`: 多重ボーレートスイープ (9.6k 〜 115.2k bps)
* **【テスト目的】**
  115200 bps までの各ボーレートにおける LINAUTO 同期安定性とリレー周回を評価する。

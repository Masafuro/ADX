# ATTINY1616ボードとRS-485フィールドネットワークにおける遠隔リセットシステムの検討
## 方式名：UUID ＆ LID（論理ID）ハイブリッド管理方式

---

## 1. 背景と解決すべき課題

* **背景:**  
  長距離（最大数百メートル規模）のRS-485マルチドロップバスに接続された分散ノード（ATtiny1616搭載）において、遠隔からのファームウェア更新（スケッチ書き込み）およびCPU暴走・フリーズ時の確実な復旧を実現したい。
* **技術的課題:**  
  * CPUが完全停止（割り込み禁止の無限ループやメモリ破壊）した状態では、ソフトウェア制御の再起動（WDTや通常通信によるソフトリセット）は期待できない。
  * 外付けリセット役マイコンを同一RS-485バスに配置する場合、送信系（TX/DE）の共有は物理層のインピーダンス乱れやバス衝突（バスファイト）を引き起こす。
  * リセット役マイコンを「送信不可（RX傍受のみ）」とした場合、設定パケットの到達・合意確認（ACK）が取れず、動的なID同期（同期ズレ、スプリットブレイン）が致命的なリスクとなる。
  * 現場作業において、UPDIを複数回差し替えてメモリを慎重に書き換えるような高摩擦・ヒューマンエラー誘発作業は排除しなければならない。

---

## 2. システム基本アーキテクチャ

本方式では、**「末端マイコンは極限までステートレス・単能に保ち、記憶とバインディング（紐付け）の責務はリソースが潤沢な上位管理システム（PC等）に集約する」**という原則を採用する。

│ 上位管理システム（PC / 現場保守ツール / マスターPLC） │
│ ・バインディングテーブル保持（LID ⇔ リセットチップUUID） │
│ ・RS-485トランシーバ経由で全コマンドを統括 │
└──────────────────────────────┬──────────────────────────────┘
│
RS-485 物理バス (A / B)
│
┌───────────────────────┴───────────────────────┐
▼ (RO: 受信傍受のみ) ▼ (RO/DI/DE: 送受信完全接続)
┌──────────────────────────────┐ ┌──────────────────────────────┐
│ 【リセットチップ】 │ │ 【メインチップ】 │
│ ATtiny1616 │ │ ATtiny1616 │
│ ・SIGROW内蔵UUIDで自己同定 │ │ ・論理ID (LID) で動作 │
│ ・TX/DE未接続（完全沈黙） │─RESET─>│ ・通常業務アプリ (Modbus等) │

└──────────────┬───────────────┘ └──────────────────────────────┘
│
[UPDIパッド] (万一のUUID吸い出し用リード端子)


### ハードウェア結線仕様
* **リセットチップ (ATtiny1616):**
  * RS-485トランシーバの **RO（RX出力）のみ** に接続。DI（TX）およびDE/REには一切物理配線を行わない。
  * 出力端子：メインチップの物理RESETピンをドライブするGPIO（通常時ハイインピーダンス/内部プルアップ、トリガ時オープン名目LOW出力）の**1本のみ**。
  * 外部端子：工場検査および万一の吸い出し用「UPDIパッド」を基板上に配置。
* **メインチップ (ATtiny1616):**
  * RS-485トランシーバへ通常通り全線接続（RO, DI, DE/RE）。
  * リセットチップとのインターフェースは**自身のRESETピンのみ**（追加のGPIO通信線などは一切不要）。

## 3. ID体系とパケットテーブルの分離

メイン通信路の「業務パケット」と、リセットチップが監視する「制御パケット」を完全に分離し、別のパケット構造・テーブルとして定義する。

### ① 業務・ブートローダ系通信（LID管理）
* **識別子:** 論理ID（LID: 1バイト、例: `0x01`〜`0x1E`）
* **対象:** メインチップ（通常アプリおよびOptibootブートローダ）
* **プロトコル:** Modbus RTU、またはLID指定型のファームウェア転送プロトコル
* **特徴:** メインチップは通常の双方向通信（TXによる応答・ACK）を行う。

### ② リセット系通信（UUID鍵管理）
* **識別子:** リセットチップ内蔵ROM固有UUID（ATtiny1616 SIGROW領域: 10バイトシリアル）
* **対象:** リセットチップ
* **プロトコル:** リセット専用パケット（暗号論的トークンを兼ねる）


[ リセット専用パケットフォーマット（例） ]
┌───────────┬──────────────┬────────────────────┬───────────┐
│ Preamble │ Target UUID │ Reset Magic Token │ CRC16 │
│ (2 Bytes) │ (10 Bytes) │ (4 Bytes 固定値) │ (2 Bytes) │
└───────────┴──────────────┴────────────────────┴───────────┘

* **堅牢性とセキュリティ:**  
  * 10バイトUUID ＋ 4バイト合言葉トークンにより、ノイズや通常通信データとの偶然の一致（誤爆）が天文学的確率（$2^{-112}$ レベル）で排除される。
  * リセット用UUIDは「ハードウェア固有の秘密鍵」として機能し、他の通信デバイスからの誤操作・不正リセットを遮断する。

## 4. 上位管理システムによるオーケストレーション

上位PC（または現場端末）側で、盤面スロット位置・論理ID（LID）・リセットUUIDのバインディングテーブルを保持・運用する。

### ノード管理テーブル構造（概念）
```yaml
nodes:
  - slot: 1
    lid: 0x01
    reset_uuid: "1E-94-22-01-AF-3B-8C-99-10-01"
  - slot: 2
    lid: 0x02
    reset_uuid: "1E-94-22-01-AF-3B-8C-99-10-02"
  # ...
  - slot: 5
    lid: 0x05
    reset_uuid: "1E-94-22-01-AF-3B-8C-99-10-05"
```

遠隔スケッチ書き換え / 非常時復旧シーケンス
トリガ:


上位アプリから「ノード #05 のリセット（またはスケッチ更新）」を実行。

テーブル参照:


上位アプリがテーブルを引き、LID 0x05 に対応するUUID 1E-94-22-...-05 を特定。

物理リセット送出:


RS-485バスに「Target UUID = 1E-94-22-...-05」のリセットパケットを同報送信。

ハードウェア強制介入:


ノード #05 のリセットチップのみが合致を検知し、メインチップのRESETピンを一定時間（例: 100ms）LOWに引き倒す（メインチップがフリーズしていても100%強制再起動）。

ブートローダ接続:


メインチップが再起動し、LID 0x05 を保持したブートローダ待機状態に入る。

上位アプリはリセット直後、RS-485経由で「LID: 0x05」宛てにスケッチ書き込みセッションを開始。

他ノードと混信することなく、安全にファームウェア書き換えが完了する。

5. 製造・現場運用・障害復旧のライフサイクル
現場の作業負担とミス誘発要因を徹底的に排除した運用設計。

フェーズ
作業内容
信頼性・安全性の担保
工場出荷
治具プログラマ（UPDI）で一括書き込み。


・リセット側：全基板共通ファーム書き込み ＆ UUID自動吸い出し。


・メイン側：ブートローダ書き込み。


治具PCがUUID一覧CSVを自動出力し、基板にQRコードシールを貼付。

リセットチップのファームウェアは全基板100%同一バイナリ。個別設定が不要。
現場導入
基板を盤面スロットに挿入。上位ツールの画面でスロット番号と基板QRコードをスキャンして登録（紐付け完了）。
バス接続前に机上で完了。RS-485上での動的ID設定やアドレス衝突の概念自体が存在しない。
基板交換
故障基板を予備基板へ交換。上位ツールの該当スロット行で新基板のQRコードを再スキャン（UUID更新）。
現場作業員は基板を差し替えてコードを読むだけ。マイコンの内部設定書き換え作業は一切発生しない。
最悪の例外


(フェイルセーフ)

「シール紛失・判読不能」「台帳データ消失」


現場ツール（PCまたは携帯端末）を基板上のUPDIパッドに当て、UPDIリードコマンドでSIGROW（UUID）を直接吸い出し。

読み出し（リード）専用であるため、ROM破壊リスクは物理的にゼロ。確実にUUIDを再特定・復旧できる。
6. 本方式の設計的優位性まとめ
完全な物理非干渉（バス完全性）:


リセットチップはRX傍受専用のため、TXバス競合やラインインピーダンスの悪化が物理的に生じない。

極限のミニマリズム（回路の単純化）:


チップ間結線は「RESET信号線 1本」のみ。合意形成用GPIO、ロータリースイッチ、外付けマルチプレクサ等はすべて不要。

ステートレスによる頑健性:


リセットチップはEEPROM書き換えや状態遷移を持たず、自身の不変UUIDに反応してピンを叩くだけの専用番人に徹するため、バグや通信途絶による文鎮化（ロックアウト）のリスクが根本から排除される。

二層化されたセキュリティ:


長大なUUIDと合言葉トークンにより、通常通信の化けや別機器の混在による誤リセットを完全に遮断する。

# WU-3: MR32 16B × 4-Chunk 仮想 SRAM 蓄積 ＆ パケット耐性実証ベンチ

本サンドボックスは、MR32 ブートローダーの最重要コアである **「16B × 4 チャンク方式による 64 バイト ページ蓄積ロジック」** と **「パケット欠損・順序逆転・重複耐性」** を実機（ADX Core-D）で実証するための実験模型です。

Flash メモリへの書き込みは一切行わず、SRAM 上の 64 バイトバッファに対してのみ読み書きを行うため、**文鎮化リスクは 100% ゼロ** です。

---

## 🛠️ ハードウェア結線 ＆ ジャンパ設定 (ADX Core-D)

WU-1 と全く同じ配線・ジャンパ設定でそのまま実行できます：
- **H2 (DE/RE)**: 2-3 ショート（連動制御）
- **H3 (クロック)**: 1-2 ショート（内部 20MHz）
- **H4 (終端抵抗)**: OPEN
- **COM ポート例**:
  - `COM20`: CH342K Port A (SerialUPDI 書き込みポート)
  - `COM21`: CH342K Port B (Soft-UART デバッグログ @ 9,600 bps)
  - `COM22`: 市販 USB-RS485 ドングル (CH340 @ 115,200 bps)

## 📥 手順 1: マイコンへのファームウェア書き込み

### `pymcuprog` コマンドライン（推奨）
```bash
# COM20 が UPDI ポートの場合
pymcuprog write -t uart -u COM20 -d attiny1616 -f wu3_sram_painter.hex --erase
```

### ソースコード再ビルド（Linux / WSL）
```bash
make clean all
```

## 🚀 手順 2: Python ベンチマークの実行

```bash
# COM22 が RS-485 ポートの場合
python wu3_sram_painter_bench.py --port COM22
```

### 実行される 5 大テストシナリオ:
1. **[SCENARIO 1] 順次ペイント ＆ 読み戻しベリファイ (0 $\to$ 1 $\to$ 2 $\to$ 3)**:
   - 64バイトの ASCII メッセージを 4 チャンクで順次書き込み。
   - 4 チャンク読み戻し、**64/64 バイト全 512 ビットが 100% 完全一致（Bit-for-Bit Perfect Match）** することを証明。
2. **[SCENARIO 2] シャッフル・順序逆転耐性 (3 $\to$ 1 $\to$ 0 $\to$ 2)**:
   - チャンク順序をわざとシャッフルして送信。`chunk_idx << 4` のオフセット配置により正しい位置にデータが自動整列されることを証明。
3. **[SCENARIO 3] 重複再送耐性 (0 $\to$ 1 $\to$ 1 $\to$ 2 $\to$ 3)**:
   - 同一チャンクを重複送信してもバッファが破壊されず、正しく完成することを証明。
4. **[SCENARIO 4] 欠損・タイムアウト自律回復**:
   - ページ 99 を途中で中断（未完）$\to$ 新しいページ 100 を送信。未完データを引きずらず安全に新規ページが形成されることを証明。
5. **[SCENARIO 5] 連続 10 ページ 高速ペイント ＆ スループット計測**:
   - ランダムデータ 64B $\times$ 10ページ（計640バイト、40パケット往復）を高速転送し、1ページあたりの転送所要時間（目標: 約 25ms 以内）と 16KB フル書き込み推定時間（約 6.6 秒）を実測。

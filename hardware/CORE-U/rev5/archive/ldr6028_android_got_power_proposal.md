## 1. 検討の背景と狙い

[EAA コンセプト構想書](EAA_3_friendly_concept.md) において、引き出しに眠る古い Android スマホを産業用 **GOT（Graphic Operation Terminal：グラフィック操作盤）** として活かす方向性が見えた。  
しかし、現行 rev5 の `USB-COM`（`5.1kΩ` `Rd` プルダウン・VBUS 非接続）のままでは、Android が OTG ホストになった瞬間にスマホ内部の PMIC が充電スイッチを切り、逆に 5V を外へ吐き出すモードへ切り替わるため、**「USB-C ケーブル 1 本で Android と通信しながら、CORE-U 側から Android を充電する」ことが物理的にできない**。

もし、ここを突破して次の単一系統構造を実現できれば：

```text
[ 5V 3A AC アダプタ ] ──▶ [ ADX CORE-U ] ──(USB-C 1 本: 5V 充電＋2 ポート通信)──▶ [ Android GOT ]
```

ESP32（スマホとマイコンで別電源が必要）や Arduino UNO / Raspberry Pi Pico（OTG 同時充電不可・10W 駆動不可）のどれもが持ち得ない、**「電源と通信が一貫した 24 時間常設 GOT プラットフォーム」** が完成する。

本資料では、`CH32X035` による自前 USB-PD スタック開発の沼を避け、**市販の 300 円「充電しながら使える Type-C オーディオ変換アダプタ」にも採用されている 8 ピン専用 PD チップ `LDR6028`（LCSC: `C2919629`）** を CORE-U rev5 の `USB-COM` CC ラインへ適用する構想と、採用前に潰すべきリスク・検証手順を整理する。

## 2. 候補 IC：`Legendary LDR6028`（SOP-8）の概要

`LDR6028` は、USB Type-C オーディオ DAC（＝USB 2.0 Device）をスマホへ繋ぎながら、別ポートの 5V アダプタからスマホを同時充電する（中国語で「边充边听」）用途に特化して設計された **USB-C DRP ＋ USB PD 通信コントローラ ASIC** である。  
CORE-U の `CH342K` もオーディオ DAC と同じく純粋な USB 2.0 Device（UFP）であるため、用途構造が 100% 一致する。

### 2.1 主要諸元（LCSC / 公開技術資料ベース）

| 項目 | 仕様・状況 | CORE-U rev5 との親和性 |
| :--- | :--- | :--- |
| **型番 / メーカー** | `LDR6028`（Shenzhen Legendary Technology / 乐得瑞科技） | — |
| **LCSC 型番 / 在庫** | **`C2919629`**（LCSC 在庫あり 約 1,900 pcs ※2026-11 時点） | 試作・小ロット調達可（ただし単独メーカー依存リスクあり） |
| **パッケージ** | **SOP-8**（8 ピン） | 8858 基板へ容易に実装可能 |
| **参考単価（LCSC）** | 1+ pcs: `~$0.45` / 100+ pcs: `~$0.35` 前後目安 | 低コスト |
| **対応プロトコル** | USB PD 2.0（PD 3.0 互換）、**5V PDO 交渉**、**自動 `DR_Swap`（UFP 化）** | **5V 固定のため 9V/20V 降圧 DCDC が不要！** |
| **MCU 負荷・ピン消費** | **完全自律動作（ATtiny1616 ピン消費 0 本・工場書込ゼロ）** | rev5 の空きピン 0 本制約に完全適合 |

### 2.2 ピン配置・機能概要（SOP-8）

```text
          ┌─────────────┐
  VSS  1  │             │  8  VDD     (3.3V〜5.0V 電源)
ResetOut 2│   LDR6028   │  7  PDLDO   (内蔵 PD LDO 出力: 1µF)
  VBEN 3  │   (SOP-8)   │  6  CC1     (USB-COM 側 CC1)
 VDET0 4  │  C2919629   │  5  CC2     (USB-COM 側 CC2)
          └─────────────┘
```

| Pin | 名称 | 種別 | 役割・回路接続の要点 |
| :---: | :--- | :---: | :--- |
| **1** | `VSS` | Power | GND |
| **2** | **`ResetOut`** | Output | **Active-LOW**。下流の USB デバイス（本来は Audio DAC、CORE-U では **`CH342K`**）の電源スイッチ用 P-MOSFET（`AO3401` 等）ゲートを駆動。**`DR_Swap` と VBUS 安定完了後に下流デバイスを起動** するシーケンサ機能。 |
| **3** | **`VBEN`** | Output | **Active-HIGH**。PD 5V 交渉および `DR_Swap` 完了後に外部 VBUS パススイッチを ON にし、スマホ側へ 5V を供給する。 |
| **4** | **`VDET0`** | Input | `USB-PWR`（アダプタ側 5V）の電圧有無を検知する入力。**最大定格が `VDD + 0.3V` のため、5V 入力は必ず抵抗分圧経由で接続すること**。 |
| **5** | `CC2` | I/O | `USB-COM` 側 Type-C コネクタの `CC2` へ接続（最短・対称配線）。 |
| **6** | `CC1` | I/O | `USB-COM` 側 Type-C コネクタの `CC1` へ接続（最短・対称配線）。 |
| **7** | `PDLDO` | Output | 内蔵 PD 通信用 LDO 出力（`1µF` デカップリングコンデンサを近傍配置）。 |
| **8** | `VDD` | Power | チップ電源入力（`3.3V` または `5.0V`）。 |

> **設計前必須確認**：実際の回路図入力前に、LCSC（`C2919629`）の最新公式データシート PDF（Rev V2.8 以降）を入手し、`VDD` 推奨電圧、`VDET0` の分圧比・判定閾値、`VBEN` / `ResetOut` の出力形式（プッシュプル / オープンドレイン）および `CC` ラインの保護・フィルタ定数を必ず一次確認すること。

## 3. CORE-U rev5 への適用回路アーキテクチャ案

```text
  [ 5V 3A AC アダプタ ] ──▶ USB-PWR (Type-C: 5V 常時入力)
                                │
                                ├──▶ 04-LDO (3.3V) ──▶ ATtiny1616 / INA180 / LDR6028 VDD / CH342K VIO
                                ├──▶ 03-eFuse (AP22814) ──▶ 外部 ADX 20P バス (5V / VBUS_EN 制御)
                                │
                                ├──▶ [ 抵抗分圧 ] ──▶ Pin 4: VDET0 (5V アダプタ有無検知)
                                │                            ▲
                                │                     ┌──────┴──────────┐
                                │                     │    LDR6028      │
                                └──▶ [ U_GOT_SW ] ◀───┼─ Pin 3: VBEN    │  ※1A 電流制限＋真の逆流防止(RCB)
                                     (SY6280 /        │                 │    付きロードスイッチ、または双方向 FET
                                      双方向 FET)     │                 │
                                          │           │ Pin 2: ResetOut ├──▶ [ Q_RST: AO3401 ] ──▶ CH342K VDD5
                                          │           │                 │     (DR_Swap 完了後に CH342K を起動!)
                                          │           │ Pin 6,5: CC1/CC2├──┐
                                          ▼           └─────────────────┘  │
                                 ┌─────────────────────────────────────────┴─┐
                                 │        USB-COM (Type-C Receptacle)        │
                                 │  VBUS ← U_GOT_SW  /  CC1,CC2 ← LDR6028    │
                                 │  D+,D- ↔ USBLC6-2SC6 ↔ CH342K             │
                                 └─────────────────────┬─────────────────────┘
                                                       │ USB-C ケーブル 1 本
                                                       ▼
                                  [ Android GOT (5V 充電 ＋ USB Host 2 ポート通信) ]
                                  ※PC 接続時は VBEN=OFF で安全に通常通信できるかを要実機検証
```

### 回路設計上の 3 つの最重要ポイント

1. **`U_GOT_SW`（`VBEN` 駆動の VBUS スイッチ）には「真の逆流防止（RCB）＋ 電流制限」を必須とする**
   - 単一の P-MOSFET（`AO3401` 等）だけでは、FET が OFF でも寄生ボディダイオード経由で **PC 側の VBUS（5V）から CORE-U 側へ電流が逆流** してしまう。
   - **推奨構成**：`SY6280AAC`（Active-HIGH `EN`、抵抗 1 本で 1.0A 等に電流制限可、OFF 時逆流防止、SOT-23-5、約 `$0.08`）や、rev5 既存 BOM と共通の `AP22814AW5-7`（RCB 内蔵・Extended フィー増ゼロ、ただし固定 3A 制限）、あるいは **バックトゥバック（ソース共通対向）P-MOSFET × 2** を使用する。
   - 電流制限を **1.0A（5W）前後** に設定しておけば、Android GOT の画面常時点灯（消費 1.5〜3W）を余裕で維持しながら、万一スマホ側が 2A 以上引いて 5V 3A アダプタごと落ちる事故を防げる。
2. **`ResetOut` による `CH342K` の電源シーケンス制御（`VDD5` / `VIO` 分離）**
   - `CH342K` の **`VDD5`（Pin 4）** を `ResetOut` 駆動の `AO3401` 経由で給電し、**`VIO`（Pin 7）** は CORE-U の `3V3` へ接続する（CH342 データシート §5.2 により `VDD5 = 0V` でも `VIO` からの逆流ゼロ）。
   - これにより **`DR_Swap` 完了後に `CH342K` がクリーンに起動・D+ プルアップ** されるため、セルフパワー接続で起きがちな Android OTG ホットプラグ認識不良（`error -71` 等）も同時に解消できる。
3. **PC 接続時の安全フェイルセーフ（検討オプション）**
   - 実機テストで「PC（特に USB-A → USB-C ケーブル）接続時に `LDR6028` が誤って `VBEN` を上げようとする／認識しない」挙動が万一出た場合に備え、**`VDET0` を GND へ落とすハンダジャンパ／切替手段（GOT 充電機能の無効化）** を試作基板に仕込んでおくと、切り分けが圧倒的に楽になる。

## 5. 採用可否を決める 5 大リスク ＆ 検討課題

基板へ正式採用する前に、以下の 5 点を冷静に評価する必要がある。

1. **【最重要・安全】PC（Windows / Mac / Linux）接続時の安全性と認識性**
   - CORE-U の第 1 の価値は **「AI 開発時に高価な PC を絶対に壊さないこと」**。
   - **デスクトップ PC の USB-A ポート（USB-A → USB-C ケーブル、ケーブル内 `56kΩ Rp` あり・CC 通信不可）** に `USB-PWR` 通電中の CORE-U を挿した際、`LDR6028` が安全に `VBEN = OFF`（VBUS 衝突ゼロ）を維持し、かつ `CH342K` の 2 ポートが正常認識されるかが最大の関門。
   - MacBook や Windows ノート PC の Type-C（DRP）ポートに挿した際、CORE-U から PC へ 5V 充電しようとして接続ループや警告が出ないかも要確認。
2. **Android 機種間の `DR_Swap` 互換性（特に「引き出しの古い格安スマホ」）**
   - `LDR6028` は USB-PD（5V PDO ＋ `DR_Swap`）で動作するため、USB-PD 対応の Android（Pixel / Galaxy / Xperia / Xiaomi 等の主力機）では高い成功率が期待できる一方、**USB-PD 非対応の超低価格・旧世代 Android スマホ** でどう振る舞うか（充電のみになるのか、充電なし OTG へ落ちるのか）を実機確認する必要がある。
   - また、Pixel / Samsung Galaxy は低電流 PDO での `DR_Swap` に厳しい機種があるため、`LDR6028` が広告する 5V PDO 電流値（1.5A / 2A / 3A）とスマホ側の受け入れ挙動を確認する。
3. **5V 3A（15W）アダプタの電力バジェット競合**
   - `USB-PWR` の入力 15W（5V 3A）を、① ADX 外部 20P バス（最大 2.0A / 10W）と ② Android GOT 充電（0.5〜1.5A / 2.5〜7.5W）で分け合うことになる。
   - 充電側を 1.0A（5W）に制限した場合、同時利用時の ADX 外部バス上限は 1.5〜2.0A 程度となり、**「Android GOT 同時充電時の電力配分ガイド」** を仕様書へ明記する必要がある。
4. **単独メーカー品（Legendary）の長期調達・EOL リスク**
   - 同社の上位チップ `LDR6023` が LCSC で欠品しているように、専用中華 PD IC は在庫の波が大きい。量産時には一定数の先行確保、または **「`LDR6028` 未実装（DNP）＋ 0Ω バイパスで通常の `5.1kΩ Rd` 基板としても成立するフォールバック設計」** をパターンに仕込んでおくのが望ましい。
5. **実装配置の選択：CORE-U rev5 本体内蔵 vs 外付けドック／別モデル化**
   - もし実機検証で「PC（USB-A→C）との完全両立に難あり」または「相性によるサポート負荷が重い」と判明した場合、CORE-U rev5 本体は素の `Rd`（PC 絶対保護・`$17`）を死守し、**`LDR6028` 回路だけを切り出した「ADX GOT 充電ブリッジ小基板」または「GOT Edition」** へ分離する退路を持っておく。

## 6. 最速の事前実機検証プロトコル（Go / No-Go 判定）

CORE-U rev5 本体の基板を起こす前に、**数百円〜1,000 円・1 日以内** で白黒をつける。

### 6.1 実験資材
- **方法 A（最速）**：ダイソー等の `LDR6028` 搭載「充電しながら使える Type-C オーディオ変換ケーブル」（内部のオーディオ DAC を外して `D+`/`D-` を手元の `CH342K` 基板へ繋ぐ、またはまずは市販品そのものの PC/スマホ挙動を観察）。
- **方法 B（確実・推奨）**：LCSC から `LDR6028`（`C2919629`）を 5〜10 個取り寄せ、SOP-8 変換基板 ＋ `SY6280`（or 保護抵抗）＋ `AO3401` で最小評価回路を組み、手元の `CORE-D` 等の `CH342K + ATtiny1616` 基板へ接続して実測。

### 6.2 検証チェックリスト ＆ Go / No-Go 基準

| # | テスト項目 | 確認内容 | 必須判定 |
| :---: | :--- | :--- | :---: |
| **1** | **PC 安全性（USB-A → C ケーブル）** | `USB-PWR` 5V 投入状態でデスクトップ PC（USB-A）へ接続。**`USB-COM` VBUS へ 5V 逆流しないこと（テスター実測）**＋ `CH342K` 2 ポート正常認識・UPDI 書込成功。 | **MUST（NG なら本体内蔵見送り）** |
| **2** | **PC 安全性（USB-C → C ノート PC）** | MacBook / Windows ノート PC の Type-C ポートへ接続。接続ループや過電流警告が出ず、2 ポート正常認識・UPDI 書込成功。 | **MUST** |
| **3** | **Android 充電＋通信同時成立** | 手元の複数 Android 端末（Pixel / Galaxy / 古い余剰機など 3 台以上）へ接続。**充電アイコン点灯（充電電流 0.5A 以上実測）と同時に `CH342K` 2 ポート認識・UART 通信＆UPDI リセット成功**。 | **MUST（主力機で安定成立）** |
| **4** | **ホットプラグ＆電源投入順テスト** | ① `USB-PWR` 先入れ→スマホ挿抜 10 回、② スマホ先挿し→`USB-PWR` 後入れ、の双方でフリーズや認識抜けが起きないこと。 | **SHOULD** |
| **5** | **10W 負荷との同時稼働テスト** | Android 充電中に 5V 1.5A 負荷を `VBUS_PROT` 側へ印加し、`3V3` や通信が落ちないこと。 | **SHOULD** |
| **6** | **非 PD 格安スマホのフォールバック確認** | PD 非対応端末を繋いだ際、危険な動作をせず（最悪でも通信のみ or 充電のみに安全フォールバック）壊れないこと。 | **MUST（安全性）** |

- **Go 条件**：#1, #2, #3, #6 をすべてクリア → **CORE-U rev5 へ `LDR6028` 搭載（または DNP 両対応フットプリント）を正式採用**。
- **No-Go 条件**：#1 または #2（PC 安全性・互換性）に懸念が残る、あるいは Android 機種相性が激しい → CORE-U 本体は純粋な `Rd`（PC 絶対保護・`$17`）を維持し、`LDR6028` は外付けブリッジまたは [EAA 構想書](EAA_3_friendly_concept.md) の AOA GOT CARD 案へ切り替える。

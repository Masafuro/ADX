# ADX CORE-U

USB, ATtiny1616, USB 5V2A input

## 構想の概要
ADX CORE-Uはこれまで幾度となく失敗してきた。
しかし、ここまで様々な挑戦によって少しずつなにかを掴みかけてきている気はする。
さて、新CORE-U（開発コード: CORE-UA5）はこれまでのUSB開発型のADX COREボードとしては特に大きな変化があるというわけでもない。しかし、いくつかの微調整から少しずつその構想と意味が明確になってきている。

## 主な仕様
- MCU: ATtiny1616 3V3 10MHz
- USB Pow ONLY: Type-C Input 5V2A
- USB Com Only: Type-C UPDI/Serial 2 Ports
- ADX: ADX FormFactor

## なぜこの構成なのか？
まずArduino UNOとはなにか？という大きな謎、Raspberry pi picoなどの強力で安価なボードが台頭しているのに、依然として、Arduino UNOが市場で一定の存在感を得ているのはなぜなのか。そして、検討の結果、大きなボードサイズと電力供給であると考えた。そして、それはすでにADXフォームファクターにはきっちりと備わっており、Raspberry pi picoと比べても圧倒的に広いボードサイズ、拡張カードまで含めた潤沢な電力供給を実現している。つまり、MCUの能力が低くても、堂々とボードとして成立するのではないか？と考えた。そうでなければArduino UNOはとっくに消滅しているのではないか？（一般的には周辺のエコシステムの力であると説明されるが、深センのエコシステムの製造展開力と合わせて考えるとそれだけでは説明は難しいと考えた。）
そして、ここまで、CH32X035やSTM32C0系をベースとしたUSB開発のCORE-U型ボードを色々と構想したが、最後の一手で、現在のCORE-Uへと至った。
さて、ATtiny1616-MNRとCH342Kの組み合わせではArduino IDEでの開発時に、非常に不思議な感覚があった。すなわち、なにか開発しやすい。そして、RPR4での開発でRaspberry pi picoを使ったことでその差は明らかになった。つまり、CH342KによるArduino IDE上での2ポート切替は、マイコンボードをなんら触ることなく、スケッチ書き込みとデバッグを可能にするからだ。Raspberry pi picoではいつもボードのBOOTSELボタンを押さないといけない。もちろん、RP2040やSTM32系、CH32X系などで、ボタンなしの構想も色々と研究したが、やはり無理が出てしまう。それに比べて、ATtiny1616+CH342Kのコンボは多少値段が張るものの、圧倒的に安定して確実だった。
このことはCORE-Dにおける様々な開発でも明確な利点が感じられる。
そして、これは当初、ちょっと便利だな、くらいに思っていたが、CH32XやSTMなどのボードを開発して戻ってくると、むしろ必須な機能になっていた。
すなわち、ArduinoとADXの違いは、筐体フレンドリーであることだ。そして、そのことが開発UXをまったく異なるものにしている。
例えば、Raspberry pi picoベースのADXボード（これは架空のCORE-RPと呼ぶことにする。）を考えてみよう。この時、CORE-RPはユニットに納められ、どこかに据付される。さて、スケッチを書き替えないといけない。どうする？片手にノートPCを持っている。ケーブルを挿抜しながら、BOOTSELボタンを押すのか？ボタンはどうやって？安価なタクトスイッチでは、ルーターのリセットボタンのような鋭いピンが必要になる。ルーターのリセットならまだしも、スケッチ書き込み時に毎回それをやるのか？そして、リセットは？またリセットスイッチが必要になる。ケーブル挿抜でもよいが、またそれをノートPC片手にやるのか？ということになる。
そして、この問題を完全に確実に解決できる方法がATtiny1616+CH342Kだった、ということになる。ある意味で再発見とも言えるだろう。CORE-Uでは、電源のUSBケーブルは挿入したまま、デバッグ用のUSBケーブルをつなぐと、後はスケッチ書き込みはCOMポート1、Serial.printはCOMポート2というようにPC側で完全に切替でき、また、スケッチ書き込み時のリセットもCOMポート1経由のUPDIでスケッチがハングしていても確実に実行される。

## そういうわけで。
そういうわけで、CORE-Uに戻ってきたわけだ。ATtiny1616+CH342Kのコストアップはもはや必須であり、別の経路を通っても結局、現場で押しやすい大型スイッチでコスト高になる。そして、ADX規格をフルに利用できる5V/2AをTYPE-CのACアダプターからきっちり引き出せるようにした。

## 雑感
そういうわけでUSBはCORE-Uにしてきっちり作り、Arduino UNO R4 Minimaへの対抗を目指す。元々あった、CORE-A5は一旦、Archive行とし、CORE-A24、すなわちDC24V対応版を構想中である。

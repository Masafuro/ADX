# ADX CORE-U 比較分析・設計思想 (Competitive Analysis & Design Philosophy)
〜 Arduino UNO R3 / R4 Minima との対比から見る「はたらくArduino」の必然性 〜

---

## 1. はじめに：「机の上の学習」から「現場で動かす実用機」へ

Arduino は、世界中のメイカーや学生、エンジニアに「マイコンを動かす楽しさ」を教えてくれた最高のプラットフォームです。  
しかし、机の上のブレッドボードで動いたプロトタイプを、いざ「現場の箱（配電盤、ガレージ、カスタムケース、設備）」へ連れ出そうとしたとき、多くの開発者が共通の壁に直面します。

- **「スケッチがバグでハングすると、USB認識が外れてPCから書き込めなくなる」**
- **「ケースに収めたらリセットボタンやBOOTボタンが押せない」**
- **「シリアルモニタを開いていると書き込みエラーになる」**
- **「モーターやLEDテープを動かすと電源容量が足りずマイコンが落ちる」**
- **「振動でジャンパ線が抜ける」**

**ADX CORE-U** は、これらの「机の上から現場へ移行する際に生じる摩擦」を解消するために設計された、**現場で使える「はたらくArduino（The Working Arduino）」** です。  
本稿では、世界的スタンダードである **Arduino UNO R3** および **Arduino UNO R4 Minima** との工学的な対比を通じて、CORE-U が選択した設計思想とそのトレードオフを解説します。

## 3. 5つの核心的な設計思想と工学的アプローチ

### 3.1 ハング耐性と独立USBブリッジ：MCUが暴走してもPCから見失わない
近年のモダンマイコン（UNO R4 Minima や RP2040、ESP32-S3 等）は、MCU 内部の USB ペリフェラルを用いたソフトウェアブートローダに依存する構成が主流です。  
これは部品点数を減らせるメリットがある反面、**「スケッチ内で割り込み禁止（CLI）のまま無限ループに入った」「メモリ破壊でUSBスタックがクラッシュした」** 瞬間に PC 側の COM ポートが消失し、物理的なリセットボタンの二度押し（DFUモード移行）やBOOTSEL操作を強いられます。

CORE-U は、UNO R3 が持っていた「独立 USB ブリッジの安心感」をさらに進化させ、**独立したハードウェア USB ブリッジ IC（CH342K）** を採用しました。
- MCU がどれほど激しく暴走・ハングしていても、PC との USB 接続は常に物理的に維持されます。
- 書き込みは専用の **ハードウェア UPDI（Port 0）** 経由で行われるため、MCU を外部から強制的にデバッグモードへ引き込み、物理ボタンを一切触ることなく確実にファームウェアを再書き込みできます。

### 3.2 開発体験の革新：シリアルモニタを開いたまま瞬時に書き込める
Arduino 開発において、最も頻繁に発生するストレスが「書き込み時のシリアルポート競合エラー」です。  
1 ポート構成のボードでは、スケッチを書き込むたびにシリアルモニタを閉じ、書き込み後に再びモニタを開き直す必要がありました。

CORE-U は、CH342K による **完全独立した 2 つの CDC シリアルポート** を 1 本の Type-C ケーブルで提供します：
- **COM Port A (Port 0):** SerialUPDI スケッチ書き込み専用
- **COM Port B (Port 1):** `Serial.swap(1)` 常時デバッグモニタ専用

Arduino IDE 1.8.x（クラシック版）と組み合わせることで、**シリアルモニタの別ウィンドウを開いてリアルタイムログを眺めたまま、一度もモニタを閉じることなく何度でもスケッチ書き換えが可能** です。再接続の待機時間やポートの掴み損ねによるフリーズが根本から解消されます。

### 3.3 電源アーキテクチャ：デュアル Type-C と 5V 2.0A 給電自律保護
従来のボードでは、PC の USB ポートから給電される 500mA 程度が限界であり、小型リレーや LED テープ、センサーを複数接続すると容易に電圧降下（ブラウンアウト）が発生して MCU がリセットを繰り返す原因となっていました。

CORE-U は **「電源専用ポート（USB-PWR）」と「通信専用ポート（USB-COM）」を物理的に独立** させています：
- **USB-PWR:** ACアダプタやモバイルバッテリーから最大 5.0V / 2.0A（10W）を受電。パワースイッチ IC（AP22814A）を経由して ADX 20P バスおよび外部 LED ポート（CN2）へ十分な電力を供給。
- **自律保護:** パワースイッチの過電流フラグ（FLG）はマイコンの `PA7` に接続されており、過電流トリップ時に高速（ナノ秒オーダー）で回路を保護するハードウェア自律インターロックを構成可能。
- **現場での安全性:** 現場で主電源（USB-PWR）を入れたまま、ノートPC（USB-COM）を安全に抜き差しできます。PC を切り離してもシステム全体の動作は継続します。

### 3.4 筐体フレンドリー：密閉ケース内でも「音と光」で状態がわかる
「ケースに収めてネジを締めた後」の運用性を徹底的に考慮しています：
- **物理ボタンの全廃:** リセットスイッチや押しボタンを基板上に一切配置していません。現場のケースに「スイッチ用の穴」を開ける必要がありません。
- **Neopixel RGB LED (`PB4`):** わずか 1 ピンで緑（稼働中）、青（通信中）、橙（書き込み中）、赤（エラー）など、状況をケースの隙間やアクリル窓越しに一目で伝えます。
- **パッシブ圧電サウンダー (`PB5`):** 密閉された制御盤やケースの奥深くにあっても、電源投入時の「ピピッ」、書き込み完了の「ピロリ♪」、過電流トリップ時の「ピー」といったビープ音を耳で確実に確認できます。

### 3.5 接続性：緩いピンソケットから「耐振IDC・XH・HY2.0」へ
Arduino UNO のメスピンソケットは手軽な反面、振動や経年劣化で接触不良を起こしやすく、引っ張られたジャンパ線が抜けてショート事故を引き起こすリスクがありました。

CORE-U は、すべての外部接続にロック機構やガイドを持つコネクタを採用しています：
- **ADX 20P IDC ヘッダ:** リレーや通信 CARD を強固にスタックする耐振コネクタ。
- **CN2 (JST XH 4P):** LED テープ等の大電流 5V 配線用。定格 3A で、4線式高信頼 LED（WS2813/WS2815）のバックアップライン（BI）直結にも標準対応。
- **U1 (HY2.0 4P):** M5Stack や Grove とピン互換の 3.3V 外部センサ・サーボ直結ポート。

## 4. トレードオフの開示（CORE-U が選ばなかったもの）

エンジニアリングにおいて、すべての要求を満たす「完璧な万能基板」は存在しません。CORE-U もまた、現場でのタフネスと実用性を最優先するため、いくつかの要素を明確に割り切っています。

| 割り切った要素 | 選択した仕様 | 工学的理由（トレードオフの背景） |
| :--- | :--- | :--- |
| **CPU 速度競争** | 8-bit AVR 10MHz (3.3V) | 3.3V LVCMOS ネイティブ駆動において最も安全動作マージンが広く、密閉ケース内でも自己発熱が極小で熱暴走しないため。 |
| **巨大な RAM 容量** | 2KB SRAM / 16KB Flash | 制御・ロジック・シーケンス処理に必要十分なサイズに絞り、チップコストと消費電力を極小化するため。 |
| **WiFi / Bluetooth 内蔵** | あえて非搭載 (有線直結) | 電波遮蔽される金属ケース内での動作不良を防ぎ、電波認証コストや予期せぬ通信切断トラブルを排除するため。 |
| **多ピン引き出し** | 厳選された 20P IDC ＋ 外部 2 ポート | 基板面積（87×48mm）の小型化を維持しつつ、配線密度を下げて製造歩留まりと耐ノイズ性を高めるため。 |

## 5. まとめ

```text
［ Arduino UNO R3 / R4 Minima ］        ［ ADX CORE-U ］
  机の上の学習・実験・プロトタイプ   ──▶   現場のリアルな箱へ連れ出す実用機
  （手軽さ・オープンなピンソケット）         （耐振スタック・ハング耐性・音と光のUI）
```

Arduino UNO でアイデアを素早く検証し、動くコードが完成したら、それをそのまま **ADX CORE-U** に載せ替えて現場のケースに組み込む。  
これが、ADX プロジェクトが提案する **「はたらくArduino」** のあるべき姿です。

# ADX CORE-U：AI フレンドリー・マイコンボード構想
〜 **「AI で書かせて、AI で動かす」第 4 世代マイコンボード** 〜

> **「自分でコードを書いて L チカさせた感動」から、「AI が L チカさせた感動」への転移。**
> **No Arduino IDE. No BOOTSEL Button. Built for AI Agents.**

- **作成日**: 2026-11-26
- **位置づけ**: [concept_20261126.md](concept_20261126.md)（ニッチ未発見問題）および [2026-11-26_craftsmanship_is_not_an_optimization_problem.md](../../memo/99_SMOKINGROOM/2026-11-26_craftsmanship_is_not_an_optimization_problem.md) の哲学的ブレイクスルーを受けて再定義した、ADX CORE-U の新コア構想書。
- **前提方針**: EasyEDA SPARK 等の外部締め切りはオミットし、単なる仕様最適化ではなく**「生態系の中で唯一無二の種として生き残る（How to survive?）」**ための本質的価値とキラーコンテンツ（UX・ソフトウェア・体験込み）の構築に集中する。

## 1. 哲学的ブレイクスルー：「計算力強化」は本当に必要なのか？

### 1.1 2005 年の問いは終了した
2005 年に誕生した Arduino が世界を変えた理由は、当時最大の壁だった **「コードを書いてマイコンを動かすこと自体」** を民主化した点にある。

しかし 2026 年現在、**AI（LLM / コーディングエージェント）が数秒で実用的なコードを書ける時代**になった。Arduino が解いた問題はすでに「終了」しつつあり、手打ちコーディングを前提とした既存の教育・開発エコシステムにも限界が迫っている。

### 1.2 「大脳」と「脊髄」の分離
Arduino UNO R4（RA4M1）、Raspberry Pi Pico（RP2040/2350）、ESP32、CH32V 系 RISC-V など、既存のマイコンボードはこぞって **クロック・RAM・多機能・無線通信の強化** へ走ってきた。それは「ボード単体に知能（小さなパソコン）を詰め込む」発想の延長線上にある。

だが、AI 時代における最も根本的な問いはこうだ：

> **「ホスト PC / AI エージェント側に無限の計算力があるのに、末端のマイコンボードにまで計算力競争は本当に必要なのか？」**

既存のマイコンボードは「小さなパソコン（大脳）」を目指した代償として、**物理世界と接するハードウェアにとって最も重要な性質**を構造的に失ってしまった。

- 内蔵 USB や複雑な OS / スタック依存による **「暴走時の復帰不能（物理 BOOTSEL / リセットボタン必須）」**
- 複雑な 32-bit SDK・Strapping pin・発熱・無線アンテナ制約という **「ブラックボックス化と筐体不適合」**
- 手軽な USB 1 本給電ゆえの **「負荷駆動時の電圧降下とホスト PC 破損リスク」**

AI 時代において、物理世界側に必要なのは中途半端な「小さなパソコン」ではない。
**大脳（AI / PC）の指示を確実に物理世界へ伝え、大脳がどんな失敗をしても絶対に文鎮化せず・PC を壊さず・物理操作ゼロで 100% 従順に動き続ける『脊髄（Spinal Cord）』** である。

## 2. CORE-U の UX とは何か：「AI が L チカさせた」感動への転移

### 2.1 原体験のシフト（`My First Blink` → `AI's First Blink`）
かつて世界中の何千万人もの人が Arduino の最初の「L チカ（Blink）」に震えたのは、LED が点滅すること自体が便利だったからではない。**「画面の中に書いた自分の言葉（コード）が、初めて物理世界を動かした」** という魔法の原体験に心を撃ち抜かれたからだ。

2026 年、画面の中で AI が文章やコードや画像を生成することには、もはや誰もが慣れ始めた。
いま、次に世界を震わせる新しい原体験――それこそが **CORE-U の UX の本質** である。

> **画面の中に閉じ込められていた AI に向かって一言語りかけた瞬間、AI が画面の壁を突き破り、目の前の物理世界の LED を自分の手（基板への物理接触）ゼロでチカッと光らせる。**
> **「コードを書いて L チカさせた感動」から、「AI が L チカさせた感動（AI's First Blink）」への転移。**

### 2.2 CORE-U の 3 段階 UX ジャーニー
CORE-U の UX は、箱を開けた最初の 60 秒から、そのまま現実世界の装置・産業システムへ一直線に伸びるよう設計されている。

1. **Stage 1：箱出し 60 秒の魔法（追加パーツゼロ × オンボード 3 色 LED）**
   - 拡張 CARD を 1 枚も挿さない本体単体の状態で USB を接続。
   - 工場出荷の AI 直接操作モード（B パターン）により、Antigravity へ「赤・黄・白の LED をホタルみたいにゆっくり光らせて」「SOS のモールス信号にして」と入力した瞬間、**コンパイル待ち 0 秒・基板への接触ゼロで目の前の物理 LED が生き物のように光り出す**。
   - これまで単なるステータス表示だったオンボード 3 色 LED（赤・黄・白）が、**「AI's First Blink」を箱出し 1 分で完結させる最初の物理インターフェース**になる。
2. **Stage 2：5 分後の覚醒（自律ファーム化 ＆ 無人自己修復 ＆ ケーブル解放）**
   - 「気に入ったから、PC を抜いても単体で動き続けるようにして」と言えば、AI がコード生成 → 1 秒ビルド → UPDI 自動焼込（A パターン）を実行。
   - わざとバグや無限ループを仕込んでも、人間がリセットボタンを押すことなく AI 自身が UPDI から 2 秒で復旧する。
   - `USB-COM` ケーブルをスッと抜いても、机の上で 5V 2A 電源のまま動き続ける。
3. **Stage 3：物理世界への拡張（10W CARD × 8858 筐体 × CORE-A 接続）**
   - L チカという最初の魔法の先に、ADX 20P IDC 経由で 10W 級のモーター・ヒーター・センサー CARD を接続。
   - AI と対話しながら 8858 規格の 3D プリント筐体へ収めて「壊れない本物の装置」を完成させ、さらに同じ作法・同じ MCU・同じバス規格のまま過酷現場の `CORE-A` へシームレスに到達できる。

## 3. ポジショニング：マイコン開発ボードの世代交代

CORE-U は **「Arduino IDE と決別する」**。
VS Code および Antigravity 等の AI エージェントから完全にハック・直接制御できる、**第 4 世代のマイコンボード**として既存エコシステムの前提を破壊する。

| 世代 | 開発スタイル | 代表プラットフォーム | 開発環境 | 最初の感動（UX） | AI 完全自律を阻む構造的限界 |
| :---: | :--- | :--- | :--- | :--- | :--- |
| **第 1 世代** | 人間が C/C++ を手打ち | Arduino UNO | Arduino IDE | コードを書いて L チカ | 1 ポート競合・USB 給電依存・IDE 前提 |
| **第 2 世代** | 人間がブロックを並べる | M5Stack / micro:bit | UIFlow / MakeCode | ブロックで L チカ | 人間向け GUI 投資・ESP32 の発熱と重さ |
| **第 3 世代** | 人間が Python / C を書く | Raspberry Pi Pico | Thonny / UF2 (DFU) | 安価に高速動作 | DFU は強いが、**暴走時に物理 BOOTSEL 必須** |
| **第 4 世代** | **AI に書かせて・直接操作させる** | **ADX CORE-U** | **VS Code / Antigravity (CLI & MCP)** | **AI が L チカさせた** | **なし（物理ボタンゼロ強制復旧・PC 保護・1 秒書込）** |

## 4. コア技術構成：「A パターン × B パターン」の完全両立

スーパーファミコンという異質なハードウェアを、同時発売の『スーパーマリオワールド』が 1 秒で世界に証明したように、CORE-U はハードウェア単体ではなく **「A / B 両立ソフトウェア層」** を狂気の完成度で同時リリースする。

```text
                ┌──────────────────────────────────────────────┐
                │   Host PC : VS Code / Antigravity (AI 大脳)  │
                └──────────────┬────────────────┬──────────────┘
                               │                │
         [ A パターン: CLI / UPDI ]       [ B パターン: MCP / AI-Firmata ]
         コード生成 → 1秒ビルド            コンパイル待ち 0 秒で直接操作
         → 強制焼込 → 暴走時自己修復        (LED/GPIO/PWM/ADC/I2C/SPI/電源診断)
                               │                │
                               ▼                ▼
                      ┌──────────────────────────────────┐
                      │  USB-COM (VBUS 物理分離・PC保護)  │
                      │       WCH CH342K (Dual CDC)      │
                      │   Port 0: UPDI  │  Port 1: UART  │
                      └────────┬────────┴───────┬────────┘
                               ▼                ▼
                      ┌──────────────────────────────────┐
                      │      ATtiny1616-MNR (脊髄)       │
                      │  ・オンボード赤/黄/白 LED 直結    │
                      │  ・B ⇄ A を AI が 2 秒で自在往復  │
                      │  ・USB-COM 抜去後は単体自律稼働   │
                      └────────────────┬─────────────────┘
                                       ▼
          [ USB-PWR (5V 2A / 10W) ] ─▶ eFuse (AP22814 + FLG) ─▶ ADX 20P IDC (CARD)
```

### 4.1 B パターン：AI 直接操作モード（AI-Firmata / MCP・工場出荷標準）
往年の Firmata を **AI エージェント専用 API（MCP / CLI）** として現代的に再設計し、工場出荷時の標準ファームウェアとして搭載する。

- **コンパイル時間 0 秒の即応体験**: 箱から出して USB を挿した瞬間から、Antigravity が `Port 1 (UART)` 経由で直接ハードウェアを操作できる。
  - 例：「赤と白の LED を交互に光らせて」「I2C バスをスキャンして繋がっているセンサーを読んで」「P02 から 1kHz の PWM を出して」「eFuse の異常フラグと電源電圧を確認して」
- **ATtiny1616 に最適化した極小プロトコル**: 歴史的負債を排した軽量コマンド体系により、Flash 3〜5KB / SRAM 数百バイト程度で軽快に動作。リッチな JSON スキーマや自然言語インターフェースはホスト側の MCP サーバー／CLI が担う。

### 4.2 A パターン：AI 自律開発・強制焼込モード（VS Code / Antigravity Native）
Arduino IDE を廃し、VS Code と Antigravity から CLI（`avr-gcc` / `arduino-cli` / `pymcuprog` ラッパー）経由で完全に自動駆動する開発ループ。

- **物理ボタンゼロの完全無人ループ**: AI がコード生成 → 1〜2 秒でビルド → `Port 0 (SerialUPDI)` から強制書き込み → `Port 1 (UART)` でシリアルログを自動観測・検証。
- **自己修復（文鎮化ゼロ）**: AI がバグったコードや無限ループを書き込んでマイコンが暴走しても、人間が基板に触れることなく AI 自身が `Port 0 (UPDI)` から 2 秒で強制上書き復旧できる。
- **スタンドアロンへの解放**: テストが完了したら `USB-COM` を引っこ抜くだけで、そのまま `USB-PWR`（5V 2A）駆動の独立装置として 8858 筐体の中で稼働し続ける。

### 4.3 最大のキラー体験：「B ⇄ A」を AI が 2 秒で自在に往復できる
1. **B パターン** で対話的に「AI's First Blink」やセンサー確認・アクチュエータ実験・デバッグを行う。
2. 動きが決まったら **A パターン** で高速制御・スタンドアロン用ファームウェアを AI に生成させ、`Port 0` から焼き込む。
3. 別の実験に戻したくなったり、暴走したりしたら、AI に一言伝えるだけで **`Port 0 (UPDI)` から 2 秒で B パターン（AI-Firmata）へ焼き戻せる**。

この「対話的探索（B）」と「自律ファーム実行（A）」のシームレスかつ完全無人の往復は、物理 BOOTSEL や 1 ポート共有に縛られる RP2040 / Arduino / ESP32 には構造的に再現できない。

## 5. なぜ CORE-U（rev4）のハードウェア仕様が 100% 必然になるのか

これまで単体ボードとしては「弱み」や「使いにくさ」に見えていた CORE-U（[spec_proposal.md](spec_proposal.md)）のすべての設計判断が、「AI フレンドリー・脊髄ボード」という文脈のもとで完全な強みに反転する。

| ハードウェア仕様 | 従来の汎用ボード視点（弱み・謎） | AI フレンドリー脊髄ボード視点（100% の必然） |
| :--- | :--- | :--- |
| **`ATtiny1616-MNR`** (8-bit / 16KB / 2KB) | Pico や ESP32 に比べて非力で割高 | 計算は大脳（AI/PC）が担う。極小・決定論的・1 秒ビルドで、**AI がデータシート全体を把握してハルシネーションゼロで書き切れる透明性** |
| **`CH342K`** (UPDI / UART 独立 2 ポート) | 部品コスト増 | **A（神の権限 UPDI）と B/監視（UART）の物理分離**。物理ボタンゼロの完全無人ループと自己修復を実現する心臓部 |
| **オンボード 3 色 LED**（赤・黄・白） | 最低限のエラー表示に過ぎない | **箱出し 60 秒・追加パーツゼロで「AI が L チカさせた（AI's First Blink）」感動を完結させる最初の物理インターフェース** |
| **デュアル Type-C** (`USB-PWR` / `USB-COM` 分離) ＋ **`AP22814`** eFuse ＋ `FLG` | USB が 2 本で UNO より使いにくい | **AI が暴走出力や過負荷を起こしてもホスト PC が絶対に燃えない物理安全構造**。さらに `FLG` でハードウェア異常を AI に即座にフィードバック |
| **5V 2A（10W）独立電源** | 使い道がぼやけている | PC の 500mA 制限を離れ、AI の指示を実社会の負荷（モーター・リレー・LED・ヒーター等）として力強く動かす筋力 |
| **`8858` 固定寸法** ＋ 低発熱 ＋ 無線なし ＋ ボタンレス | 模型などには大きい・Wi-Fi がない | **AI が OpenSCAD 等で 3D プリント筐体を自動生成して一発で収まる定型規格**。PLA が熱で溶けず、電波も死なず、ボタン用の穴も不要 |
| **`ADX 20P IDC`** 一本化 | 単体で直結できない | ジャンパ線の接触不良ゼロ。拡張 CARD との確実な結合。そして**同じ規格・同じ MCU のまま過酷現場の `CORE-A` へ直結** |

### 5.1 ハードウェア（rev4）への小改良検討：電源電圧の「AI の目」追加
現行 rev4 では余剰 GPIO が 4 本（`PA4`, `PA5`, `PB4`, `PB5`）あり、オンボード 3 色 LED（赤・黄・白）に 3 本を割り当てると **1 本のピンが余る**。
この余剰 1 ピン（ADC 対応の `PA4` または `PA5`）に **`VBUS_PROT` の抵抗分圧（抵抗 2 本のみ）** を接続しておけば、実質コストゼロで以下の能力が標準装備される。

- B パターン（AI-Firmata）および A パターンにおいて、AI が `get_power_status()` で **「現在の 5V 電源電圧（ドロップ有無）＋ eFuse 異常フラグ (`PA7/FLG`)」を自力で計測・診断** できる。

## 6. PV（プロモーション）およびローンチ構成案

「AI で書かせて動かすマイコンボード」の価値は、スペック表ではなく **60 秒の映像（PV）** で一撃で伝わる。

### 6.1 60 秒 PV ストーリーボード案
1. **掴み：AI's First Blink（0:00–0:15）**:
   - 机の上に置かれた CORE-U（8858 筐体入り）。人間の手はキーボードの上だけ（基板に一切触れない）。
   - Antigravity に一言打ち込む：「赤・黄・白の LED を、呼吸するようにゆっくり点滅させて」。
   - コンパイル待ち 0 秒、B パターン（AI-Firmata）で目の前の 3 色 LED が即座に滑らかに光り出す。**「画面の中の AI が、初めて現実世界を光らせた」瞬間。**
2. **10W 拡張・直接観測（0:15–0:28）**:
   - 20P IDC で繋いだ負荷・センサーを AI が B パターンで即座にスキャン・駆動（例：「温度を読んで閾値を超えたらファンをテストして」）。
3. **A パターン＆無人自己修復の実証（0:28–0:45）**:
   - 「単体で動くファームウェアにして書き込んで。わざと無限ループでハングさせても復旧できるか試して」→ AI が生成・1 秒ビルド・UPDI 自動書込 → 意図的フリーズ → **物理ボタンに一切触れず、AI が UPDI で 2 秒で強制復旧＆上書き完了**。
4. **スタンドアロン解放（0:45–0:55）**:
   - `USB-COM` ケーブルをスッと抜去。それでも 5V 2A の `USB-PWR` だけで 8858 筐体入りの装置がそのまま動き続ける。
5. **エンディング（0:55–1:00）**:
   - テロップ：**「AI's First Blink. No Arduino IDE. No BOOTSEL Button. — ADX CORE-U」**。

### 6.2 同時ローンチ（スーパーマリオワールド）を構成する 4 点セット
CORE-U 本体を裸で出すのではなく、以下を 1 つの体験パッケージとして同時にねじ込む。

1. **本体ハードウェア**: `ADX CORE-U (rev4)`（オンボード 3 色 LED ＋ VBUS 分圧監視の追加を検討）
2. **AI ソフトウェア層（キラーエンジン）**:
   - 工場出荷標準ファーム：**`ADX AI-Firmata`**（B パターン）
   - ホスト側ツール：**`adx-cli` ＆ `adx-mcp`（＋ Antigravity Skill / VS Code テンプレート）**（A パターン自動ビルド・UPDI 書込・Port 1 監視・B モード復旧）
3. **最初のキラー拡張 CARD（検討中）**:
   - L チカの次のステップとして、20P IDC の先で「5V 2A の目に見える物理パワー」と「電流・電圧・センサー観測（Observability）」を体感させる最初の 1 枚（例：AI 実験・電流監視サンドボックス CARD、または 10W アクチュエータ／温調 CARD）。
4. **AI 生成フレンドリー筐体テンプレート**:
   - 8858 規格のパラメトリック OpenSCAD / STEP ベースデータ（AI がユーザー要望に合わせて 3D プリントケースを即座にカスタム出力できる）。

## 7. Post-AI 時代の教育・産業エコシステムへの接続

この構想は、単なるホビー・開発者向けガジェットにとどまらず、**AI 時代の新しい教育** と **ADX 本丸の産業領域（CORE-A）** を一直線に結ぶ。

- **AI 時代の「新しい工学教育」**:
  手打ちコード試験が崩壊したあと、高専・大学・企業研修が本当に教えるべき「物理現象の観測・原因切り分け・安全設計（電源分離／保護）・電×ソ×メカ統合・AI との協業検証」を、**壊れない・PC を守る・摩擦ゼロの教材**として体現できる。
- **CORE-A へのシームレスな昇格**:
  机上で CORE-U を使って AI と一緒に開発・検証した設計資産（ATtiny1616 コード、`ADX_P01`〜`P10` バス、CARD 基板、8858 筐体）は、そのまま **過酷環境・耐熱・絶縁 RS-485 の産業用エッジ（`CORE-A`）** へ連続的に移行できる。

## 8. Next Steps（構想から実装へ）

# ADX CORE-U (rev6) ディープスリープ機能の可能性とアーキテクチャ考察

〜 **「無線を捨て、有線とハード遮断を極めた」からこそ成立する、“耳だけ開けて深く眠る”組込エッジノード** 〜

- **作成日**: 2026-11-28
- **対象ボード**: ADX CORE-U (rev6)（[spec.md](spec.md) v0.3 準拠）
- **参照データシート**: Microchip `ATtiny1616` (§10, §11, §16.3, §24.3.2.7, §33.3.9, Table 37-5) / TI `TPS70933` *(旧案 `TLV75533` から高耐圧化)* / 3PEAK `TP181A2` / TI `SN74LV4066A`

## 1. エグゼクティブ・サマリー：ESP32 のディープスリープが抱えるジレンマとの決別

屋外・遠隔地の組込システムでは、消費電力と自己発熱を抑えるために ESP32 等のディープスリープがよく使われる。しかし、現場のエンジニアは必ず次の **「無線ディープスリープの壁」** に悩まされる：

- **寝ると無線（Wi-Fi / BLE）が完全に死ぬ**：外部から「今すぐ状態を見たい」「設定を変えたい」と思っても、次の定期起床（10 分後・1 時間後）まで待つしかない。
- **現場で起こすには物理ボタン（リセット）が必要**：密閉防水ケースや 3D プリント筐体にボタン穴を開けざるを得ず、しかもリセット起床のため **SRAM の状態が毎回すべて揮発する**。
- **起床時の電流スパイクと再接続コストが重い**：Wi-Fi 再接続に数秒＋200〜400 mA の大電流スパイクが発生し、低温時のバッテリ電圧降下や接続失敗による電池浪費を招く。

これに対し、**CORE-U (rev6)** は以下の 3 要素が組み合わさったことで、ESP32 とはまったく異質の **「深く眠りながら、外部からいつでも・ボタンレスで・数十 µs で・SRAM を保持したまま起こせる」** という強力なディープスリープ・アーキテクチャを副産物ゼロ・追加コストゼロで手に入れた：

1. **MOSFET 3 個による `CH342K` 0mW 完全遮断 ＋ `PB5 (ADX_USB_COM_DET)` 割込**：普段は USB ブリッジを完全無通電にしておきながら、**`USB-COM` ケーブルを挿す物理アクションだけで `CH342K` と Power-Down 中の MCU を同時に叩き起こせる**。
2. **`ADX-BUS-SPEC-v5.0` でバス側へ引き出した `PA2 (ADX_RX)`**：有線フィールドバス（RS-485 / LIN）の受信線に完全非同期割込 (`Px2`) と `USART0` スタートフレーム検知 (`SFDEN`) が直結しているため、**無線のように耳を塞がず「有線の耳だけ開けて眠る」** ことができる。
3. **ATtiny1616 ネイティブの SleepWalking ＆ UPDI スリープ独立性**：CPU を寝かせたまま ADC 監視ができ、万一バグで永久スリープしても `USB-COM` 経由の UPDI で物理ボタンなしに必ず復旧できる。

## 2. ESP32 vs CORE-U (rev6) ディープスリープ比較

| 比較項目 | ESP32 系（一般的屋外 IoT 構成） | **ADX CORE-U (rev6)** |
| :--- | :--- | :--- |
| **スリープ中の通信待受** | ✗ Wi-Fi / BLE は完全停止（耳が塞がる）<br>*(Modem-sleep は数十 mA 消費)* | **◎ 有線（RS-485 / LIN / I2C）で「耳だけ開けて」µA〜数 mA 級待機が可能** |
| **現場での即時保守・起床** | △ 次の定期起床待ち、または物理リセットボタン必須 | **◎ `USB-COM`（PC / Android GOT）を挿すだけで µs 即起床（ボタン不要）** |
| **保守終了後の復帰** | △ スイッチ戻し忘れ・タイムアウト待ち | **◎ ケーブルを抜くと `PB5 (BOTHEDGES)` が自動検知して元のスリープへ復帰** |
| **起床時の RAM 保持** | ✗ 原則リセット起動（RTC SRAM 以外すべて揮発） | **◎ 全 SRAM (2KB)・全レジスタ完全保持のまま中断箇所の次行から再開** |
| **起床所要時間** | 数百 ms 〜 数秒（ブート＋Wi-Fi 再接続） | **数十 µs**（内蔵 RC 発振器起動のみ。USB 列挙完了前に MCU は待機完了） |
| **起床時の突入電流** | 200 〜 400 mA スパイク（寒冷地バッテリに厳しい） | **約 3〜5 mA**（10MHz / 3.3V、電源電圧降下ゼロ） |
| **誤スリープ（ブリック）復旧** | 物理 `BOOT` + `EN` ボタン操作が必要 | **◎ `USB-COM` 接続 → `CH342K` Port 0 (UPDI) がスリープ中でもハード強制介入** |
| **温度耐性（屋外・車載）** | 民生部品・大発熱により高温密閉に弱い | **◎ Mode 1 理論仕様 `-40℃ 〜 +85℃`**（スリープ時は自己発熱がさらに極小化） |

## 3. CORE-U (rev6) が持つ「6 つの起床経路（Wake-up Architecture）」

ATtiny1616 のスリープは主に **Power-Down**（全クロック停止、`0.1 µA` Typ）と **Standby**（選択ペリフェラルのみ自律稼働、`0.71 µA`〜）の 2 階層があり、CORE-U rev6 では以下の **6 経路すべて** を用途に応じて自由に組み合わせられる。

### ① `USB-COM` ケーブル挿抜起床（`PB5`: `ADX_USB_COM_DET`）
- **対応スリープ**: **Power-Down** / Standby（`PORTB.PIN5CTRL = PORT_ISC_BOTHEDGES_gc`）
- **仕組み**: `USB-COM` 挿入で `Q1/Q2/Q3` が動作し、`CH342K` へ 3.3V 通電すると同時に `USB_COM_EN` が `0V → 3.3V` へ立ち上がる。一般ピン `PB5` でも `BOTHEDGES` 設定ならメインクロック停止中の Power-Down から確実にシステムを起こせる（Table 16-4）。
- **双方向イベント**: 挿した瞬間（`LOW → HIGH`）だけでなく、抜いた瞬間（`HIGH → LOW`）も同じ `PB5` 割込で捕捉できる。

### ② 有線フィールドバス（RS-485 / LIN）からの即時起床（`PA2`: `P05 / ADX_RX`）
`ADX-BUS-SPEC-v5.0` で `PA2` を IDC バス側へ移した最大の副産物の一つ。2 通りの起床方式を選べる：
- **Power-Down からのエッジ起床**：`PA2` は **完全非同期ピン (`Px2`)** であるため、RS-485 / LIN バスに Break やスタートビット（立ち下がり）が届いた瞬間に `0.1 µA` の Power-Down から即座に目覚める（マスターが最初にウェイクアップ Break やダミーバイトを送るプロトコルと相性抜群）。
- **Standby からの `USART0` スタートフレーム検知（`SFDEN`）**：Standby スリープ中に `USART0.CTRLB.SFDEN = 1` を有効にしておくと、**スタートビット検知でハードウェアが OSC20M を自動起動し、1 バイト目のデータを取りこぼさずに受信しながら起床** できる（§24.3.2.7）。さらに `LINAUTO` と組み合わせれば、Break + `0x55` で温度ドリフト補正と一斉起床を同時に完了できる。

### ③ 拡張バス I2C スレーブアドレス一致起床（`PB0`/`PB1`: `P06`/`P07`）
- **対応スリープ**: **Power-Down** / Standby（`TWI0` ハードウェアアドレスマッチ機能）
- **仕組み**: 上位ホスト（例：Raspberry Pi CM0/CM4 CARD や別マスター）と I2C で接続したマルチモジュール構成において、**Power-Down で完全停止したまま、自分の I2C スレーブアドレスが呼ばれた瞬間だけハードウェアが自動起床して応答** できる。

### ④ 外部センサー割込 ＆ SleepWalking 自律監視（`PA6`: `P01 / ADX_AIN` ほか全 `P01`〜`P11`）
- **外部イベント起床**: `PA6 (P01 / AIN)` は完全非同期ピン (`Px6`)、その他 `P01`〜`P11` の全ピンも `BOTHEDGES`/`LEVEL` で Power-Down 起床が可能。リミットスイッチ、漏水・浸水接点、雨量計ティッピングバケット、PIR 人感センサ、加速度センサの INT ピンに直結して「事象が起きた瞬間だけ起きる」設計が可能。
- **SleepWalking（ADC ウィンドウ比較）**: Standby スリープ中、**CPU を起こさずに RTC / Event System 経由で `ADC0` を間欠自動起動し、計測値が設定ウィンドウ（上限・下限）を超えた異常時だけ CPU 割り込みで起床** できる。

### ⑤ 内蔵 `RTC` / `PIT` による自律定期起床
- **対応スリープ**: Power-Down / Standby（内蔵 `OSCULP32K` 使用、**Typ `0.71 µA` @ 25℃ / Max `6.0 µA` @ 85℃**）
- 外付け 32.768 kHz 水晶なしで、数ミリ秒〜数時間ごとの定期サンプリング→送信→再スリープを自律実行できる。

### ⑥ `UPDI`（`PA0`）による絶対不沈のハード強制介入
- **データシート根拠（§33.3.9）**: UPDI 物理層はすべてのスリープモードから独立して動作する。
- 万一、開発中のバグで「起床割り込みを 1 つも設定せずに Power-Down へ突入（ソフトウェア上の永久睡眠）」してしまっても、**`USB-COM` を挿せば `CH342K` Port 0 の UPDI がハードウェアレベルで強制起床・リセット・再書込できる**。AI エージェントが自律開発中にスリープ関連のコードでミスをしても絶対にブリックしない。

## 4. 現場で活きる 5 つのキラーユースケース

1. **屋外ソーラー／12V・24V 蓄電池での「挿すだけ Android GOT 点検ノード」**
   - 農業ハウス・水位監視・太陽光発電所・屋外仮設設備などで、普段は RTC 定期計測＋Power-Down で超低消費電力稼働。巡回点検員がスマホ（Android GOT）を `USB-COM` に挿した瞬間に即起床し、内部ログ・現在値・電力状態を 6 インチ画面へ表示。抜けばその瞬間にスリープへ戻る。
2. **「耳だけ開けて眠る」省電力 RS-485 / LIN フィールドスレーブ群**
   - 複数台の CORE-U + 絶縁 RS-485 CARD を 1 本のフィールドケーブルに並べ、普段は全スレーブが Standby (`SFDEN`) または Power-Down (`PA2` 割込) で待機。マスターが必要な時だけ Break / コマンドを投げると対象ノードだけが即座に起きて応答し、再び眠る。**無線では原理的に不可能な「低消費電力 × ミリ秒即応」** を有線で実現。
3. **密閉高温環境での「熱マージン極大化（サーマルデューティ制御）」**
   - 真夏の直射日光下の防水ボックスや車載キャビン内（+75〜+85℃）では、常時 10MHz 稼働するより間欠スリープを行うことで、MCU 発熱を実質ゼロ（µW 級）へ抑え込み、部品寿命と熱マージンをさらに伸ばせる。
4. **SleepWalking 番犬ノード（異常時のみ即時発報）**
   - `VBUS_VSENSE`（電源低下監視）や `P01 (AIN)`（温度・振動・圧力・ガスセンサ）を CPU 停止のまま SleepWalking で自動監視し、閾値逸脱の瞬間だけ CPU が起床して RS-485 警報送信やリレー遮断を実行。
5. **ハイブリッド無線ゲートウェイ構成の「脊髄」**
   - どうしてもクラウド送信が必要な屋外案件でも、**「普段の計測・異常監視・現場保守起床は CORE-U rev6（低消費・即応）が常時担当し、1 日数回や異常時だけ拡張 CARD 側の LTE/LoRa/Wi-Fi モジュールへ電源を入れて送信する」** 役割分担にすれば、ESP32 単体で悩んでいた無線ディープスリープ問題を根本解決できる。

## 5. 現実の待機電力バジェット（MCU 単体 vs ボード全体）と設計チューニング余地

「MCU が `0.1 µA` で寝られる」ことと「CORE-U rev6 ボード全体の待機電流」は明確に分けて把握しておく必要がある。Mode 1（`Full embedded mode`、IDC 5.0V 受電、`USB-COM` / `USB-POW` 非接続）における Power-Down 時の全素子電流積算は以下の通り（25℃ Typ 目安）：

| 回路ブロック / 部品 | Mode 1 Power-Down 時電流 | 備考・データシート根拠 |
| :--- | :---: | :--- |
| `ATtiny1616-MNR`（Power-Down + RTC） | `0.7 µA` *(RTC 停止時 `0.1 µA`)* | データシート Table 37-5（85℃ Max: `5.0〜6.0 µA`） |
| `CH342K`（`Q2` 遮断状態） | **`0.0 µA`** | 電源・信号とも完全遮断（0 mW） |
| `SN74LV4066A`（アナログスイッチ） | `0.01 µA` | データシート Typ（125℃ Max: `20 µA`） |
| 高耐圧 3.3V LDO（第一候補 `TPS70933DBVR`） | `1 µA` *(旧 `TLV75533`: `25 µA`)* | データシート Typ $I_Q$（30V 動作・逆流防止内蔵） |
| `TP181A2-CR`（電流センスアンプ） | `120 µA` | データシート Typ $I_Q$（全温度 Max: `150 µA`） |
| `VBUS_VSENSE` 分圧（`10kΩ + 10kΩ` @ 5V） | `250 µA` | $5.0\text{V} / 20\text{k}\Omega$ |
| `USB_COM_EN` プルアップ（`Q3` ON 時 `100kΩ` @ 3.3V） | `33 µA` | $3.3\text{V} / 100\text{k}\Omega$ |
| **小計（`LED_SYS` 緑を除く全回路）** | **約 `405 µA`（約 `2.0 mW`）** | **1mA 未満の超省電力！** |
| **`LED_SYS` 緑（`VBUS_PROT` 常時点灯）** | **約 `2,000〜3,000 µA`（`2〜3 mA`）** | **待機電流の約 80〜85% を占有** |
| **現行標準 rev6 合計（Mode 1 睡眠時）** | **約 `2.4 〜 3.4 mA`（約 `12 〜 17 mW`）** | 12V 7Ah 鉛蓄電池なら数ヶ月単位で余裕稼働 |

### ★ 回路図作成前に検討する価値がある「低消費チューニング余地（コスト `$0`）」
上記の積算から、**部品構成を一切変えず定数とパターンを少し工夫するだけで、Mode 1 睡眠電流を劇的に下げられる** ことが見えてきた：

1. **`VBUS_VSENSE` 分圧を `10kΩ + 10kΩ` → `100kΩ + 100kΩ`（＋ `0.1µF` X7R）へ変更**
   - `0.1µF` コンデンサが ADC サンプリング時の低インピーダンス電荷リザーバになるため、100kΩ 分圧でも高精度に計測可能（消費電流が `250 µA` → **`25 µA`** へ 1/10 に激減！）。
   - これだけで **`LED_SYS` 除く待機電流が約 `180 µA`（`0.9 mW`）** まで落ちる。
2. **`LED_SYS` 緑の電流設定（`2〜3 mA` → `0.5〜1.0 mA`）＋ 脱着式 `0Ω` 抵抗ブリッジ（`0805` 推奨）**
   - 現代の高輝度 InGaN 緑 LED（`HVRTB-3433EPX`）は `0.5〜1.0 mA` でも屋内・制御盤内で十分視認できる。
   - さらに制限抵抗 `R_LED_G` と直列に、**大きめの `0Ω` 抵抗（`0805` Basic 推奨、シルク `JP_PWR_LED`）** を基板端寄りなど付け外ししやすい位置へ 1 個設けておけば（OPTION）、① 基板をカッターで傷つけず防湿・OSP 信頼性を維持でき、② 工場 PCBA でも BOM 1 行の DNP 指定で省電力版を量産でき、③ 再有効化時にはんだブリッジしても直列の `R_LED_G` により LED 焼損リスクゼロで **ボード全体 `~200 µA`（`1 mW`）級の超低消費電力ディープスリープ・ノード** へ安全に切り替えられる。

## 6. ファームウェア実装時の重要チェックリスト

CORE-U rev6 でディープスリープを活用する際の標準ガイドライン（ライブラリ化候補）：

1. **`PB5` は必ず `PORT_ISC_BOTHEDGES_gc` を使う**：`RISING` では Power-Down 復帰しない。復帰後に `digitalRead(ADX_USB_COM_DET)` で挿抜方向を確認し、チャタリング吸収（20〜50ms）を入れる。
2. **`USB-COM` 挿入直後は `50〜100 ms` 待ってから UART / SoftwareSerial を開始する**：`Q2` による `CH342K` 電源立上り・`SN74LV4066A` 閉成直後の過渡グリッチを回避する。
3. **未使用・非稼働ピンのリーク防止**：Mode 1/2 のスリープ前は `LED_MCU` (`PB4`) を必ず LOW にし、使っていないバスピンの入力バッファ無効化（`PORT_ISC_INPUT_DISABLE_gc`）または確定レベル維持を行う。
4. **BOD（Brown-Out Detector）のスリープ時設定**：ヒューズまたはランタイムで Power-Down 時の BOD を `SAMPLED`（間欠監視・低消費）または `DISABLED` とし、BOD 常時稼働による ~15〜20µA の消費を抑える（フィールド電源安定時）。
5. **RS-485 拡張 CARD 併用時の低消費注意**：絶縁 RS-485 CARD 上の絶縁 DC-DC モジュール（例：`TDA51S485HC`）は常時 ~10〜20mA 消費するため、フィールドバス待機でボード全体の省電力を極めたい場合は、**RS-485 CARD 側にもシャットダウン／低消費レシーバ設計（または非絶縁低消費トランシーバ選択）** を検討すると、CORE-U rev6 のディープスリープ性能を 100% 引き出せる。

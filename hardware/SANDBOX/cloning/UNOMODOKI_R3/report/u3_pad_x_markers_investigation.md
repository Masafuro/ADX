# U3 調査レポート：PCB プレビュー上の全パッド `×` マークの正体と発生原因（リードオンリー調査）

- **作成日**: 2026-11-28
- **作成者**: プロジェクトリーダー（AI）
- **調査方針**: サポーターの指示により、**PCB への改修・変更・保存は一切行わず**、完全リードオンリーで全パッド・ラッツネスト・DRC 項目を照合調査した。
- **生データ**: [u3_ro_drc_audit.json](../outputs/u3_ro_drc_audit.json)

---

## 1. 結論（安心して大丈夫です！）

1. **全パッドに出ている黄色 `×` マークは「異常なエラー・配置破損」ではなく、U4 配線前の「未配線マーカー（`Connection Error`）」です。**
2. **数の一致による完全証明**:
   - 全 37 部品の総パッド数: **`166` 個**（ネット割当あり **`152` 個** ＋ 意図的未接続 NC **`14` 個**）
   - `pcb_Drc.check` で検出された `Clearance Error`（外形干渉・パッド接触等）: **`0` 件**
   - `pcb_Drc.check` で検出された `Connection Error`（未配線）: **ちょうど `152` 件（40 ネット）**
   - ラッツネスト本数（`getRatlines().total`）: **`112` 本**（数学的理論値 $\sum (n_i - 1) = 152 - 40 = 112$ と完全一致）
   - 意図的未接続の **14 パッド**（`J_POWER.1(NC)`, `J_POWER.8(VIN)`, `J_USB.A8/B8`, `U1.19/22`, `U2.7..12,14,15`）には画像上でも **`×` が 1 つも付いていない**ことが確認できます。
3. **なぜ 1 回目の PNG には無かったのに 2 回目の PNG で突然 152 個も出現したのか？**
   - EasyEDA Pro の仕様として、**フル DRC（`eda.pcb_Drc.check(...)`）を呼ぶと、`userInterface = false` であってもキャンバス上の全未配線パッドへ黄色 `×`（`visible: true`）を一斉描画する副作用**があるためです。
   - 2 回目のスクショ撮影時に PL が **`pcb_Drc.check()` を呼んだ直後に PNG を撮ってしまった** ことで、152 個の未配線 `×` がそのまま写り込んでしまいました。

## 4. 今回の立ち止まり調査で得られた超重要な知見（M5 への改善ルール）

サポーターが「改修せず一度立ち止まって調べよう」と止めてくれたおかげで、AI 運用における **レビュー画像生成の重要な罠** を発見できました。

1. **AI → 人間レビュー用 PNG の撮影順序ルール（M5 標準化）**
   - 配線前（U3）の配置レビュー用 PNG を撮る際は、**必ず `pcb_Drc.check()` を呼ぶ前に `getCurrentRenderedAreaImage()` を撮影する**こと。
   - その**あとで** `pcb_Drc.check(true, false, true)` を実行し、`Connection Error` 以外のカテゴリが **0 件** であることを JSON で自動検証してテキスト報告する（これにより、人間が見る配置スクショが未配線 `×` だらけになって視認性を損なうのを防げる）。
2. **「今すぐ何か改修する必要があるか？」への回答**
   - **改修は不要です。** 現在の `Sandbox_UNOMODOKI_R3`（`PCB1`）は、`Clearance Error = 0 件`・38 ピン座標誤差 `0.000 mm` の健全な配置状態であり、次の **U4（2 層配線・GND ベタ）** で配線が進むにつれて 152 個の `×` と 112 本のラッツネストが順次消え、最終的に全 DRC 0 になります。
   - *(※もし Windows GUI 上で今の未配線 `×` 表示が邪魔で作業しづらい場合は、EasyEDA Pro 画面左側の DRC パネルからクリア／チェックオフするか、そのまま配線を進めれば各ネット完了ごとに消えていきます。)*

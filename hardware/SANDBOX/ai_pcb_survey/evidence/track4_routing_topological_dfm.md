## 2. 一次エビデンス ①：90° vs 45° vs 曲線配線の「電気物理」と「製造プロセス」の真相

### 2.1 製造プロセスの重要な区別：**化学エッチング vs CNC ルーター**
一般的な工業 PCB（JLCPCB 等の量産・試作ライン）では、**銅箔パターンの形成は CNC ルーターによる切削ではなく「フォトリソグラフィ＋化学湿式エッチング」** で行われる（CNC ルーター／エンドミルが使われるのは、基板外形カット・長穴スロット・V カット・ドリル加工、あるいは卓上基板加工機による簡易切削のみ）。

| 観点 | 90° 直角配線 | 45° 面取り配線（現行標準） | 曲線（Arc / Any-Angle）配線 |
| :--- | :--- | :--- | :--- |
| **電気特性（SI/EMI）**<br>*(Bogatin / Johnson 定説)* | 外角の過剰容量は **`~0.01–0.02 pF`**（遅延 `~0.5 ps`）。立ち上がり時間 `<20 ps`／数十 GHz 級の RF・超高速以外では **電気的に透明**。`CORE-U rev6`（10MHz・USB Full-Speed）では問題なし。 | 過剰容量をさらに低減。一般デジタル〜数 GHz 帯まで実用上完璧。 | 超高周波（mmWave / RF / 極細差動）で最も均一なインピーダンス遷移。一般デジタルでは SI 改善効果は誤差範囲。 |
| **化学エッチング（酸トラップ）** | 30〜40 年前の旧式浸漬エッチングでは懸念されたが、現代の高圧スプレーエッチングでは 90° 自体は実質問題にならない。**本当に危険なのは鋭角（`< 90°`）の V 字ポケット**（エッチング液滞留→細り・断線）。 | 鋭角を作らず、エッチング液流動が均一。**JLCPCB DFM が公式推奨する安全基準**。 | 鋭角ゼロでエッチング流動は最良。ただしパッド接続部等で意図せぬ鋭角ポケットを作らない幾何制御が必要。 |
| **機械的信頼性（ピール強度・熱応力）** | 熱サイクル（リフロー／`-40〜+85℃` 稼働）や基板たわみ時に角へ応力集中が起きやすい（特に細線＋軽微過エッチングが重なると銅箔剥離リスク増）。 | 応力が分散され、産業用温度サイクル（`CORE-U rev6` `-40〜+85℃`）でも信頼性が高い。 | 応力集中が最小。フレキシブル基板や極限環境では有利。 |
| **配線密度・ツール対応** | 格子チャネル管理が最も単純だが、斜め近道ができず配線長が伸びやすい。 | ほぼ全 EDA・全ルーター（Specctra DSN/SES 含む）がネイティブ対応。 | **Specctra DSN/SES 形式が直線ポリライン前提**のため曲線は多角形近似される。EasyEDA Pro の手動・API 修正性も低下。 |

**結論（Track 4-2 の明確な答え）**：  
「90° は電気的に絶対 NG」は迷信だが、**`CORE-U rev6`（`-40〜+85℃` 産業耐熱・JLCPCB 量産前提）では「45° 面取り（鋭角 `<90°` 厳禁）」が電気・DFM（化学エッチング）・熱応力（ピール強度）・ツール互換性のすべてで最適解** である。曲線／任意角にこだわる理由は電気特性ではなく、**「トポロジカル配線による高密度収容」** に限定される。

## 3. 一次エビデンス ②：トポロジカル／ゴム紐（Rubber-band）ルーターの正体と実装の壁

- **系譜**: Leiserson & Maley（平面配線理論）→ **SURF**（Dai, Dayan & Staepelaere：Rubber-band Sketch）→ 商用基準 **TopoR**（Eremex）および OSS 実験（`pcb-rnd` 等）。
- **仕組み**: 最初から座標を決めず、ピン・障害物を「杭（Peg）」、配線を「ゴム紐（Rubber-band）」とみなし、**ホモトピー類（どの障害物のどちら側を通るかという位相関係）** を解いてから、張力最小化で滑らかな任意角・曲線形状へ緩和する。
- **JITX 等の技術分析で指摘されている「自前実装の 3 大ハードル」**：
  1. **3D ホモトピーの困難（多層＋ビア）**：2D 平面では美しいが、ビアで層を跨ぐ瞬間に別層のホモトピー領域と干渉し、DRC 違反を誘発しやすい。
  2. **ゼロ幅→実幅膨張（Inflation）でのトポロジ崩壊**：抽象段階では線幅ゼロで解くが、実銅箔幅＋クリアランス＋フィレット（円弧半径）へ膨張させた瞬間、異形パッド（USB-C 長穴や QFN）周りで局所トポロジが壊れ、鋭角やクリアランス違反が発生する。
  3. **浮動小数点幾何の堅牢性（Robustness）**：微小な数値誤差でトポロジ判定と物理 DRC が食い違いやすく、実務では手動手直しやフォールバックループが不可欠になる。

**エンジニアリング判定**：  
トポロジカル／ゴム紐ルーターを自前でゼロ開発するのは **計算幾何学だけで数年級の研究開発** であり、`CORE-U rev6` 級の 2〜4 層・30〜100 部品基板に対しては **明確なオーバーエンジニアリング（Do Not Build）** である。

## 4. 一次エビデンス ③：EasyEDA Pro から使える実戦自動ルーター比較

| ルーター / エンジン | アルゴリズム / 特徴 | EasyEDA Pro 連携手段 | ロック配線保護 | 30〜150 部品基板での実戦評価 |

| **FreeRouting（ヘッドレス CLI / ローカル API）** | 波面探索＋リッパップ＆再配線＋事後最適化（45° / 90° / free angle 切替可） | `getDsnFile()` → `java -jar freerouting.jar -de in.dsn -do out.ses -ap N -pp M -mt T` → `importAutoRouteSesFile()`（またはローカル WebSocket ポート `37864`） | **○**<br>DSN の `(type fix)` / `(type protect)` で保護（EasyEDA ロック連動） | **◎ 最有力（Adopt）**。OSS・無料・完全自動ヘッドレス化可能。30〜150 部品規模なら数秒〜数十秒で完走。 |
| **FastRoute（Rust 版 FreeRouting 移植）** | FreeRouting アルゴリズムの Rust マルチスレッド移植（JVM 不要・省メモリ高速） | 同上（DSN / SES 互換） | **○**（DSN 準拠） | **○ 有望（監視・代替候補）**。FreeRouting の速度や JVM 依存がネックになった際の有力な差し替え先。 |

## 5. Track 4 判定：Adopt / Adapt / Build（ADX 向け）

| 要素 | 判定 | ADX（EasyEDA Pro / `CORE-U rev6`）での具体方針 |
| :--- | :---: | :--- |
| **「重要マッス＝AI 自作 45° 配線＆ロック」＋「一般信号＝API / ヘッドレス自動配線」の 2 段階自動化** | **Adopt / Adapt（本命）** | U4-b の人間 GUI 操作を完全撤廃。①電源・アナログ・USB 差動を AI が 45° 面取り配線して `locked: true` 固定 → ② `startAutoRouting()` または `getDsnFile()` + ヘッドレス FreeRouting (`-de`/`-do`/`-ap`/`-pp`/`-mt`) + `importAutoRouteSesFile()` で一般信号を完全自動配線 → ③厳格 DRC 0 アサート。 |
| **45° 面取り自動変換ヘルパー（鋭角 `<90°` 禁止アサート付）** | **Build（極小実装）** | `UNOMODOKI R3` の直角ポリライン生成スクリプトへ、45° 面取り関数＋鋭角チェックを追加。 |
| **独自トポロジカル／曲線・物理場ルーターのゼロ開発** | **Do Not Build** | 3D ホモトピー・実幅膨張・DSN 互換性のコストに対して `CORE-U rev6` 規模でのリターンが薄い。物理場の発想は **Track 3（配置・交差最小化）** へ集中投下する。 |
| **OrthoRoute / 商用クラウド（Quilter・DeepPCB）導入** | **Do Not Adopt** | 規模不適合（OrthoRoute）またはブラックボックス・コスト・EasyEDA 非対応（Quilter/DeepPCB）。 |

# Track 1 エビデンス調査：仕様・データシート → 制約形式化 ＆「DRC の先」の決定的検証ループ

- **調査日**: 2026-11-28
- **位置づけ**: プリレビューで最大の盲点として浮上した **「Parseable / DRC 0 ≠ 電気的に動作する」問題** の先行研究・実装知見の精査
- **ADX 側の主要ターゲット**: [ADX CORE-U rev6](../../../CORE-U/rev6/spec.md)（`VBUS 4.5–5.5V` MUST、`TPS259470A` eFuse OVLO、`TPS70933` 高耐圧 LDO、`10mΩ` + `TP181A2-CR` 電流計測、`CH342K` Mode 1 完全遮断、全稼働部品 `-40〜+105℃`）

## 1. リサーチクエスチョン（RQ）

1. LLM にゼロから回路図や制約を作らせると、どの工程で・なぜ失敗するのか？
2. 純粋な LLM 自己レビューではなく、**決定的（Deterministic）検証ループ** で成功率を劇的に上げた先行手法は何か？
3. SPICE シミュレーション・Code-as-CAD アサーション・VLM 目視検品は、それぞれ **何ができて何ができないのか**？
4. EasyEDA Pro 環境（`UNOMODOKI R3` の資産）へ最小コストで組み込める **「DRC の先」の検証ゲート** は何か？

## 2. 先行研究・ツールから得られた一次エビデンス

### 2.1 ベンチマークが暴いた「物理的直感の欠如」と「DRC の限界」

- **`HWE-Bench`（Qiu et al., 2026, [arXiv:2603.18102](https://arxiv.org/abs/2603.18102)）**
  - 実在 IC データシート約 3,000 件と GitHub/OSHWLab 由来の 300 基板タスクを用い、静的 ERC だけでなく **動的回路シミュレーション** で評価。
  - **結果**: 最先端 LLM でもデータシートを読解しているように見えながら、ゼロからの基板レベル回路設計合格率は **約 8.15%** に低迷。最大要因は「物理的・電気的直感の欠如（定格超過、誤ピン結線、動作条件逸脱）」。
- **`PCB-QA`（Srinivasan et al., 2026, [arXiv:2606.23704](https://arxiv.org/abs/2606.23704)）**
  - 8 つの OSS 基板プロジェクト由来の 480 Q&A で、回路接続・データシート照合・SPICE 由来特性を評価。
  - **重要結論**: LLM は生 PDF や画像より、**構造化テキスト／JSON 表現** を与えた方が構造理解・検証精度が圧倒的に高い。
- **`CircuitLM`（Hasan et al., 2026, [arXiv:2601.04505](https://arxiv.org/abs/2601.04505)）と比較研究の教訓**
  - 部品選定・ピンアウト抽出・`CircuitJSON` 生成・検証をマルチエージェント化したが、後続比較（`PCBSchemaGen` 等）で **「LLM 自身のスコア付けや自己レビューだけではハルシネーションを止められない」** ことが明確になった。

### 2.2 ブレークスルー：`PCBSchemaGen` の「データシート圧縮 KG ＋ 決定的 5 層検証器」

- **`PCBSchemaGen`（Zou et al., UT Austin, 2026, [arXiv:2602.00510](https://arxiv.org/abs/2602.00510)）**
  - **学習不要（Training-free）** で、オープンウェイト LLM（Gemma 系バックボーン等）の回路図生成合格率を **81% 超** まで引き上げた決定打。
  - **核心技術 ①：データシートの 50 倍構造化圧縮**
    - 通常約 16,000 トークンある IC データシートを、**約 300 トークンのスキーマ誘導型ナレッジグラフ（Knowledge Graph: KG）** へ圧縮し、ピンごとの意味論的ロール（電源・GND・イネーブル・フィードバック・オープン禁止等）と許容接続ルールを明文化して LLM を拘束。
  - **核心技術 ②：決定的 5 層連続報酬検証器（Deterministic 5-Layer Verifier）**
    - ①構文検証 → ②ERC → ③二部グラフ対応検証 → ④KG ルール検証 → ⑤サブグラフ同型（VF2）によるトポロジ検証、の 5 層で **ピン単位のエラー局所化（pin-level error localization）** を行い、Thompson Sampling バンディットで候補を反復改善。
  - **ADX への示唆**: `UNOMODOKI R3` の U1 でやった「4 部品バッチでの LCSC 実ピン極性抽出」をさらに一歩進め、**主要 IC ごとに 300 トークン級の「ピン意味論＆制約 JSON（Pin-Role & Constraint Schema）」を 1 回確定して SSOT 化** すれば、後続の回路図・配置・配線・レビュー全工程のハルシネーションを構造的に封じられる。

### 2.3 SPICE 自動検証ループの適用境界

- **`AnalogCoder`（Lai et al., 2024, [arXiv:2405.14918](https://arxiv.org/abs/2405.14918)）＆ `SPICEAssistant`（2025）**
  - 学習なしで自然言語仕様→Python 経由 SPICE ネットリスト生成→波形・ログ解析→自動修正ループを回す手法を実証。
- **重要境界（`PCBSchemaGen` 論文の指摘）**
  - **基板全体のデジタル＋マイコン回路を丸ごと SPICE にかけるのは非現実的**（MCU や CH342K 等の IBIS/SPICE モデル欠如、収束失敗）。
  - 一方、**局所アナログ／電源ブロック単位（部分回路）の `ngspice` 検証** は極めて有効：
    - `CORE-U rev6` なら、① `VBUS_VSENSE` 分圧回路、② `TPS259470A` OVLO 分圧定数（`5.5V` 非誤遮断・`6.0V` 遮断マージン）、③ `10mΩ` シャント＋`TP181A2-CR`（0〜3.3A 出力線形性）、④ `CH342K` 遮断 FET (`Q3`) ＋ `SN74LV4066A` リーク／スニークパス検討、といった **小規模・高リスクのアナログ／保護ブロックだけピンポイントに `ngspice` / 数値スクリプトで検証する** のが実務最適解。

### 2.4 Code-as-CAD 発の「コンパイル時・電気アサーション」文化（`atopile` / `JITX`）

- **`atopile`（`.ato` assertions）と `JITX`（Python 電気チェッカー）のエッセンス**
  - 回路図を「絵」ではなく「型・定格を持つプログラム」とみなし、ビルドごとに以下を自動アサートする：
    1. **電源ドメイン整合性**：異なる電圧ドメイン（`5V VBUS` vs `3.3V VDD` vs `0V 遮断領域`）の誤結線・絶対最大定格超過検知。
    2. **部品ディレーティング検証**：印加電圧 vs コンデンサ定格（例：`VBUS 5.5V` に対し MLCC `25V X7R`）、動作温度定格（`CORE-U rev6` Mode 1 稼働品は全品 `-40〜+105℃` MUST）、許容消費電力（シャント $I^2 R = 2^2 \times 0.01 = 0.04\text{W}$、LDO 損失 $(5.5 - 3.3) \times I$）。
    3. **電圧ベース絶縁クリアランス（IPC-2221）**：ネット電圧属性に応じた最小沿面・空間距離。
    4. **バックパワー（スニークパス）監査**：Mode 1/2 で無通電となる `CH342K` 側へ、MCU 側プルアップや信号線経由で保護ダイオード電流が流れ込まないか（`SN74LV4066A` 遮断境界のグラフ到達性チェック）。
- **ADX への示唆**: `atopile` や `JITX` をツールごと導入しなくても、**EasyEDA の Protel2 ネットリスト＋`bom_verified.json`＋「制約 JSON」を入力とする 200 行程度の Node/Python 決定的アサーションスクリプト** で、このエッセンスの 8 割以上を EasyEDA Pro ワークフローへ即移植できる！

### 2.5 VLM（視覚言語モデル）検品の適用範囲と失敗モード

- **`PCB-Bench`（Li et al., ICLR 2026）＆ `MuaLLM`（Abbineni et al., 2025, [arXiv:2508.08137](https://arxiv.org/abs/2508.08137)）＆ `OmniSch` / `OmniLayout`**
  - **VLM の致命的失敗モード**：
    1. **微細空間グラウンディング崩壊**：QFN パッドや高密度配線のピクセル対応を誤認し、偽陽性・偽陰性を多発。
    2. **大域接続の追跡不能（Schematic Blindness）**：複数ブロックに跨る AGND/DGND 誤結合やプルアップ漏れを画像から追えない。
    3. **標準リファレンス回路の記憶ハルシネーション**：実基板固有の修正点を見落とし、データシートの定型文を答えてしまう。
    4. **ビューポート脆弱性**：ズーム率・配色・グリッド表示の僅かな差で精度が急落。
  - **VLM が本当に活きる用途**：電気・幾何の合否判定には使わず、**「シルク文字の重なり・向き」「コネクタ突き出し・3D 干渉の一次目視」「人間レビュー前の明らかなレイアウト違和感検知」** の補助に限定すべき。

## 3. Track 1 判定：Adopt / Adapt / Build（ADX 向け）

| 要素 | 判定 | ADX（EasyEDA Pro / `CORE-U rev6`）での具体方針 |
| :--- | :---: | :--- |
| **Protel2 ネットリスト全数照合 ＋ NC フィルタ DRC** | **Adopt（継続）** | `UNOMODOKI R3` で確立済みの決定的ゲートを標準化。 |
| **IC データシート 300-token スキーマ化（`PCBSchemaGen` エッセンス）** | **Adapt** | 主要 IC（`ATtiny1616`, `TPS259470A`, `TPS70933`, `TP181A2`, `CH342K`, `SN74LV4066A`）のピンロール・絶対最大定格・温度範囲・禁止接続を機械可読 JSON へ事前構造化し、AI 生成時の拘束条件にする。 |
| **ネットリスト×BOM 電気アサーション（`atopile`/`JITX` エッセンス）** | **Build（軽量実装）** | Node/Python による決定的チェッカーを作成：①電圧ドメイン＆絶対最大定格照合、②温度定格（`-40〜+105℃`）一括監査、③消費電力／電流幅チェック、④Mode 1/2 電源遮断境界のスニークパス（到達性）自動監査。 |
| **局所アナログ／保護ブロックの `ngspice` 自動検証** | **Adapt** | 基板全体ではなく、OVLO 分圧・VSENSE 分圧・10mΩ シャント計測・LDO 熱損失の 4 ブロックのみ部分回路テストベンチ化。 |
| **VLM による自動回路／配線合否判定** | **Do Not Adopt（限定利用）** | 電気・幾何の合否には絶対に使わない。シルク視認性・3D 違和感チェックの補助＋最終人間検品の補佐に限定。 |
